## 現況（2026-09-16，`c83e108` 已推送）

### #24：入口 2 就是每一區的打斷參數，remake 一次都沒跑過

`camp.go` 的 `restInterruption()` 從 `eventMachine.Memory` 讀 `6DD2h`（週期）／`6DD3h`（門檻），
spec 114 寫著「ECL VM 本來就在跑那些 `SAVE`，所以值是自然到位的」——**那句話是錯的**。
寫這兩個位址的 `SAVE` 幾乎都在**入口 2**，而 remake 只跑入口 0（每格）、1（搜尋）、3（打斷之後）。
`grep SetEntry cmd/pool-game/camp.go` 一筆都沒有，所以兩個值永遠是 0／0，任何地方休息都不會被打擾。
（spec 114 那一句要照 `rulebook/63` 改成現況，推翻紀錄集中一處。）

入口 2 的位址從 `pool-ecl-trace` 的 `entry_addresses` 取（索引 2），已經讀出來的四份：

| 區 | 入口 2 | 內容 |
|---|---|---|
| 城區 `ecl3/0` | `9A5Eh` → `GOSUB 9A63h` | `4ABA < 254`（還沒通關）且 `4A07 == 0` → `6DD2 = 1`、`6DD3 = 101`；否則 0／0 |
| 貧民窟 `ecl2/20` | `9A0Eh` | `4A0B == 255` → **24／24**；否則 `4ABB >= 254`（清完）→ 0／0；否則地形 `@6E82 == 0`（街上）→ **24／24**；否則 0／0 |
| 古托井 `ecl8/29` | `9BDDh` | 先 `CALL @C018`、預設 `0／100`；井底（`4A10 == 1`）地形 16 就 EXIT，諾里斯還活著（`4A24 != 255`）→ `6DD2 = 1`；地面 `4A22 < 10` 且地形不是 1 → `12／12` |
| 索寇要塞 `ecl4/21` | `9A29h` | `4A03 <= 4`（巡邏還在）→ `2／1`；否則 0／0 |

**入口 2 讀地形**（`@C04F`、`@6E82`），所以跑之前要先投影座標——`gamepack.RunInitialSessionCampEntry`
（入口 3）已經有 `projectInitialPosition` 那一步，入口 2 照抄。

**還沒讀到的**：原版在哪一刻叫入口 2。spec 114 已證休息主迴圈 `0C45h` 裡**沒有**任何 ECL 呼叫
（`0D69`／`0D6D`／`0D76` 是 entry 11／14／15），所以它一定在迴圈之前——候選是進紮營畫面、
按下 R）EST、或每次換格／換圖。這是這一輪要判的第一件事。

### #20：七個時鐘變數一個都沒投影

spec 069〈時間推進〉已證：**overlay-20 entry 2（`0392h`）把時間加到 ECL 的
`49C6h..49CCh`**（class 0，`[4933h] + 6E00h + addr × 2`），entry 4 再換算成分、遞減效果。
remake 的 `advanceGameTime`（`party_panel.go:155`）只動 `a.gameTime` 與效果，沒有那一步。

索引對位址（spec 114 的進位表）：`49C6h` 起 0..6，所以 **`49C9h` 是小時**（上限 24）、
`49C8h` 是分的十位、`49CAh` 是日。腳本讀的就是 `49C9h`：

| 讀的地方 | 條件 | 效果 |
|---|---|---|
| `ecl3/0 9BAEh` | `49C9 > 14` 就跳過 `PICTURE 41` | 上船的圖 |
| `ecl3/0 ADAAh` | 城門的馬車商人 | `49C9 >= 14` 直接 EXIT（spec 137 死區表）|
| `ecl4/21 AE48h` | `49C9 >= 14` → `4A18 = 8`（否則 11）| 索寇要塞的圖 |
| `ecl8/29 AF30h` | 同類 | 古托井 |

## 2026-09-16 收在哪（`6a72caf`）

兩條都做完並關閉；接上之後露出一條新的硬限制，開 #38。

**#24 的那一個 RE 問題答出來了（exact）。** 入口 2 是**紮營畫面一打開**就跑的——不是每一刻、
也不是每一格。推法：spec 022 已證五個 header 依序寫到 `DS:4944..494C`，所以入口 2 是 `4948h`；
`pool-disp-scan -addresses 4944,4946,4948,494A,494C` 掃下去 `4948h` 只有 overlay-03 `3134h`
一筆，而正對照 `494Ah` 也只有 `3151h` 一筆——那正是本來就知道的入口 3 呼叫點，兩筆在同一支
常式裡相隔 29 個位元組：

```
312A  push bp ; mov bp,sp ; sub sp,2
3130  mov byte [bp-1], 0        ; 被打斷了沒（out 參數）
3134  push ds:4948h → 3139 call 35DBh    ★ 入口 2
3141  call far 00ACh:0025h      ; overlay-15 entry 1 ＝ 紮營畫面
3146  cmp byte [bp-1], 0 ; jz 3159
3151  push ds:494Ah → 3156 call 35DBh    ★ 入口 3
```

`00ACh` 查 spec 109 是 overlay-15、`(25h−20h)÷5 = 1` 是 entry 1；IDA 讀 `1E45h` 起確認它是整個
紮營畫面（存時鐘 `DS:6CB6h` 14 個 word、畫視窗、清 out 參數），休息迴圈 overlay-20 entry 3
`0C45h` 在它裡面（掃 overlay-15 找 `9a 2f 00 d2 00` 一筆命中 `07ECh`）。dosgolem 那條退路沒有用到。

**順手抓到一個會安靜出錯的地方**：入口 2 讀的是 `@6E82`（入口 0／1 用 `AND 127 @C04F` 留下的），
不是 `@C04F`，而且遮罩是 `7Fh` 不是 `1Fh`——貧民窟的 `80h` 遮完是 0（仍算街上），`81h`／`82h`／
`83h` 才是屋內。第一版測試就是被這個絆到（屋內那一格讀出 24／24）。

**改了什麼。** `gamepack.RunInitialSessionRestEntry`（入口 2，與 0／1／3 同形先投影座標）＋
`openCamp` 在算 `restInterruption()` 之前叫它；`GameTime.ProjectClock` 寫七位 `49C6h..49CCh`，
`advanceGameTime`、`configureEventSession`、讀檔三處各叫一次。spec 114 那句「值是自然到位的」
是過期斷言，改成現況並補上呼叫鏈那一節；spec 022 的 header 表補 `4948h`／`494Ah`；spec 069
的對照表補投影那一列。測試五條：四份入口 2 的值（含四個負對照）、按 E 的接線（負對照是按之前
兩個值都是 0）、七位投影、換 machine 之後補投影。

**接上之後露出來的事（開 #38）。** 回一點生命力要連續睡滿 24 小時（288 刻），而貧民窟街上是
每兩小時擲一次、24% 被打斷，十二次全過只有 4%——**街上實際上睡不了**；而且被打斷跑的入口 3
（`ecl2/20 9A49h`）不是選單，是 `SAVE 200 @4A1F`、`PARTYSTRENGTH`、`GOTO 9B68h` 直接排一場
隨機遭遇，實測傷兵連睡八次就是全滅。城區是 1／101 更糟。原版只有屋內或城區 `4A07 != 0`
（hypothesis：旅店）睡得成。`restUntilHealed` 因此改成「這一區會打擾就不睡、記一行」——
先試過「走去屋內找床」，傷兵在路上四場架就死了，與那一支先前註解記的教訓一樣，退回來。

**代價：新增一條紅。** `TestQuickCombatEarnsExperience` 的治具在城裡漫無目的地走 900 步才找到
第一場架（量到第 15 個小時，走到碼頭搭船去索寇打四隻毒蛙），時鐘接上之後城裡十四點宵禁的
衛兵 38 隻（含 12 名六級戰士）先把它攔下來。試過四種修法（改走貧民窟、避開三個致命固定事件、
換骰流、接近宵禁才去碼頭）都只是換個地方死——治具的隊伍沒有任何裝備（AC 10、空手），而遭遇
