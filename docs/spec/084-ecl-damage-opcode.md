# Spec 084：`2Eh DAMAGE`

狀態：READY（五個運算元的意義、傷害擲法、目標選擇、豁免與狀態轉移都讀完
並實作）；DRAFT（`4954h == 5` 那條戰鬥中支線的倒地計時欄位）。
日期：2026-09-03。

## 為什麼重要

47 個呼叫點，是待辦裡最多的一條。陷阱、法術陷阱、劇情傷害都走它。

## 五個運算元（overlay-03 `2AE2h`）

| 運算元 | 意義 |
|---|---|
| 1 | 旗標 |
| 2 | 骰子個數 |
| 3 | 骰子面數 |
| 4 | 固定加值 |
| 5 | **豁免類別**（只用低三位，`2B9Dh` 的 `and 7`）|

旗標的四個位元：

| 位元 | 意義 |
|---|---|
| 7（80h）| 沒設就整條什麼都不做（`2B89h` 直接跳到結尾）|
| 6（40h）| 全隊；沒設就隨機挑一個人 |
| 5（20h）| 不給豁免 |
| 0..4（1Fh）| **豁免修正**，加進 d20 |

順序由呼叫端的推疊順序決定（overlay-03）：

```
2BC8  push 記錄的 far pointer
2BCE  push 運算元5 & 7
2BD2  push 旗標 & 1Fh
2BD6  lcall 0100h:0043h        ; overlay-24 entry 7、code 0D61h
```

最後推的在最低位址，所以豁免常式看到的是
`(旗標 & 1Fh, 運算元5 & 7, 記錄)`。而那支常式（spec 075 也記過同樣的順序）
把第一個參數 `cbtw` 之後加進 d20（`0D8Fh..0DA9h`），第二個存進 `DS:6788h`
再拿去索引 `record[+6Dh + 類別]`（`0DC8h`）。所以**低五位是修正、
運算元 5 才是類別**——資料裡出現低五位等於 10 的旗標是 +10 的修正，
不是第 10 個類別（`+6Dh` 只有五格）。

**傷害只擲一次**：`2B4Fh` 在挑目標之前就把 `骰(個數, 面數) + 加值` 算好，
全隊模式下每個人吃的是同一個數字。豁免成功**完全不受傷**，沒有折半。

隨機單體那一支擲的是 `骰(1, [4937h]+67Ch)`——`+67Ch` 是隊伍人數。

全隊那一支從 `DS:5CF4h` 走角色鏈，`+104h` 是下一個。

## 狀態轉移（overlay-25 entry 28，`2266h`）

```
hp = record[+11Bh]
if hp >= damage: remaining = hp - damage; deficit = 0
else:            remaining = 0;           deficit = damage - hp

赤字 > 9                    → 狀態 6
剩餘 = 0 且原狀態 = 1        → 狀態 6
赤字 > 0                    → 狀態 5（戰鬥中還會寫倒地計時）
剩餘 = 0                    → 狀態 4
其餘                        → 狀態不變

新狀態 ∈ {0, 1}（overlay-25 `2246h` 那個集合，第一個位元組是 03h）
  → record[+11Bh] = 剩餘
否則
  → record[+10Dh] = 0、record[+11Bh] = 0
    戰鬥中（`4954h` = 5）再把 `[6772h + record[+10Eh]]` 那一邊的人數減一
```

「赤字大於 9 直接死透」就是規則書的 −10 點；狀態 4 是剛好歸零的不省人事，
5 是瀕死，6 是死透。

## 訊息

overlay-03 的字串：`" is hit for "`、`" points of damage."`、`" dies. "`。
remake 用同樣的兩句，中文照 glossary。

## remake 怎麼接

`2Eh` 走 passthrough，前端解五個運算元、擲一次傷害、依旗標挑目標，
逐個擲豁免再套用 `ApplyDamage`，最後把訊息放進文字框並讓 ECL 繼續。

豁免的目標值由職業等級查 `DS:41E6h`（spec 075 的 `0253h`）。remake 的角色
記錄還沒有豁免修正欄位（`+101h`），一律當 0。
