# Spec 079：移動力

狀態：CONFORMED（基礎值、重算常式抄哪些欄位、盔甲與負重兩條規則的門檻與
方向）；DRAFT（`+11Ch` 在原版存檔裡的值代表什麼——見最後一節）。
日期：2026-09-03。

## 為什麼需要它

`29h ENCOUNTER MENU`（spec 078）的逃跑判定要拿**隊伍最慢的移動力**和運算元
13 比，逼近判定拿**最快的**和運算元 14 比。算移動力的 `1F87h` 逐人讀記錄
`+11Ch`，所以這個欄位是那條 opcode 的前置條件。remake 目前的角色記錄
（`internal/save.Character`）沒有這個欄位。

## 基礎值是 12

`+72h` 是基礎移動力。建角常式（overlay-16 `1C0Bh`）寫 12，overlay-12 `0B96h`
也寫 12；原版七名預設人物的 `+72h` 全部是 12。被 Animate Dead 叫起來的不死
生物寫 6（overlay-22 `2115h`，在該法術的處理常式裡）。

## 重算：`+11Ch = +72h`

overlay-25 `0E36h` 那一段是「把衍生值抄回基礎值」：

| 寫入 | 來源 | 意義 |
|---|---|---|
| `+101h` | 常數 0 | 豁免修正（spec 075）|
| `+111h` | `+A9h` | 內部 AC ← 基礎 AC |
| `+11Ch` | `+72h` | 目前移動力 ← 基礎移動力 |
| `+110h` | `+2Dh` | 內部 THAC0 ← 基礎 THAC0 |

四對「基礎／目前」欄位在同一段裡一起重設，彼此印證。

## 盔甲：overlay-25 `01F8h`

一次一件物品（`bp+6` 是物品、`bp+0Ah` 是角色）。先看物品型別表
（`DS:54E0h + 型別 × 16` 的第 0 個 byte，spec 065）：**不是類別 2 就直接返回**，
所以只有盔甲影響移動力。

| 物品 `+37h` 的重量 | `+11Ch` |
|---|---|
| 0..150 | `+72h`（基礎）|
| 151..399 | 9 |
| 其餘（含負值）| 6 |

之後如果物品 `+32h` 的加值不為零，而且算出來的移動力 ≤ 9，就再 +3——
魔法盔甲等於輕一級。

## 負重：overlay-25 `03C5h`

輸入是一個總重（負值先夾成 0）：

| 總重 | 得到 |
|---|---|
| 0..512 | 維持原值 |
| 513..768 | 9 |
| 769..1024 | 6 |
| 1025 以上 | 3 |

**這條只會往下壓**（`cmp; jae` 之後才寫），不會把已經被盔甲壓低的值調回去。

## `+11Ch` 在原版存檔裡不是好 oracle

七名預設人物的 `+11Ch` 是 3、9、9、12、3、3、12，用上面三條規則搭配他們
`.itm` 裡的物品**推不出來**：

- `chrdatd1` 是戰士 8，穿 Plate Mail +3（重 300、有加值）。盔甲規則給
  151..399 → 9，加值再 +3 → 12；負重總和 960 → 6。兩條都不是 3。
- `chrdatd6` 是法師 6，身上一件盔甲都沒有，總重約 255，兩條規則都不會動它，
  應該留在 12，實際是 3。

同一個欄位至少有三支常式寫（`01F8h`、`0421h`、`0E5Dh`），而 `0E5Dh` 是
「重設成基礎值」。合理的讀法是 **`+11Ch` 是「當下還剩多少移動力」而不是
「算出來的移動速率」**，SSI 出貨的那幾個檔案存的是某個當下的殘值——
但這還沒證實，所以列為 DRAFT。

**在證實之前不要拿這七個數字當驗收目標**。要驗證上面三條規則，得另外找
一個能控制輸入的量測點（例如在模擬器裡讓角色換裝再讀記錄），不是拿出貨檔
回推。
