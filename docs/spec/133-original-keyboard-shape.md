# Spec 133：原版怎麼讀鍵盤

狀態：READY（唯一的讀鍵入口與它對擴充鍵的處置、選單元件的方位鍵集合與
轉換表、實測哪些鍵在種族選單有作用）；DRAFT（為什麼只有 `1` 有作用、
`[bp+0Ch]` 這個參數的呼叫端語意）。
日期：2026-09-09。

## 結論先講

**原版只有一個讀鍵入口，而它對方向鍵回 `#0`。** 想用自動化在原版選單裡
移動，送方向鍵不會有反應——這不是模擬器的問題。

## 輸入

- `START.EXE` SHA-256 `12811cbc8166a9e753283e972a7396db566e37e81ff1b272e34833d99b810d9f`
- `overlay-26.bin`（`GAME.OVR` 抽出）
- dosgolem 的按鍵軌跡（`cmd/shots -keytrace`，dosgolem `docs/spec/185`）

## 唯一的讀鍵入口：`026B:0048`

IDA 認得 Borland 符號：這一支呼叫 `@READKEY$qv` 與 `@KEYPRESSED$qv`
（Turbo Pascal 的 Crt unit）。全遊戲只有它在讀鍵——`START.EXE` 三處、
overlay-09／21／26／30／35／37 各一兩處，沒有別條路。

```
ch := ReadKey
if ch = #19 then …切音效…
if ParamStr(1) = 'STING' then …兩個除錯鍵（#4、#3）…
loop: if ch = #0 then Result := ch          ← 擴充鍵就這樣回去了
      if not KeyPressed then Result := ch
      ch := ReadKey; goto loop              ← 把緩衝區剩下的鍵吃掉，只留最後一個
```

兩件事因此定了下來：

1. **擴充鍵回 `#0`。** 呼叫端得自己再叫一次才拿得到掃描碼（Turbo Pascal 的
   `ReadKey` 把掃描碼留在 RTL 的 pending 變數 `DS:82C9h`）。
2. **尾巴那個迴圈會把緩衝區裡剩下的鍵吃光**，只留最後一個非零的。所以
   一次送一串鍵給它，中間那幾個會消失。

## 選單元件：overlay-26 `00E4h`

```
02C8  KeyPressed 為假就回迴圈頂
02D4  ch := 讀鍵
02DC  ch ≠ 0 → 跳到 02FE 的比對鏈
02E2  ch = 0（擴充鍵）→ 再讀一次拿掃描碼
02EA  [bp+0Ch] ≠ 0 → 設「這是方向鍵」旗標並回傳掃描碼
      [bp+0Ch] = 0 → 忽略，回迴圈頂
02FE  ch = 1Bh（ESC）／0Dh（Return）各自處理
031F  其餘走 5BBh:1837h（大寫化）之後比對呼叫端傳進來的字元表
035B  [bp+0Ch] ≠ 0 且 ch 在集合 0C4h 裡 → 查表轉成掃描碼，設旗標並回傳
```

集合 `0C4h`（Pascal 的 set of char，32 bytes）是 **`123456789`**。
轉換表在 `DS:289Eh`，以 `ch − '1'` 為索引：

| 鍵 | `1` | `2` | `3` | `4` | `5` | `6` | `7` | `8` | `9` |
|---|---|---|---|---|---|---|---|---|---|
| 值 | `4Fh` | `50h` | `51h` | `4Bh` | `20h` | `4Dh` | `47h` | `48h` | `49h` |
| 對應 | End | Down | PgDn | Left | 空白 | Right | Home | Up | PgUp |

也就是**主鍵盤數字列的 `1`..`9` 對應數字鍵盤那一圈的方位**，排法與數字鍵盤
的實體位置相同（`7 8 9` 在上、`1 2 3` 在下）。

## 實測：種族選單只吃 `1`

建角的種族清單（`DWARF`／`ELF`／`GNOME`／`HALF-ELF`／`HALFLING`／`HUMAN`），
每按一次鍵之後逐格比對整張畫面：

| 送的鍵 | 字組 | 畫面差異 |
|---|---|---|
| `1` ×5 | `0231h` | 反白逐格從 `DWARF` 走到 `HUMAN` |
| `2`、`8` | `0331h`／`0938h` | 0 個像素 |
| `Down`、`KP2` | `5000h` | 0 個像素 |
| `P`（`50h` 當成字元） | `1950h` | 0 個像素 |
| `Space`、`Tab` | — | 0 個像素 |

**為什麼只有 `1`（轉成 `4Fh` ＝ End）有作用還沒解。** 要往上追到選單的
呼叫端才答得出來——那一層決定 `[bp+0Ch]`，也決定拿到掃描碼之後做什麼。

## 對自動化的意思

- **在原版選單裡移動就送 `1`。** 方向鍵送得到（`int 16h AH=00` 回 `5000h`、
  程式也讀走了），但那一層不處理它。
- 一次只送一個鍵。連送一串會被讀鍵層尾巴那個迴圈吃掉中間幾個。
- 要確認「鍵到底被誰讀走、讀到什麼」，用 `cmd/shots -keytrace`：它印出
  字組、走哪一條出口、呼叫端的返回位址。這次就是靠它把三個鍵回溯到同一個
  `1E03:02D9`，再對回 overlay-26 的 `02D4` 一次命中。
