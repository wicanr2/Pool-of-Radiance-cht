# Spec 112：效果代碼的分派（overlay-24 entry 3／entry 1 與 `014Dh`）

狀態：READY（三支的簽章、二十組的代碼表、有作用範圍的那四個代碼、
`DS:6786h` 那張表怎麼填、否決 `DS:677Ch` 的四個代碼，以及群組編號的意思
——效果系統就是原版套用命中與豁免修正的機制——都讀出來了；
115 支處理常式已有機器盤點，逐支的語意還沒閉合）。
日期：2026-09-05。

## 為什麼要讀這一支

spec 096 把 overlay-24 entry 3（`02E2h`，2051 bytes）列成「還沒讀」，而怪物
AI 的「這個候選能不能打」（overlay-13 `1087h`）整個靠它：`1087h` 只是把
`DS:677Ch` 清成 0、問兩次、再看那個 byte 有沒有被立起來。

```
1087  f(候選: far; 自己: far): boolean      ; retf 8
1091  候選為 NULL → 回 false
109c  候選就是自己 → 回 true
10b1  DS:677Ch = 0
10b6  0100h:002Fh(1, 候選)                  ; overlay-24 entry 3，群組 1
10c4  DS:677Ch != 0 → 1117h
10cb  存下自己 runtime +0Ah／+0Ch（目前的目標）
10df  把目標暫時換成這個候選
10f4  0100h:002Fh(0, 自己)                  ; 群組 0
1102  還原 +0Ah／+0Ch
1117  DS:677Ch 仍為 0 → 回 true，否則 false
```

群組 0 只有一個代碼（`7Eh`），而且是**對自己**問的——先把自己的目標指向候選
才問，所以 `7Eh` 的處理常式讀的是行動者當下的目標。

## 三支的分工

| 位置 | 簽章 | 做什麼 |
|---|---|---|
| overlay-24 entry 3（`02E2h`）| `f(群組: byte; 記錄: far)`，`retf 6` | 純表：對群組裡的每個代碼各呼叫一次 `014Dh` |
| overlay-24 `014Dh`（近呼叫）| `f(代碼: byte; 記錄: far)`，`retf 6` | 判斷這個代碼代表的效果會不會影響到這筆記錄 |
| overlay-24 entry 1（`0000h`）| `f(代碼: byte; 記錄: far; 節點: far; 模式: byte)`，`retf 0Ch` | 用代碼查 `DS:6786h` 的遠指標表，把 (記錄, 節點, 模式) 交給那個代碼自己的處理常式 |

`02E2h` 是一個 20 路的 `case`，除了選群組之外沒有任何判斷——2051 bytes 幾乎
全是 140 次相同形狀的呼叫。

## `014Dh`：這個效果影響得到誰

```
014d  f(代碼: byte; 記錄: far)
0154  命中 = 0
0159  走訪指標 = DS:5CF4h                    ; 戰鬥者串列頭
0167  overlay-25 entry 27(記錄, 代碼, &節點)  ; ＝ 21DCh，spec 059 的效果串列走訪
017e    有 → 命中 = 1，跳到收尾
0188  代碼不在 CS:012Dh 那個集合裡 → 跳到收尾（命中仍為 0）
019b  把 DS:6679h 起的 0D8h bytes 存進區域緩衝
01af  對串列上的每一個戰鬥者：
01bc    命中已經是 1 → 停
01c6    overlay-25 entry 27(這一個, 代碼, &節點) → 沒有就換下一個
01e4    DS:4954h != 5 → 命中 = 1              ; 不在戰術地圖上就不算距離
01ee    半徑 = (代碼 == 31h) ? 6 : 1
0200    x／y／體型 = overlay-32 entry 15／16／17(這一個)
0234    近鄰查詢(DS:6674h 的戰術地圖, x, y, 半徑, 0FFh, 體型)
0241    n = DS:6678h；逐筆比 DS:[6676h + i × 3] 是不是「我」的索引
027c      是 → 命中 = 1
0292    走訪指標 = 這一個的 +104h            ; 串列的下一個
02a8  還原 DS:6679h 的 0D8h bytes
02bc  命中 → overlay-24 entry 1(代碼, 記錄, 節點, 0)
02df  retf 6
```

兩條路：**自己身上帶著**這個效果，或者**站在別人的作用範圍裡**。後者只對
`CS:012Dh` 這個集合裡的四個代碼成立——`15h`、`2Dh`、`2Eh`、`31h`，其中 `31h`
的半徑是 6，其餘是 1。集合常數是 Turbo Pascal 的 32-byte 位元集，逐位元展開
就是這四個值。

`019Bh` 與 `02A8h` 把 `DS:6679h` 起的 216 bytes 存下來又還原，是因為中間的
近鄰查詢會覆寫那張表（spec 056 的鄰近查詢結果表就在 `DS:6676h`）——呼叫端
可能正拿著那張表在用。

## `DS:6786h` 那張表

`call dword ptr [di+6786h]` 裡的 `6786h` 是 **Turbo Pascal 的偏移基底**，不是
表的第一格。表宣告成 `array[1..N] of far pointer`，實際落在 `678Ah`，編譯器把
基底寫成 `678Ah − 4 × 1 = 6786h`（`combat.DisablingEffectCodes` 的
`DS:2880h` 折疊基底 `287Fh`、索引 1..4 是同一個手法）。所以 `6786h..6789h`
那四個 byte 是別的變數——overlay-12 `0152h` 就把 `DS:6784h`／`6786h` 當成
「目前目標」的遠指標在用。**看到 `[di + 常數]` 的表不要假設常數就是第一格。**

填表的是 **overlay-12 entry 1（`31B2h`）**，一長串直線寫入：

```
31b5  ax = 0039h；dx = 006Ch
31bb  DS:678Ah = ax；DS:678Ch = dx      ; 代碼 1 → 006Ch:0039h
31c2  ax = 003Eh；…                     ; 代碼 2 → 006Ch:003Eh
…
```

`006Ch` 是 overlay-12 自己的 stub segment（spec 109），偏移換算回進入點是
`(offset − 20h) ÷ 5`。整支填了 **138 格，代碼 1 到 139**；漏掉的 `58h` 由
**overlay-22 `3760h`** 另外填。處理常式的落點：136 個在 overlay-12，
2 個在 overlay-13（代碼 `49h`、`4Ah`，`0096h` 段）。

處理常式的簽章是 `f(記錄: far; 節點: far; 模式: byte)`，`retf 0Ah`。
**模式有兩個值**：`014Dh` 命中時傳 0（套用），overlay-24 entry 2（`0028h`）
把節點摘掉之前傳 1（收尾）。entry 2 順帶把效果串列的版面補齊：節點 9 bytes，
`+0` 代碼、`+4`「有收尾常式」旗標、`+5`／`+7` 下一個的遠指標，串列頭在記錄
`+7Fh`／`+81h`，釋放走 RTL 的 FreeMem。

## `DS:677Ch` 是誰立起來的

不是那三支分派。全 36 顆 overlay 與 `START.EXE` 掃過 `A2 7C 67`／
`C6 06 7C 67`／`A0 7C 67`／`80 3E 7C 67` 四種存取形狀：

| 檔案 | 寫 | 讀 |
|---|---|---|
| overlay-12 | `0946h`（entry 25）、`0C52h`（entry 35）、`173Ah`（entry 66）、`2ECAh`（entry 120）| `2E84h`（entry 120）|
| overlay-13 | `10B1h`（`1087h` 清成 0）| `10C4h`、`1117h` |

拿表一查，那四個進入點就是四個效果代碼：

| 進入點 | 代碼 | 做什麼 |
|---|---|---|
| entry 25（`0927h`）| `19h` | 問 `DS:5CF0h` 指到的那一位有沒有效果 `18h`，**沒有**就 `677Ch = 1`；接著 `DS:6780h −= 4`（無條件）|
| entry 35（`0C40h`）| `25h` | 記錄的 runtime `+3`（先攻分數）大於 0 → `677Ch = 1`、`DS:6780h = FFh` |
| entry 66（`1737h`）| `47h` | 直接 `677Ch = 1`、`DS:6780h −= 4` |
| entry 120（`2E50h`）| `7Eh` | 走**目標**（`+108h` 的 `+0Ah`）的物品串列（`+0C8h` 起、`+2Ah` 接下一個），某一格的 `+2Eh + i` 是 `98h` 而 `+31h` 是 `FCh`，或 `+2Eh + i` 是 `76h` → `677Ch = 1` |

於是 `1087h` 的「能不能打」完全展開了：

- 群組 1 問候選：`19h`、`25h`、`47h` 三個會否決，**`3Fh` 不會**——它指到
  overlay-12 entry 126（`31A9h`），那是一支 `push bp; mov bp,sp; mov sp,bp;
  pop bp; retf 0Ah` 的**空常式**（代碼 `05h` 也指到它）。
- 群組 0 問自己：`7Eh` 讀的是**自己當下的目標**，所以 `1087h` 才要先把
  `+0Ah`／`+0Ch` 暫時換成候選再問（`10CBh`..`1102h`）。

`DS:6780h` 是這些常式共用的另一個累加格（entry 66 減 4、entry 35 寫 `FFh`、
overlay-12 `0165h` 加 2），語意還沒對。

## 群組在做什麼

把呼叫端逐個讀出來之後，群組編號就有了名字——**效果系統就是原版套用戰鬥
修正的機制**，`0100h:002Fh` 是那個掛勾點：

| 群組 | 呼叫端 | 意思 |
|---:|---|---|
| 0 | overlay-13 `10FDh` | AI 判「我能不能打這個候選」時問**自己**（`7Eh` 讀的是自己當下的目標）|
| 1 | overlay-13 `10BFh` | 同上，問**候選** |
| 7 | overlay-08 `021Ah` | 反應攻擊的否決（＝ `DS:2880h` 那四個，spec 059）|
| 0Ah（10）| overlay-24 entry 6 `0CF3h` | **攻擊者**身上會影響命中的效果 |
| 0Ch（12）| overlay-24 entry 7 `0DB2h` | **豁免**的修正（spec 075）|
| 10h（16）| overlay-24 entry 5 `0C81h`、entry 6 `0D00h` | **目標**身上會影響命中的效果 |
| 12h（18）| overlay-13 entry 1 `005Eh` | 每回合初始化時調整攻擊次數的工作值 `DS:6778h` |
| 6 | overlay-24 entry 19 `1351h` | 套用**傷害**時的修正（`DS:6776h`）|
| 4 | overlay-13 `021Eh` | 近戰**傷害骰**算完（含背刺倍數）之後的修正 |
| 0Eh（14）| overlay-09 `0B66h` | 怪物接近迴圈裡問的 |
| 11h（17）| overlay-09 `1172h`／`11C5h` | 士氣那一段 |

三個累加格因此也定了下來：

| 位址 | 是什麼 | 由誰擲 |
|---|---|---|
| `DS:6780h` | **命中骰**（1d20，自然 1 直接失手、自然 20 改寫成 100）| overlay-24 entry 5／6 |
| `DS:6774h` | **豁免骰**（1d20 加 `+101h` 與呼叫端修正）| overlay-24 entry 7（spec 075）|
| `DS:6788h` | 目前這一次的**豁免類別**，給效果常式判斷該不該加成 | 同上 |
| `DS:6776h` | **傷害量**。近戰由 overlay-13 `01CFh` 擲出來寫進去（背刺倍數在這之後乘，spec 050），套用時由 overlay-24 entry 19 再讀一次 | 兩處 |
| `DS:6777h` | 傷害訊息的旗標：低三位選句型（`13DEh` 的 `and 0F7h` 之後比 1／2），位元 3 另一個（`14ABh` 的 `and 8`）| 由施法的處理常式（overlay-22）設 |

所以「效果碼 `47h` 讓 `DS:6780h` 減 4」就是「這個效果讓對它出手的攻擊 −4」。

傷害那一支的順序值得記：**先讓群組 6 調整 `DS:6776h`，才套豁免**——
`1354h` 之後，豁免規則 1 是全免（傷害寫 0）、規則 2 是減半（整數除 2）。
所以「減半」減的是效果調整過的值，不是原始骰值。

## 一百一十五支處理常式的覆蓋台帳

`docs/audit/dos-effect-handlers.json` 是機器產生的盤點：138 個在 overlay-12 的
代碼對到 **115 支相異處理常式**（有些代碼共用一支），另外 `49h`／`4Ah` 在
overlay-13、`58h` 由 overlay-22 填。每一支記了大小、指令數、寫了哪些全域、
碰了記錄的哪些欄位、呼叫了哪些跨 overlay 進入點。

幾個一眼看得出來的分群：

- **十二個代碼指到空常式**（entry 126／18／49／50，9–12 bytes，`retf 0Ah`
  什麼都不做）。它們在群組表裡出現，但永遠不會改變任何東西。
- **四支會立起 `DS:677Ch`**（否決）：entry 25 ＝ `19h`、35 ＝ `25h`、
  66 ＝ `47h`、120 ＝ `7Eh`。
- **依代碼數計的全域寫入**：`6780h`（命中骰）20 個、`6776h` 19 個、
  `6774h`（豁免骰）16 個、`6784h`／`6786h`（目前目標的遠指標）13 個、
  `6777h` 7 個、`677Ch` 4 個。
- 最大的五支是 entry 37（`28h`，728 bytes）、76（`53h`）、77（`54h`）、
  122（`83h`）、68（`4Bh`）。

## 效果的生命週期

五支撐起整個系統：

| 位置 | 做什麼 |
|---|---|
| overlay-24 entry 10（`0E54h`）| **掛上**一個節點：`GetMem(9)`，接在記錄 `+7Fh` 串列的**尾端** |
| overlay-24 entry 2（`0028h`）| **摘掉**並 `FreeMem(9)`；`+4` 非 0 時先以模式 1 叫一次處理常式 |
| overlay-24 entry 1（`0000h`）| 用代碼查 `DS:678Ah` 的表，分派給那個代碼自己的處理常式 |
| overlay-24 entry 3（`02E2h`）| 群組 → 一串代碼 |
| overlay-24 `014Dh` | 這個代碼影響不影響得到這筆記錄 |

節點是 **9 bytes**，欄位由 entry 10 的參數填：

```
0e54  f(記錄: far; 代碼: byte; 持續: word; 等級: byte; 有收尾: byte)   retf 0Ch
+0     代碼
+1..+2 持續（word）
+3     下效果者的等級（低四位；0FFh 代表解除魔法解不掉，spec 098）
+4     「摘掉時要叫一次處理常式」旗標
+5..+8 下一個節點的遠指標
```

掛上去是**接在尾端**不是插在頭：`0E98h` 沿 `+5` 走到 NULL 才接。所以效果的
順序就是掛上去的順序，而 `21DCh`（spec 059）的線性搜尋找到的是**最早掛上**
的那一個。

**21 個代碼會呼叫 entry 10**——那些效果會替自己掛節點；**15 個會呼叫
entry 2**——那些會把自己（或別的代碼）摘掉。25 個只呼叫 RTL 的字串常式，
也就是只印一句話。

## 四十八個代碼的修正算式

處理常式對累加格的改動可以機械抽出來（`ds:<格>, <值>` 這個形狀）。
115 支裡有 **48 個代碼**直接改累加格，逐條如下。其餘的做別的事——換句話說，
「還沒讀」的範圍已經從 115 支縮到「不直接改修正的那些」。

| 代碼 | 對命中骰 | 對豁免骰 | 對傷害 | 其他 |
|---|---|---|---|---|
| `01h` | | | | 士氣 +5 |
| `02h` | | | | 士氣歸零再 −5 |
| `03h` | +2 | | +2 | |
| `06h` | +N | | +N | 傷害訊息 = 9 |
| `08h`／`09h` | −2 | +2 | | |
| `0Ah`／`14h` | | +3 | 覆寫 | |
| `11h` | | | **歸零** | |
| `19h`／`47h` | −4 | | | 否決（`DS:677Ch`）|
| `21h`／`24h` | −4 | −4 | | |
| `25h` | **FFh**（自動落空）| | | 否決 |
| `2Dh`／`2Eh` | −2 | +2 | | |
| `2Fh`／`30h` | −4 | | | |
| `3Dh` | | +4 | −2 再覆寫 | |
| `59h` | **FFh**（自動落空）| | | |
| `5Ah`／`61h` | | 覆寫 | | |
| `6Fh`／`7Dh` | | **= 100**（自動成功）| | |
| `71h`／`72h`／`76h`／`5Dh` | | | 覆寫 | |
| `7Ah` | | | 覆寫再加 | |
| `7Eh` | | | | 否決 |

**與 spec 115 對得上**：`21h` 是神殿治得好的**失明**、`24h` 是**詛咒**，
而它們的效果都是「命中 −4、豁免 −4」。兩份各自解出來的東西吻合，
所以這張表的讀法是對的。

`03h`（命中 +2、傷害 +2）與 `01h`（士氣 +5）看起來就是祝福術那一組。

一支常式可以同時碰好幾個累加格——它不知道是誰叫它的，而呼叫端只會讀自己
關心的那一格，所以無關的寫入沒有副作用。

推變數的反例。群組 2、3、6、9、10、12、16 沒有出現在表裡，可能是被變數形式
的呼叫用掉的。`START.EXE` 也掃過，常駐段一次都沒有呼叫這一支。

## OPEN

- 115 支處理常式裡逐條讀過內容的有六支（entry 25／35／66／120／126 與
  overlay-12 entry 1）。其餘的已經有機器盤點（大小、碰哪些欄位、呼叫誰），
  但語意還沒逐支閉合。
- overlay-13 `1726h` 那一處讀 `DS:6776h` 的用途（`01CFh` 那一處已經確認是近戰
  傷害骰，spec 050）。
- 代碼的編號與法術編號**不是同一套**：`33h` 在法術表是閃電束（spec 069），
  在這裡是反應攻擊否決的四個之一。兩套編號要分開看。
- 群組編號的語意（哪一組是「不能移動」、哪一組是「看不見」……）要等處理常式
  讀出來才給得出名字，現在只有代碼清單。
