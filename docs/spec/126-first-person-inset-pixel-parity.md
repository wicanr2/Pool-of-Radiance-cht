狀態：CONFORMED（兩張原版基準圖 **7744/7744 逐格相同**；遮罩的機制是
**另一張 AND 點陣圖，不是顏色鍵**）；DRAFT（那張遮罩自己從哪裡填進來）。
日期：2026-09-06。

`TestFirstPersonInsetMatchesTheDOSShot` 的兩個位置都是 **100.0%**：

## 一、`PostWall` 只蓋黑的

`viewport.FillBackgroundToStageInset` 回傳兩塊：牆片**之前**畫的 `Backdrop`
與**之後**畫的 `PostWall`。`PostWall` 存在的理由寫在 spec 047——
「牆片合成後，斜邊素材的黑底還會重新蓋住頂部角落」。

**要復原的是那些變成黑色的格子，不是整條 row。** 整條蓋會把真的牆片一起洗掉：
城門那一格 `(0,4)` 左上角有一個 120 格的灰色三角（原版 EGA 7），整條蓋之後
變成天空 B，對拍從 97.6% 掉到 97.0%。

這是**套用規則**，不是 engine 的輸出變了——`FillBackgroundToStageInset`
回傳的矩形一模一樣，改的是消費端怎麼貼。

## 二、符號色號 `0Dh` 不畫

8×8 牆面符號裡的 `0Dh`（EGA 13 洋紅）**不畫，讓背景透出來**。

證據是逐格的。把它畫出來的時候，兩張基準圖的差異**全部**是同一個形狀
——「remake 是 D、原版是那一區的背景」：

```
拱底左側 (x=32,y=56)      拱底右側 (x=48,y=56)     左上角 (x=0,y=0)
 remake   原版             remake   原版            remake   原版
00000008 00000008         80000000 80000000        DDDDDDDD BBBBBBBB
0000008D 00000086         D8000000 68000000        7DDDDDDD 7BBBBBBB
000008DD 00000866         DD800000 66800000        77DDDDDD 77BBBBBB
00008DDD 00008666         DDD80000 66680000        777DDDDD 777BBBBB
```

形狀一模一樣，只有顏色不同：地平線以下透出地面棕 `6`、以上透出天空 `B`、
城門那邊透出灰 `7`。**原版截圖的調色盤裡根本沒有洋紅**。
跳過之後兩張都是 7744/7744。

### 機制讀出來了：是**另一張遮罩點陣圖**，不是顏色鍵

`Put8x8Symbol`（overlay-35 `015Dh`）在 `[bp+8]` 非零時走
**overlay-36 entry 8（`08F5h`）**。開頭決定要不要走遮罩路徑：

```
08FB  al = [bp+0Eh] & 1                  ; 旗標位元 0 ＝ 要求遮罩模式
0904  ax = es:[di+13h] | es:[di+15h]     ; 圖片記錄裡的遮罩遠指標
090F  兩者都成立才 [bp-16h] = 1
```

`[bp-16h]` 為 1 時走 `0A10h` 那一支，逐位元組貼：

```
0A7A  cl = 來源圖  [記錄 +17h + 位移]      ; 像素資料（+17h 是資料起點）
0A84  les di, es:[記錄 +13h]              ; **遮罩的遠指標**
0A8A  dl = 遮罩[位移]                     ; 同一個位移的遮罩位元組
0A95  al = 目的地 [+17h + 位移]           ; 畫面上現有的像素
0A99  al &= dl                            ; **目的地 AND 遮罩**
0A9B  al |= cl                            ; **再 OR 來源**
0AA7  目的地[+17h + 位移] = al
```

這就是教科書式的 **AND 遮罩 ＋ OR 圖形**：遮罩位元是 1 的地方保留背景、
是 0 的地方讓圖形蓋上去。`[bp-16h]` 為 0 時走 `0AECh`，整列直接
`05BB:1692h`（Turbo Pascal 的 `Move`）複製過去，沒有透明可言。

**所以「哪一個值算透明」這個問題問錯了**——引擎不看顏色，看的是另一張
同樣大小的遮罩。overlay-36 全檔沒有任何對 `0Dh` 的立即數比較，正是因為
根本不存在顏色特判。remake 跳過 `0Dh` 得到的逐格 100% 仍然成立，
它只是把「素材的遮罩恰好留白的那些格」用顏色反推出來而已。

**還沒讀的縮小成一格**：記錄 `+13h`／`+15h` 那張遮罩是誰在載入時填的
（牆片素材本身有沒有帶遮罩、還是繪製前現算）。這一格不影響像素結果，
因為兩張基準圖已經逐格對上。

## 對共用 engine 的意思

兩條都在**消費端**，engine 的輸出沒有變，所以 CoAB 不受影響。
`PostWall` 的套用規則已經寫進 `viewport` 的註解，免得下一個作品又整條蓋。
