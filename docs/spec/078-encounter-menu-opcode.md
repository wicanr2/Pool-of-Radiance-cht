# Spec 078：`29h ENCOUNTER MENU`

狀態：CONFORMED（運算元陣列的版面與十四個運算元的型別與用途、四個選項的
字面、怪物逼近的走法、隊伍移動力的算法、四個選項各自寫回哪個結果碼；
remake 已接上並走得到索寇要塞的第一場戰鬥）；DRAFT（結果碼 0..3 在 ECL
那邊各自代表什麼、`4933h+1CCh` 那個條件、類型 3 選 ADVANCE 那一格）。
日期：2026-09-03。

## 為什麼先讀它

只用按鍵從標題走出去（`TestNormalKeysReachTheFirstDungeonStep` 的路徑再往下
走），隊伍會搭船抵達索寇要塞（archive 4、block 21），然後停在

```
continue Pool SearchLocation: opcode 0x29 at 1288 has no core handler or adapter passthrough
```

同一條路上隨機走 4000 步，**一次戰鬥都沒觸發**。這條 opcode 是目前主線最前面
的攔路石。

## 運算元怎麼存

取運算元的常式是 overlay-07 entry 2（code `0000h`）。ECL 的 PC 放在
`DS:494Eh`，指令位元組從 `[DS:493Fh] + 6700h` 讀。每個運算元 `i`（1 起算）
拆成三個平行陣列：

| 陣列 | 位址 | 內容 |
|---|---|---|
| 型別 | `DS:6DCBh + i` | 型別碼；1、2、3 表示後面還有一個高位元組 |
| 低位元組 | `DS:6E4Bh + i` | 值的低 8 位 |
| 高位元組 | `DS:6E0Bh + i` | 值的高 8 位（只有型別 1..3 才有）|

`0045h:0025h` 回傳低位元組；要 16 位的值就自己把兩個陣列合起來
（`0045h:0052h` 就是 `(高 << 8) | 低`）。

## 十四個運算元

`20B1h` 開頭 `mov al, 0Eh / lcall 0045h:002Ah` 一次取 14 個。

| 運算元 | 取用處 | 用途 |
|---:|---|---|
| 1 | `20E4h` → `DS:6D47h` | 訊息索引，交給描述字串常式 |
| 2 | `20EFh` → 記錄 `+580h` | 距離上限 |
| 3 | `2100h` → `DS:6D48h` | 第二個訊息索引 |
| 4 | `210Bh`／`210Fh`（直接讀兩個陣列）| **結果要寫進哪個 ECL 變數**（16 位位址）|
| 5..9 | `212Dh` 的迴圈 → `[bp-6+i]` | 五格結果表，用選單的選擇當索引 |
| 10..12 | `2151h` 的字串複製迴圈 | 三段打包文字，抄到 `DS:6D8E + i × 256` |
| 13 | `2189h` | 逃跑門檻，和隊伍**最慢**的移動力比 |
| 14 | `2195h` | 另一個門檻，和隊伍**最快**的移動力比 |

## 運算元的型別是量出來的

把索寇要塞那一批 `29h` 解出來，十四個運算元的型別碼一模一樣：

```
[00 00 00 01 00 00 00 00 00 80 80 80 00 00]
```

- `00` 是一個 byte 的常數：運算元 1、2、3、5..9、13、14。
- **運算元 4 是 `01`——帶位址的記憶體運算元**。所以要用 `WordAddress` 取它的
  位址，不能用 `NumericValue`：後者取的是那個變數**現在的內容**，拿去當位址
  會寫到別的地方，而且不會報錯。
- 運算元 10、11、12 是 `80`，打包文字。那正好對上 `2151h` 那段把三段字串抄到
  `DS:6D8E + i × 256` 的迴圈。

## 選單就是金盒子那四個選項

字面常數就放在常式前面：

| 位址 | 字串 |
|---|---|
| `2054h` | `~COMBAT ~WAIT ~FLEE ~PARLAY` |
| `2070h` | `~COMBAT ~WAIT ~FLEE ~ADVANCE` |
| `208Dh` | `Both sides wait.` |
| `209Eh` | `The monsters flee.` |

`~` 標的是快速鍵。`2333h` 決定用哪一版：記錄 `+582h` 為零，或
`[DS:4933h] + 1CCh` 為零，就用 PARLAY 那一版，否則用 ADVANCE。
選單輸入走 `0045h:0089h`（overlay-07 entry 21）。

## 怪物離隊伍幾格：`0045h:0043h`

`+582h` 是**怪物與隊伍的距離**，由 `0045h:0043h(DS:6A0Bh, 6A0Ch, 6A0Dh)`
算出來（overlay-07 `0489h`），再夾到運算元 2 給的上限。那三個全域是怪物那
一群在地圖上的 x、y 與朝向；朝向用的是 **0／2／4／6**（0 北 y−1、2 東 x+1、
4 南 y+1、6 西 x−1），與牆面查詢同一套，不是隊伍朝向那套 0..3（spec 076）。

常式最多讓怪物往前走兩步（`lcall 0131h:0034h` 一步，撞到就停），回報走了
幾步。`[DS:4933h] + 1CCh` 為零時直接給 2，不走。

`0045h:004Dh` 拿兩個訊息索引與這個距離組出描述字串放到 `DS:828Eh`。
選 PARLAY 或 ADVANCE 就把 `+582h` 減一並重組描述——那就是雙方再靠近一格。

## 隊伍移動力：`1F87h`

`20D4h` 呼叫的 `1F87h` 走一遍隊伍串列（頭在 `DS:5CF4h`，下一個在記錄
`+104h`），逐人取記錄 `+11Ch` 的移動力，並且

- 身上有效果碼 `27h`（Haste）→ 移動力 ×2
- 否則有效果碼 `2Ah`（Slow）→ 移動力 ÷2

再把**最大值**與**最小值**分別寫回兩個輸出參數。查效果用的是
`010Ah:00A7h`，也就是 spec 069 那支效果串列搜尋。

`27h` 與 `2Ah` 正好是 spec 074 從參數表 `+0Ah` 解出來的 Haste 與 Slow 的
效果碼——兩條獨立的證據鏈在這裡對上了。

## 結果寫回 ECL 變數

選完之後：

選完之後先查五格結果表：`類型 = 運算元(5 + 選擇)`，再依「類型 × 選擇」
決定寫哪個結果碼。

```
23B2  選單索引 3 且（+582h == 0 或 +1CCh == 0）→ 索引改寫成 4
23BC  di = 索引
23C3  al = [bp-6+di]          ; 五格結果表 → 類型
23D0  類型 0 → 23D5
2413  類型 1 → 241Bh
2531  類型 2 → 2539h
25E5  類型 3 → 25EDh
26D3  類型 4 → 26DBh
```

**第四項的索引要看它顯示什麼**：`23B2h` 的改寫條件與「第四項顯示 PARLAY」
的條件是同一個（`+582h == 0` 或 `+1CCh == 0`），所以

- 第四項是 **PARLAY** → 表的第 **4** 格；
- 第四項是 **ADVANCE** → 表的第 **3** 格。

| 類型 | 選擇 | 行為 |
|---:|---|---|
| 0 | 除 FLEE 以外 | 寫 1 |
| 0 | FLEE | 隊伍最慢的移動力 ≥ 運算元 13 就寫 2，否則寫 1 |
| 1 | COMBAT | 寫 1 |
| 1 | WAIT | 印 `Both sides wait.`，回選單再問一次 |
| 1 | FLEE | 寫 2 |
| 1 | ADVANCE（`2483h`）| 距離大於零就減一、重組描述、回選單；為零就印 `Both sides wait.` 回選單 |
| 1 | PARLAY（`24E9h`）| 距離大於零就減一、回選單；**為零就寫 3** |
| 2 | COMBAT | 運算元 14 > 隊伍最快的移動力就寫 0 並印 `The monsters flee.`，否則寫 1 |
| 2 | 其餘 | 寫 0，印 `The monsters flee.` |
| 3 | COMBAT | 寫 1 |
| 3 | WAIT／ADVANCE（`260Ch` 同時比 1 與 3）| 距離大於零就減一、回選單；為零印 `Both sides wait.` |
| 3 | FLEE | 寫 2 |
| 3 | PARLAY（`2686h`）| 距離大於零就減一、回選單；**為零就寫 3** |
| 4 | COMBAT | 寫 1 |
| 4 | FLEE | 寫 2 |
| 4 | WAIT／ADVANCE／PARLAY（`26F4h` 同時比 1、3、4）| 距離大於零就減一、回選單；**為零就寫 3** |

**交涉真的成立時寫的是 3。** 先前這一節把 PARLAY 當成表的第 3 格、
ADVANCE 當成第 4 格，於是索寇要塞登陸的那個亡魂（ecl4/21 `AA0Ah`，
五格類型表是 `0 3 1 1 4`）選 PARLAY 會查到類型 1 而不是類型 4，
落進「印字再問一次」的分支——**選單永遠關不掉**，那一段主線也就走不下去。

`0045h:0070h`（overlay-07 `0C93h`）不是跳位，是**寫 ECL 變數**：它先用位址
分出三個記憶體區（`DS:4933h`／`4937h`／`493Bh`）再把值寫進去。所以這條
opcode 對 ECL 的可見效果就是「把 0..3 其中一個結果碼寫進運算元 4 指的
變數」，後面的 `COMPARE`／`IF` 再據此分支——**remake 不需要解讀那些碼的
意義，只要寫對就好**，分支由 ECL 自己做。

## 還沒讀完的部分

## remake 這一側

`internal/gamepack.ResolveEncounterChoice` 是上面那張表；讀不到證據的組合
（類型 5 以上）回錯誤而不是猜——猜錯的症狀是「遭遇被靜靜跳過」，
在測試報表上看不出來。

接上去之後實測：探索器在索寇要塞登陸的遭遇選 PARLAY、對亡魂說出 `LUX`、
再對費蘭選「說謊」，`DS:4A01h` 變成 255——那正是 spec 102 追的船票旗標。

`cmd/pool-game` 把 `29h` 接成一個四選項選單，選完之後把結果碼寫進運算元 4
指的 ECL 變數再讓 ECL 跑下去。`TestNormalKeysReachTheFirstCombat` 只用按鍵
從標題走到索寇要塞，觸發選單、選 COMBAT，然後 ECL 依結果碼分支，把原版的
骷髏 ×6 與殭屍 ×6 擺上場。
