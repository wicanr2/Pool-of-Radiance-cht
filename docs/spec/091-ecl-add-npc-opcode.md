# Spec 091：`36h ADD NPC`

狀態：READY（資料來源、上限、陣營與戰鬥數值都讀完並實作）；
DRAFT（記錄 `+84h` 與 `+ABh` 的語意）。日期：2026-09-03。

## 派發（overlay-03 `2EDBh`，2 個運算元）

```
2EE9h  a = 運算元 1 的值                       ; NPC 編號
2EF4h  overlay-17 entry 9（`1216h`），參數 a    ; 依編號載入
2EFDh  b = 運算元 2 的值
2F08h  b = b / 2（有號）
2F19h  b |= 80h
2F21h  [5CF0h] 指到的記錄 `+84h` = b
2F2Ah  a = 18h 時 `+10Eh` = 1，否則 0          ; 陣營（spec 057）
2F46h  overlay-25 entry 7（`0BBEh`）
2F53h  overlay-25 entry 2（`0762h`）           ; spec 079／080 的重算鏈
```

`18h` 是**唯一**會站到對面的編號，而且它真的出現在資料裡：
`ECL4/block 10 @158Dh` 就是那一條。全部七個呼叫點的編號是
19h、6Bh（ECL3/b0）、變數（ECL3/b11）、1Bh、**18h**、68h ×2。

## 載入（overlay-17 entry 9，`1216h`）

```
121Ch  隊伍人數（`[4937h] + 67Ch`）> 7 就直接返回      ; 上限八人
122Bh  配置 11Dh ＝ 285 bytes
1244h  近呼叫 0E90h(record, 編號)
1250h  record[+ABh] = 骰(1, 100h)
1261h  掃 record[+96h + j]（j = 0..6）收集非零的職業槽，一個都沒有就當 {2}
```

`0E90h` 組出來的檔名是 `MON` ＋ `[52D4h]` ＋ `CHA` ＋ `.dax`，也就是
**`MON<n>CHA.DAX`**，編號就是 block ID——remake 早就在讀同一批檔案
（`ReadDOSMonsterRecord`）。

## remake 怎麼接

- 存檔的隊伍上限提高到 **8**，但**玩家自己建的角色仍然只佔得了 6 格**；
  多出來的兩格留給 NPC。NPC 不進角色庫——它是劇情加進來的，不該出現在
  「加入隊伍」的清單裡。
- NPC 帶著自己的 285-byte 記錄，**戰鬥數值直接讀它**（做法與已 staged 的
  怪物同一套）。硬套建角那組欄位會得到一個「一級戰士」，與原版差很多。
- 陣營非零的 NPC**擺到對面**。因此戰場的隊伍索引要另外記
  （`provisionalRoster` 回傳 `partySlot`），不能再靠「友方槽依序對應隊伍」
  那個假設——那個假設在有叛徒的時候會把數值套到錯的人身上。

## 還沒讀

- `+84h`：`(運算元 2 / 2) | 80h` 這個形狀說明它帶旗標，但讀取端還沒找到，
  所以 remake 沒有寫它。
- `+ABh` 那個隨機位元組給誰用。
- overlay-25 entry 7（`0BBEh`）在重算之前先做了什麼。
