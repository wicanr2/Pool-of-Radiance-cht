# Spec 120：8×8 符號的五帶

狀態：READY（五帶的界線與來源、兩個全域集的檔案與區塊、對拍量測）；
DRAFT（編號 `1`／`2`／`3` 為什麼不畫）。**第 4 帶誰在用 2026-09-10 讀出來了：
平面圖**——overlay-30 offset 0 用 `0104h + 北1 東2 南4 西8` 取那一帶的圖塊，
十六種牆組合各一張（`0104h`..`0113h`）。詳見 spec 119。
日期：2026-09-05。

## 問題長什麼樣

第一人稱視野裡 `(0,4)` 朝西正前方是**城門**，原版畫得出門與門裡的人形，
remake 一整道都沒有。對拍只有 60.4%。

先前的診斷是「`BuildWallLayout` 對 `wallType=1` 一片圖章都產不出來，
WALLDEF record 0 的 slice 0 大概是空的」。**那是錯的**——把那一段倒出來看，
layout 6 的視窗（索引 54..109）是這樣：

```
01 01 01 01 01 01 01   28 0D 0D 0D 0D 0D 27
28 0E 0E 0E 0E 0E 27   28 0E 0E 0E 0E 0E 27
28 0E 0E 0E 0E 0E 27   28 0E 0E 7C 0E 0E 27
28 0E 22 03 21 0E 27   28 22 03 03 03 21 27
```

形狀就是一道有拱的門面。掉光的原因是**取圖的方式**。

## 原版怎麼取（exact）

`Put8x8Symbol` 是 overlay-35 進入點 3（code offset `015Dh`；它前面就是
Borland 除錯符號 `Put8x8Symbol.`）。它先把編號分帶：

| 帶 | 編號範圍 | 寬度 |
|---:|---|---:|
| 0 | `0001h..002Dh` | 45 |
| 1 | `002Eh..0073h` | 70 |
| 2 | `0074h..00B9h` | 70 |
| 3 | `00BAh..00FFh` | 70 |
| 4 | `0100h..011Eh` | 31 |

編號 0 直接返回不畫。分完帶之後：

- `DS:5D98h + 帶×4` 是五個遠指標，指向該帶目前載著的 8×8 圖片；
  指標是空的就不畫。
- `DS:2736h + 帶×2` 是五個基準編號，實測是 `{1, 2Eh, 74h, BAh, 100h}`
  ——與上表一致。`item = 編號 − 基準`。

**所以決定去哪一組取圖的是編號自己落在哪一帶，不是那一筆 WALLDEF 記錄。**
共用 engine 的 `BuildWallLayout` 是用記錄決定（`item = id − SymbolSetBase[記錄的集]`），
所以低號帶那些編號一律算成負索引被丟掉。engine 自己的註解早就寫了這件事，
並且留了 `RawWallStamps` 讓呼叫端自己解——這一版就是照那條路走。

## 第 0 帶與第 4 帶是開機時載的

`37h LOAD PIECES` 只換第 1..3 帶。第 0 帶與第 4 帶由 overlay-11 `04AAh`／
`04B5h` 連著兩次 `Load8x8Set`（overlay-35 進入點 2，`003Bh`）載一次：

```
push 0CAh ; push 4 ; call Load8x8Set   ← 區塊 202 → 帶 4
push 0CBh ; push 0 ; call Load8x8Set   ← 區塊 203 → 帶 0
```

`Load8x8Set` 的檔名是 `8x8d` ＋ `Str(DS:52D4h)`，而 overlay-11 跑的時候
`DS:52D4h` 是 1，所以是 **`8X8D1.DAX`**。那個檔正好有區塊 201／202／203，
其他 `8X8D*.DAX` 都沒有。**區塊 203 剛好 45 個 item**，與第 0 帶的
`01h..2Dh` 一樣寬——這個自洽同時是「帶 0 就是它」的驗算。

## `1`／`2`／`3` 不畫

那三個編號在 `Put8x8Symbol` 裡沒有特別待遇，區塊 203 的第 0..2 個 item 也
不是空白。但**畫它們會讓兩張基準圖都變差**：

| 做法 | `(14,1)` | `(0,4)` |
|---|---:|---:|
| 共用 engine 的 `BuildWallLayout` | 96.1% | 60.4% |
| 按帶取圖，`1..3` 也畫 | 72.9% | 92.9% |
| **按帶取圖，`1..3` 不畫** | **98.6%** | **97.0%** |

形狀上也說得通：`(0,4)` 那道門面的最上一列整列是 `01`（原版那裡是天空），
拱底那一列中間是 `03`（原版那裡是地面）——像是天／頂／地的標記，
背景已經畫過了。切點只能界定在 **4..13** 之間（這兩張圖裡 4..13 沒出現），
**為什麼不畫還沒讀**，所以列在 DRAFT。

負對照（都試過、都不對）：低號帶改用 `8X8D3` 的區塊 1／3／5，或用那一筆
record 自己的區塊——每一種都讓 `(0,4)` 好一點卻讓 `(14,1)` 掉到七十幾。

## 契約

1. `gamepack.ReadDOSGlobalSymbolBands` 從 `8X8D1.DAX` 讀區塊 203（帶 0）與
   202（帶 4）。找不到就失敗，不補空圖。
2. 前端用 `graphics.RawWallStamps` 取得未解析的編號，再自己按帶解：
   帶 0 用全域集，帶 1..3 用 `LOAD PIECES` 那三組（`SymbolSetIDs` 對應），
   `item = 編號 − 帶的基準`。
3. 編號小於 `structuralSymbolLimit`（4）不畫。
4. 落在 11×11 視野格外的整片丟掉——8 像素對齊，不會只露一半。

## 驗收

`TestFirstPersonInsetMatchesTheDOSShot` 兩個位置的地板改成 98.0 與 96.0
（實測 98.6% 與 97.0%）。城門那一格從 60.4% 變 97.0%，那 36.6 個百分點
就是整道門。

## 仍未閉合

- `1`／`2`／`3` 不畫的機制（見上）。
- 第 4 帶（`0100h..011Eh`，`8X8D1.DAX` 區塊 202）誰在用還沒讀；
  第一人稱視野這兩張圖裡沒出現過那一帶的編號。
- 剩下的百分之二三：`(0,4)` 拱底兩側 remake 多了兩塊粉紅，原版是黑的。
