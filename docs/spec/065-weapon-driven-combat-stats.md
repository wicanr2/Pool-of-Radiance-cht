# Spec 065：物品型別表與裝備武器決定的戰鬥數值

狀態：READY（`poolrad/items` 的形狀與索引、三張能力值修正表、
overlay-25 entry 1 的十一個步驟、以及穿戴中物品的槽位規則已實作並有真檔
測試）；DRAFT（記錄 `+0AAh` 與 `+2Eh` 的 producer、entry 其餘欄位）。
日期：2026-09-03。

## `+0Ch` 是射程加一

挑目標的介面（overlay-13 `358Dh`）拿裝備中的武器算射程：

```
357C  les  di, es:[di+0CCh]         ; 裝備中的那一格（spec 080 的 +CCh 起）
3581  mov  al, es:[di+2Eh]          ; 物品的型別索引
358D  mov  al, [di+54ECh]           ; 型別表的 +0Ch
3593  dec  ax
359F  cmpb $0 / $0FFh → 墊成 1      ; 0 與 FFh 都當成 1
```

所以表裡存的是**射程加一**，近戰武器存 0：

| `+0Ch` | 0 或 1 | 4 | 6 | 7 |
|---|---:|---:|---:|---:|
| 打得到 | 1 格（相鄰）| 3 格 | 5 格 | 6 格 |

`internal/gamepack.ItemTypeEntry.AttackRange()` 就是這條規則，
測試逐筆對原版的位元組。

**距離怎麼算還沒讀**：原版的挑目標介面會顯示 `Range = `，那一段在
overlay-13 `352Ch`。remake 用的是戰場座標的切比雪夫距離，是自己的選擇。

## 為什麼需要這一段

spec 063 已把「武器怎麼決定 THAC0 與傷害」讀出來，但停在兩個洞上：物品型別表
的內容沒有，三個能力值修正函式沒有讀。少了它們，remake 的隊伍傷害只能掛
placeholder（`1d8`），勝負數字不作數。

## 一個假零：表不在 START.EXE 裡

overlay-25 以 `type × 16` 索引 `DS:54E0h`。把該處 1,024 bytes 匯出來
（`docs/audit/ida-ds-item-type-table-uninitialized.json`）得到的是**整片 FF、
`file_offset` 為 -1**——那段 DS 是未初始化的，表是執行時載進去的。
正對照：同一支匯出器在 `DS:3C16h`（職業 THAC0 表）拿得到 88 bytes 且
`file_offset` 是 46022，所以工具沒壞，是這一段真的沒有內容。

表的來源是 ZIP 裡的 `poolrad/items`：2,050 bytes ＝ 2-byte 檔頭加
**128 筆 × 16 bytes**，SHA-256
`ece7dc8d8331c9b915b79c5963454bd5a4c3ab3b015844829b67016334eb0cf2`。

## 索引的正對照

`ITEM3.DAX/33h` 的 `Two-Handed Sword +1 +3 vs. Undead`（spec 033）記錄
`+2Eh = 26h`、`+32h = 01`。表的第 `26h` 筆是 `+2/+3 = 3d6`、`+9/+0Ah = 1d10`，
正是 AD&D 雙手劍對大型／中小型的傷害，而 `+32h` 的 1 與名稱的 `+1` 相符。

這一條同時釘住三件事：`poolrad/items` 就是 `DS:54E0h` 那張表、索引就是物品記錄
的 `+2Eh`、`+9/+0Ah` 是對中小型目標的那一組。任一件讀錯，三個數字不會同時對上。

| entry offset | 語意 | 證據 |
|---|---|---|
| `+0` | 類別 | overlay-25 `01F8h` 以它是否為 2 分支 |
| `+2`／`+3` | 對大型目標的傷害骰 | 與 `+9/+0Ah` 成對，雙手劍 3d6／1d10 |
| `+9`／`+0Ah` | 傷害骰數／骰面（寫進 `+115h`／`+117h`）| overlay-25 `01C4h`／`01E6h` |
| `+0Bh` | 傷害加值（寫進 `+119h`）| overlay-25 `007Bh` |
| `+0Eh` | 旗標 | 四個位元由 overlay-25 的分支決定 |

旗標：bit 0 需要發射器（再加 `+0F8h` 那件的 `+32h`）、bit 1 投射（THAC0 加敏捷
修正）、bit 2 近戰（THAC0 與傷害加力量修正）、bit 7 使用彈藥（再加 `+0FCh`
那件的 `+32h`）。其餘位元未用到，不猜。

## 三張能力值修正表（exact）

`docs/audit/ida-overlay25-ability-modifiers.json` 保存 overlay-25
`1173h..1400h` 的 247 條指令。

**`1203h` 力量索引**：力量 0..17 直接當索引；18 依特殊力量百分比分成
`12h`（0）、`13h`（1–50）、`14h`（51–75）、`15h`（76–90）、`16h`（91–99）、
`17h`（100，即 18/00）；19..25 是力量加 5。spec 035 的負重容量用同一個索引。

**`12AEh` 力量命中修正**與**`1366h` 力量傷害修正**都先取上面的索引，並且**都被
記錄 `+0AAh` 是否為零擋著**。分段逐一照抄，包含幾個與規則書不同的邊界：兩張表
在索引 0 與 31 以上都回 0。

**`1173h` 敏捷投射修正**直接讀記錄 `+13h`，**沒有 `+0AAh` 那道閘門**；
敏捷 0..2 回 -4（規則書是 -6／-4 分開）。

## 十一個步驟（照 overlay-25 entry 1）

依 spec 063 的列表實作，順序有兩處容易寫反：

1. 傷害加值是**先指派**表的 `+0Bh`，再加力量傷害修正，再加 `modifier`。
2. `record[+2Eh] == 2` 且武器型別是 `24h`、`25h` 或 `29h..2Ch` 時 `modifier` 加 1，
   **而這一步在 `modifier` 已經加進傷害之後**——所以那個 +1 只影響命中，不影響傷害。

## 玩家路徑

物品記錄的 `+34h` 非零代表已裝備。撿到的物品 `+34h` 是 0（墓園那五筆都是），
所以要玩家自己裝上。遊戲裡按 `I` 開裝備頁，`ENTER` 裝上或卸下。裝上之後
戰術戰鬥的 THAC0、傷害骰、AC 與腳程都改由裝備決定，畫面上也直接把算出來的
數字印出來——看不到數字就分不出「裝備沒生效」與「這把武器本來就這麼弱」。

### 穿戴中的物品放進哪個槽

重算（overlay-25 `0C76h`）逐件依**型別表的類別**把物品指標寫進角色記錄：

| 類別 | 槽 |
|---|---|
| 0..8 | `+CCh + 類別 × 4` |
| 9 | `+F0h`，已占用則 `+F4h`（兩個戒指槽） |
| 型別索引 `49h` | `+F8h` |
| 型別索引 `1Ch` | `+FCh` |

**武器是類別 0 那一件**：判斷「這個角色有沒有武器」的 `0E81h` 讀的正是
`+CCh`／`+CEh`，空指標就走徒手那一支（`12AEh`）。槽是覆寫不是累加，
所以同類別有多件穿戴中時最後一件贏。

這一條要照著讀，不能用「物品鏈上第一件標成裝備的東西」代替：預設人物身上
第一件裝備多半是戒指（`chrdatd2` 是火焰抗性戒指），而戒指在型別表裡的傷害骰
是 `0d0`——拿它當武器，整隊會打不出傷害，但戰鬥照跑，報表上只看得到「打不贏」。
`+F8h`／`+FCh` 就是型別旗標 bit 0／bit 7 要去取加值的那兩格（發射器與彈藥）。

驗收：`docs/screenshots/pool-remake-chinese-equipment.png`，以及
`cmd/pool-game` 的四條測試（撿到時未裝備、ENTER 切換、一次只裝一件、
裝上之後戰鬥數值變成 typed THAC0 16／1d10+7）。

## 不做

- 不替記錄 `+0AAh` 與 `+2Eh` 取名。remake 目前一律當 `+0AAh` 是開著的，
  因為建角出來的角色都是正常角色；producer 讀出來之前不得宣稱那是「職業旗標」
  之類的東西。
- 不補徒手傷害。原版那支在沒有武器時直接返回，`+115h`／`+117h`／`+119h`
  維持原值。
- 不替型別表 `+0` 的類別 1..8 逐一命名。只有 0（武器）、1（盾）、2（盔甲）與
  9（戒指）由 overlay-25 的分支證實，其餘只知道它決定槽位，不知道語意。

裝備之後的 AC 與腳程重算已分別由 spec 080 與 spec 079 閉合並接上。
- 裝備頁的版面是 remake 的呈現；原版的 ITEMS 選單還沒反組譯，不宣稱一致。
