# Spec 089：`3Ch PROTECTION`

狀態：READY（迴圈、停止條件與印出來的值都讀完並實作）；
DRAFT（那串數字在畫面上代表什麼）。日期：2026-09-03。

## 它做的事（overlay-03 `31D8h`，1 個運算元）

```
31FAh  取運算元 1
3202h  base = 運算元 1 的**位址**（`6E0Ch`／`6E4Ch` 是它的低／高位）
3212h  索引 = 0
323Ch  addr = base + 索引
3247h  v = 讀 ECL 變數 addr（overlay-07 entry 17）
324Fh  v++
3253h  v ≤ 1 → 跳出
3259h  把 v 接成一格印出去（overlay-25 entry 10 只是「位元組轉十進位字串」）
32A7h  欄 `5D82h`++；索引++
32BAh  跳出之後列 `5D83h`++
```

所以它是**把運算元 1 位址起的連續 ECL 變數印成一列數字**，遇到 0 就停，
印的是讀到的值**加一**。

名稱查表這一步不存在：`010Ah:0052h`（overlay-25 entry 10）只是
`05BBh:0E3Ah` 的包裝，把一個位元組轉成十進位字串。所以畫面上出現的是
數字，不是法術名。

## 這是什麼

不確定。三個線索：

- 呼叫點裡有一組是 `ECL4/block 21` 的 `2D7h` 先 `3Dh CLEAR BOX`，
  接著 `2D8h`／`2DDh`／`2E2h` 連三條 `3Ch`——像是「清框之後印三列」。
- 緊接在 handler 後面（`32C2h` 起）的字串是 `codeop = `、` last = `、
  `string = `，那是另一支除錯傾印常式。
- opcode 的公開名稱是 PROTECTION，但它不碰任何防護欄位。

**沒有證據說它是防護清單**，所以正文只寫它做了什麼。

## remake 怎麼接

`3Ch` 走 passthrough，前端讀運算元 1 的位址（要用 `WordAddress`），
把連續的非零值接成一列加進文字框，最後換行。remake 這一側多加一個
64 格的上限——原版靠「遇到 0 就停」收尾，資料壞掉時那條件不一定成立。
