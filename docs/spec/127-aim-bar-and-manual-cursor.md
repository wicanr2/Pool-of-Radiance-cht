# Spec 127：瞄準列與 Manual 格子游標（overlay-13 `352Ch`）

狀態：CONFORMED。整支讀完並接上了：選項列、五個字母、游標的八個方向鍵、
離開的那兩個**集合**、確定與取消、`Center`，以及 `07D4h` 的模式值。
日期：2026-09-06。

## 選項列

字串在 overlay-13，四段接起來：

| 位址 | 長度 | 內容 |
|---|---:|---|
| `2A44h` | 8 | `Range = ` |
| `2A50h` | 7 | `Target ` |
| `2A58h` | 17 | `Next Prev Manual ` |
| `2A6Ah` | 11 | `Center Exit` |
| `2A76h` | 4 | `Aim:` |

`2B96h` 把 `2A58h` 與 `2A6Ah` 接成一條，提示語用 `2A76h`，交給
`011D:002Fh`——**和鎖住的門那個選單是同一支選單常式**（spec 122）。
所以瞄準時底下那一列是

```
Aim: Next Prev Manual Center Exit
```

## 五個字母跳去哪

`352Ch` 的主迴圈拿回字母之後逐個比：

| 位址 | 字母 | 去哪 |
|---|---|---|
| `365Bh` | `N` | 下一個目標（就地改 `[bp-0DCh]` 那一組游標欄位）|
| `366Ch` | `P` | 上一個目標 |
| `367Dh` | `M` | **Manual**：`call 2DD3h`，回來之後 `010A:0093h` 重畫、`call 32C3h` 更新，並把 `[bp-0DDh]` 清成 0 |
| `36CDh` | `T` | `call 2C17h`——把目前這一格收成目標（`2C17h` 先看 `[bp+0Eh] == 1` 時跑 `2977h` 的可打判定，不成立就把 `[bp+0Ah]` 指到的旗標清成 0）|
| `3714h` | `C` | **Center**：把視窗捲到目前目標身上（下一節）|

`E`（Exit）不在比較鏈裡，但它**不是靠「都不 match」離開的**——真正的出口在
迴圈頭 `35F2h`：那裡拿上一次按的鍵去測另一個集合 `cs:350Ch`，
解出來是 **{掃描碼 0, `E`}**。按 `E` 會先走完整條比較鏈掉進共用的收尾
`3744h`，繞回 `35E6h` 之後才在迴圈頭被那個集合攔下來。

迴圈頭還有一道更早的閘：`35E6h` 先看 `[bp+0Ah]` 指到的旗標，非 0 就直接收尾
——那是 `T`（`2C17h`）確定目標時設起來的。

`3606h` 還有一支自動跳過：`1087h` 判定目前這個目標不合格時，
直接拿 `[bp-0DCh]`（`N` 設 +1、`P` 設 −1）呼叫 `3364h` 換下一個，不等玩家按鍵。
`M`／`T`／`C` 都只把**共用收尾用的** `[bp-0DDh]` 清成 0（＝不換目標），
`[bp-0DCh]` 留著上一次 `N`／`P` 的方向——那就是自動跳過要往哪邊走。

## Manual 的游標（`2DD3h`）

```
2DDA  05BB:16B5(記錄, 7, 0)              ; 字串／畫面前置
2DEB  X = 013D:006Bh(記錄)               ; 目前目標那一格
2DF9  Y = 013D:0070h(記錄)
2E07  [bp-2Ah] = 20h                     ; 目前按鍵，初值是空白
2E0B  [bp-2Fh] = 8                       ; 目前方向，8 ＝ 原地（九方向表）
2E16  DS:6674h 指到的地圖 +4／+5 都設成 1
2E28  迴圈：[bp-2Ah] in cs:2D80h            ; 集合成員測試，cs:2D80h 是 32 位元組的位元圖
2E43  013D:0061h(X, Y, 3, 方向)          ; overlay-32 entry 13，捲視窗＋重畫
2E4F  X += DS:274Ah[方向]                ; 九方向位移表，與雲、開門共用
      Y += DS:2753h[方向]
```

**游標就是靠那張九方向位移表走的**——與臭雲的四格（spec 121）、
開門時算對面那一格（spec 122）是同一張表。方向的初值 8 是「原地」，
所以進來的時候游標停在目前的目標上。

## 游標迴圈的全貌

```
2E28  迴圈頭：[bp-2Ah] in cs:2D80h      ; 集合 ＝ {0, Return, 'E', 'T'}
2E38    → 在集合裡就離開（32BDh，retf 16h）
2E43  013D:0061h(X, Y, 3, 方向)          ; 對走到的那一格捲視窗＋重畫
2E4F  X += DS:274Ah[方向]；Y += DS:2753h[方向]
…
3151  011D:002Fh(DS:6D24h 的選單, …)     ; 讀一個鍵，存進 [bp-2Ah]
315C  Return（0Dh）或 T（54h）→ 3167h    ; **確定這一格**：地圖 +4 清 0
3217  以下逐個比方向鍵，設 [bp-2Fh]
326A  0 或 E（45h）→ 3272h               ; **取消**：013D:0043h 還原那一格、
                                          [bp+0Ah] 指到的旗標清 0
32B0／32B6  方向 = 8（原地）
32BA  jmp 2E28                           ; 回迴圈頭
```

### 方向鍵就是戰術移動那八個

| 鍵 | 碼 | 方向 |
|---|---:|---:|
| `H` | 48h | 0 |
| `I` | 49h | 1 |
| `M` | 4Dh | 2 |
| `Q` | 51h | 3 |
| `P` | 50h | 4 |
| `O` | 4Fh | 5 |
| `K` | 4Bh | 6 |
| `G` | 47h | 7 |

**與 spec 053 的 Move 命令逐鍵相同**（remake 的 `tacticalStepKeys` 就是這一組），
所以瞄準的游標與走路用同一套手感，不是另一組鍵。

`Return` 與 `T` 都是「就選這一格」，`E` 與掃描碼 0 都是取消——
取消時先 `013D:0043h` 把那一格還原，再把回傳旗標清成 0。
這也解釋了外層 `36CDh` 那個看起來多出來的 `T`：**它與 Return 是同一件事**。

## 離開的條件是一個**集合**，不是字串

先前把 `2E31h` 呼叫的 `05BB:08D4h` 讀成 Turbo Pascal 的 `Pos`、
把 `cs:2D80h` 讀成長度 1 的字串 `" "`，結果兩種極性都會矛盾
（游標的按鍵初值就是空白）。**那個矛盾本身就是讀錯的訊號。**

`05BB:08D4h` 在 `START.EXE` 裡（檔頭 `03B0h`，所以檔案偏移
`03B0h + 5BBh × 16 + 8D4h = 6834h`），是**集合成員測試**：

```
6834  bx = sp
6836  les di, ss:[bx+4]      ; 集合的遠指標（32 bytes 的位元圖）
683A  al = ss:[bx+8]         ; 要測的元素
683E  bx = al >> 3           ; 元素 ÷ 8 ＝ byte 索引
6846  cl = al & 7            ; 位元編號
684B  al = 1 << cl
684F  test es:[bx+di], al    ; **結果留在旗標裡，不在 AL**
6852  retf 6
```

同一段位址對照組：`05BB:0C94h`（檔案 `6BF4h`）是教科書式的
`Random(word)`——`call 更新種子; xor ax,ax; bx = 參數; bx==0 → 0;
xchg dx,ax; div bx; xchg dx,ax; retf 2`，與 spec 098 早就標的名字相符。
**段基準確定，所以 `08D4h` 的解讀站得住。**

於是 `cs:2D80h` 那 32 個位元組是位元圖：

```
01 20 00 00 00 00 00 00 20 00 10 00 ...（其餘全 0）
```

解出來是 **{0, 13, 69, 84}** ＝ **{掃描碼 0, Return, `E`, `T`}**
——正好就是四個離開鍵。`2E36h` 的 `je` 因此是「不在集合裡 → 繼續迴圈」，
初值空白不在集合裡，Manual 跑得起來；按下四個裡的任何一個才離開。矛盾消失。

## `Center`（`3714h`）

```
3714  cmp al, 'C' → 不是就跳共用收尾 3744h
3718  X = 013D:006Bh(目標記錄)     ; 目前目標那一格
3726  Y = 013D:0070h(目標記錄)
3734  013D:0061h(X, Y, 0, 8)       ; 模式 0、方向 8（原地）
373F  [bp-0DDh] = 0                ; 不換目標
```

方向 8 是原地，所以它就是「對目前目標那一格做模式 0 的事」。
下一節把模式讀出來之後，`Center` 的語意就是字面上那個：
**把戰術視窗捲到讓目前這個目標落在正中央**，選到誰一個位元組都不動。

## `013D:0061h`：往一個方向走一格，在新那一格做事

overlay-32 entry 13（`0996h`）。**參數是宣告順序 `f(X, Y, 模式, 方向)`**
（Turbo Pascal 由左往右推，第一個 push 就是第一個參數；在被呼叫端看到的
`[bp+6]`＝方向、`[bp+8]`＝模式、`[bp+0Ah]`＝Y、`[bp+0Ch]`＝X 是**反過來**的
堆疊順序，別把兩者混用）：

```
099C  dx = DS:274Ah[方向]
09AA  [bp-6] = X + dx            ; 目標格的 X
09B3  dy = DS:2753h[方向]
09C1  [bp-7] = Y + dy            ; 目標格的 Y
09CA  al = 07D4h([bp-6], [bp-7], 模式)     ; 捲視窗，回報有沒有捲
09DA  al == 0 → 直接跳 0A7Fh
09E1  否則對 1..DS:5E88h 的每一格：記錄 +10Dh 非 0、
      [i*4 + 5E88h] > 0、71Ah(記錄, 0) 非 0 → 147h:003Eh 重畫那一個單位
0A7F  最後 02D7h(X, Y)                     ; 對**原來**那一格做收尾
```

**又是那張九方向位移表**（`DS:274Ah`／`DS:2753h`）——雲的四格、開門算對面
那一格、游標移動、這一支，四個地方共用同一張。

## 模式 ＝ 捲動的餘裕（`07D4h`）

`07D4h(X, Y, 餘裕)` 是戰術視窗的捲動器。原版一次只畫得下 **6×6 格**：
`0912h` 起的重畫迴圈兩層都數到 6，每畫一格螢幕座標加 3、地圖座標加 1，
資料讀 `[DS:6674h] + 7 + y*32h + x`，地形碼經 `DS:275Bh`（每項 4 bytes，
取第 0 個位元組）換成圖塊編號交給 `147h:002Fh`。視窗左上角就是戰術地圖
record 的 `+2`／`+3`，所以**中心是原點加 3**。

```
07DE  cx = [DS:6674h]+2 + 3 ；cy = [DS:6674h]+3 + 3
0802  餘裕 0FFh 當 0 用
0813  框 ＝ [cx−餘裕, cx+餘裕] × [cy−餘裕, cy+餘裕]
084C  餘裕 ≠ 0FFh 且 (X,Y) 在框內 → 回 0（不捲、不重畫，原點一個位元組沒動）
0875  否則 while (X < cx && cx > 3)    cx--
0892       while (X > cx && cx < 2Eh)  cx++
08AD  Y 同理，夾在 3..15h                ; X 與 Y 各自獨立，不是二選一
08E5  cx−3／cy−3 寫回 +2／+3，重畫整個視窗，回 1
```

**所以模式就是「離中心多遠才捲」。** 三個呼叫端各自的值因此有了意思：

| 呼叫端 | 餘裕 | 意思 |
|---|---:|---|
| Manual 游標（`2E43h`）| 3 | 游標走到視窗邊緣才捲 |
| `Center`（`3734h`）| 0 | 只要不在正中央就捲到正中央 |
| 火球術的雲心（overlay-22 `26EEh`）| 0 | 把畫面對準雲心 |

`0FFh` 是第四種：餘裕當 0，但**跳過「已經在框內」的檢查**，所以一定重畫。

中心的夾制 `3..2Eh` × `3..15h` 換算成原點就是 `0..43` × `0..18`——
配 6 格寬的視窗，剛好蓋得到 `TacticalMaxX = 31h`／`TacticalMaxY = 18h` 的盤面。

取消時用的 `013D:0043h` 是 overlay-32 entry 7（`02D7h`），
它拿 `DS:6674h` 指到的地圖的 `+2` 去算偏移——是「還原那一格」的那一半。

## remake 的現況

**Manual 接上了**（`cmd/pool-game/manual_aim.go`）：瞄準時按 `M` 進格子游標，
游標停在目前挑到的那一格，`H I M Q P O K G` 走八個方向（與戰術移動同一組鍵、
同一張位移表），`Return`／`T` 選定、`E`／`Esc` 取消。走到盤面外不動；
停在空格子按確定什麼都不做、游標留著——對應原版把回傳旗標清 0。

**`Center` 也接上了**：`C` 呼叫 `centreOnTarget`，用餘裕 0 把視窗捲到目前
目標身上，不換目標。捲動的規則本身照 `07D4h` 寫在共用的
`internal/combat.RecentreViewport`（餘裕、逐格逼近、`3..2Eh`／`3..15h` 的
夾制、`0FFh` 的特例都逐項對過），Manual 的游標每走一步用餘裕 3 呼叫它。

**remake 目前整張盤面都畫得出來，沒有 6×6 的捲動視窗**，所以視窗原點只出現在
狀態列（瞄準列尾端的〔視窗 x,y〕）。規則接在原地是為了畫面真的縮成 6×6 時
不必重讀；原點的**初值**原版從哪裡來還沒讀，remake 用零值。
