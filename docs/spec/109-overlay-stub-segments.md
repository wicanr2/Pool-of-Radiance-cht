# Spec 109：overlay 的 stub segment 對照表

狀態：READY（三十八顆 overlay 的 stub segment、推導方式與四個獨立正對照）。
日期：2026-09-03。

## 為什麼要有這張表

反組譯出來的每一個跨 overlay 呼叫長這樣：

```
9a 52 00 00 01     call 0100h:0052h
```

`0100h` 不是程式碼位址，是那顆 overlay 的 **stub segment**。少了對照表，
只能對著 `0100h`、`010Ah`、`0138h`、`018Eh` 這些數字猜是哪一顆，而
**IDA 以平坦 16-bit 載入單顆 overlay 時會把它解成同一顆裡的 `sub_1052`**
（`0100h × 16 + 52h` 剛好落在 overlay 內），那是載入方式造成的巧合，
不是真的呼叫自己（spec 056 已經記過這個坑）。

## 推導

TPOV 清冊（`docs/audit/dos-ovr-manifest.json`）每個進入點都有
`executable_file_offset` 與 `stub_offset`。兩者相減得到那顆 overlay 的
**控制記錄檔案位移**，再減 MZ header（`3B0h`）除以 16 就是 runtime segment：

```
segment = (executable_file_offset − stub_offset − 3B0h) ÷ 16
```

同一顆 overlay 的每個進入點算出來的值都相同——這本身就是一道自洽檢查。

## 正對照

四條各自獨立解出來的呼叫，用這張表查到的 overlay 與內容相符：

| 呼叫 | 查表得到 | 內容 |
|---|---|---|
| `0100h:0052h` | overlay-24 entry 10 `0E54h` | 掛效果（spec 069 另從「`mov ax,9` 之後配置」證出節點是 9 bytes）|
| `010Ah:00B6h` | overlay-25 entry 30 `23F5h` | `(記錄[+10Eh] == 0) ? 1 : 0`，也就是對立陣營值（spec 096）|
| `0138h:003Eh` | overlay-31 entry 6 `0912h` | 鄰近查詢（spec 056 已閉合並實作成 `NearbyCells`）|
| `013Dh:002Ah` | overlay-32 entry 2 `0000h` | 佔格展開，查 `DS:2860h` 的偏移表（spec 056）|
