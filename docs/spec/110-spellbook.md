# Spec 110：法術書（角色記錄 `+32h + 編號`）

狀態：CONFORMED（位置、編號範圍、值、建角與昇級兩條寫入規則、記憶畫面的
閘門）；DRAFT（法師昇級時挑法術的那一支選單常式、卷軸抄寫的觸發條件）。
日期：2026-09-04。

## 一句話

「這個人會不會這一條法術」是角色記錄裡**一格一個 byte** 的陣列，
位置是 `+32h + 1-based 法術編號`，1 是會。記憶畫面只列書上有的。

## 位置

`+32h` 本身是**最大生命值**（與 `MonsterRecord.MaxHitPoints` 同一格），
編號從 1 起算，所以：

| 編號 | 法術 | 位移 |
|---:|---|---|
| 1 | Bless | `+33h` |
| 15 | Magic Missile | `+41h` |
| 56 | Restoration | `+6Ah` |

原版一律寫成「記錄基底加編號，再取 `+32h`」：

```
mov  al, [bp-13h]        ; 法術編號
xor  ah, ah
les  di, [bp-27h]        ; 角色記錄
add  di, ax
mov  byte ptr es:[di+32h], 1
```

**所以拿 `+33h` 去搜位元組會落空**，要搜 `+32h`；而同一個位移也被最大生命值
用著，兩者在位元組層面分不出來。分得出來的是上下文（前面有沒有 `add di, ax`）
與資料。

## 編號範圍是 1..56

三處迴圈的收尾都是 `cmp byte ptr [bp-x], 38h`（56）：建角的牧師那一支、
昇級的牧師重掃、以及卷軸那一支。56 正好是法術名稱表的筆數（spec 068），
也是參數表裡「牧師 25 ＋ 法師 31」的總和（spec 074）。

## 資料上的證據：二十個預設人物檔，零反例

| 檔 | 角色 | 職業 | 書上幾條 | 來源 | 法術等級 |
|---|---|---|---:|---|---|
| `chrdatd3` | ALFRED | 牧師 6 | 24 | 全部是神術 | 1、2、3 |
| `chrdatd5` | TARRY | 法師 6 | 16 | 全部是巫術 | 1、2、3 |
| `chrdate5` | TARRY | 法師 5 | 14 | 全部是巫術 | 1、2、3 |
| `chrdatb5` | TARRY | 法師 4 | 10 | 全部是巫術 | 1、2 |
| `chrdatd6` | CARRY | 法師 6 | 17 | 全部是巫術 | 1、2、3 |
| `chrdata7` | DIRTEN | 牧師 | 25 | 全部是神術 | 1、2、3、7 |
| `chrdatd1` | HAPLO | 戰士 8 | 0 | — | — |
| `chrdatd4` | TINA | 賊 9 | 0 | — | — |

二十個檔裡非零的格子**全部是 1**；施法者的書只放自己那一類的法術；
法師 4 只有第 1..2 級、法師 5 起才有第 3 級——與可施展的等級一致。
位置或編號基底任何一項讀錯，牧師與法師的法術就會混在同一本書裡，
或整批位移一格而落到別的等級。

`TestPregeneratedSpellbooksAreClassAndLevelConsistent` 逐檔釘住這三件事。

## 誰寫這本書

| 位置 | 時機 | 規則 |
|---|---|---|
| overlay-16 建角迴圈（`1B84Fh`..`1B8CBh` 附近）| 建角 | 職業槽 0（牧師）：掃編號 1..56，參數表 `+0 == 0` 且 `+1 == 1` 的全部寫 1——**第 1 級神術全會**。職業槽 5（法師）：連著四個 `mov byte es:[di+3Dh/44h/45h/47h], 1`——**偵測魔法 11、閱讀魔法 18、護盾術 19、催眠術 21**，寫死的 |
| overlay-23 `0132h` | 重算可記憶數之後 | 先用 `DS:4035h` 把牧師三級的可記憶數寫進 `+0B1h + 等級`，再掃 1..56：參數表 `+0 == 0` 且 `記錄 +0B1h + 等級 > 0` 的全部寫 1——**牧師只要那一級有格子就全會** |
| overlay-16 `2F79h` | 訓練（昇級）| `+9Bh`（法師等級，`+96h + 5`）變大時，呼叫 `00C9:005Ch` 挑一條，回 0 且第二個 var 參數也是 0 就重來，挑到就 `mov byte es:[di+32h], 1`——**法師升一級學一條** |
| overlay-20 `0A51h` | 物品 | 由物品記錄取出編號（`+3Bh` 的低七位）再寫 1——抄卷軸那一路 |

牧師那兩條合起來就解釋了 ALFRED：建角只給第 1 級，昇級每次重掃一遍，
所以牧師 6 的書裡是第 1..3 級的全部 24 條。`TestPregeneratedSpellbooksMatchTheTwoRules`
拿「有格子就全會」算一次，逐條與 ALFRED 的記錄相同。

## 記憶畫面的閘門

overlay-15 `0C33h`（記憶法術的流程就在 overlay-15，見 spec 070）：

```
mov  al, [bp-4]                  ; 法術編號
xor  ah, ah
les  di, [5CF0h]                 ; 目前這個角色
add  di, ax
cmp  byte ptr es:[di+32h], 0
je   +17                         ; 書上沒有 → 不列
lea  di, [bp-29h]                ; 有 → 把名字接到清單上
```

**書上沒有的連列都不列。** 少了這一道，一級法師記得起火球術——而畫面上
那看起來像「法術系統做好了」，不像少了一道閘門。

## remake 怎麼接

- `save.Character.Spellbook` 存會的編號，`omitempty`，舊存檔讀回來是空的。
- 空的時候依現在的職業等級補算一次（牧師走「有格子就全會」、法師走起手
  四條），寫回隊伍與角色庫，只做一次。
- 記憶（`M`）先查書，書上沒有就拒絕並說原因。
- 訓練之後重跑牧師那一條；法師等級上升就多一次「可以學新法術」的額度。

**原版是讓玩家挑的（strong inference）。** 昇級時叫的 `00C9:005Ch`，
`00C9h` 由 spec 109 的 stub segment 表查出來是 **overlay-19**；而青色枷的
PC-98 版帶除錯符號，它的 **overlay-19 就是 `LIBRARY` 單元**，符號裡有
`PICKSPELL`（`docs/audit/overlay-module-names.md`）。兩作的 overlay 編號
在別的地方已經對過（`overlay-18` 兩邊都是結局那一支），所以「昇級時開一個
選單讓玩家挑法術」是強推論——不是隨機給。

## `00C9:005Ch` 是共用的法術清單（2026-09-05 讀出來）

`00C9h` 是 **overlay-19**，`005Ch` 是 stub → **entry 12，code `297Bh`**。
它不是「昇級專用」的常式，是全遊戲共用的**法術清單畫面**：

```
297B  依 [bp+10h]（清單種類 0..6）挑一句字尾放進區域字串
2A43  al = overlay-22 entry 2（0588h）(種類)      ; 把清單建起來，回「有沒有東西」
2A4C  *[bp+6] = al；為 0 就直接回 0               ; 清單是空的就不開畫面
2A5E  *[bp+0Ah] < 0 → 印抬頭：角色名（DS:5CF0h）＋ 字尾
2AD5  al = overlay-22 entry 1（008Ah）(&計數, [bp+0Eh])   ; 真正的挑選
```

七種字尾逐字取自 overlay-19 `2918h..2971h`：

| 種類 | 字尾 | 收哪些（overlay-22 `0588h`）|
|---:|---|---|
| 0 | `in Memory` | 記憶陣列 `+17h + i`（i = 0..14h）值在 `1..7Fh` |
| 1 | `in Spell Book` | 法術書 `+32h + n`（n = 1..37h）非零 |
| 2 | `on Scroll` | 另一支（`0441h`）|
| 3 | `on Scrolls` | 另一支（`050Dh`，參數 0）|
| 4 | `to choose from` | n = 1..38h：**那一級有格子**（`+0B1h + 組×3 + 等級 > 0`）**而且**法術書 `+32h + n` 是 0 |
| 5 | `to be memorized` | 記憶陣列 `+17h + i` 值 > `7Fh`（第 7 位＝還沒記完）|
| 6 | `to be scribed` | 同 `050Dh`，參數 1 |

清單建在 `DS:46CCh` 起的 20 格，`DS:46C8h`／`46CAh` 兩個 word 先清零、
最後 OR 起來當「有沒有東西」。組與等級由參數表取：`DS:3194h + 編號×10h`
是組、`+3195h` 是等級，這與 spec 072 的可記憶數索引（`+0B1h + 組×3 + 等級`）
是同一組欄位。

挑選那一支（overlay-22 entry 1，`008Ah`）依 `[bp+0Ah]` 印動作名，字串在
overlay-22 `0000h..001Ah`：**1 `Cast`、2 `Memorize`、3 `Scribe`、4 `Learn`**。
所以「昇級挑法術」＝清單種類 4 配動作 4。

**種類 4 的規則不看職業組**。組別已經藏在「有沒有格子」裡——牧師的格子在
牧師那一欄，而牧師昇級時神術是自動補進法術書的（overlay-23 `0132h`），
補完之後 `+32h + n` 非零就被第二個條件濾掉了。remake 的 `L` 照這一條接
（`TestLearnFollowsTheOriginalCandidateRule`）；先前多加的「只給法師」是
沒有出處的收窄。

**選單的版面**仍是 remake 的：`008Ah` 的逐鍵行為（游標、翻頁、取消）還沒
逐條讀，不宣稱畫面與原版一致。

## OPEN

- overlay-22 entry 1（`008Ah`）的逐鍵行為：游標、翻頁、取消，以及
  `[bp+0Ah] == 2`／`4` 那兩個分支設的 `[bp-5Eh]`（`0Fh`／`16h`）與
  `[bp-60h]` 是什麼。有沒有智力上限那一道閘也在這一支裡。
- 卷軸抄寫（overlay-20 `0A51h`）的觸發條件與失敗率。原版有「抄不成功」
  這回事，那一段還沒讀。
- 智力上限（AD&D 的「每級最多會幾條」與「學會的機率」）在原版有沒有實作。
  預設人物的條數（法師 4 級 10 條、6 級 16 條）比「四條加每級一條」多，
  差額從哪裡來還沒查。
- `+17h..+1Eh` 那 8 格仍然沒有證據（spec 070 的同一個 OPEN）；法術書是
  `+33h` 起，兩者不重疊。
