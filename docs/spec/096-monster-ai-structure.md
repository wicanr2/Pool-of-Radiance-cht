## 敵方回合長什麼樣子

一隻怪物的一個回合由 overlay-09 的三支撐起來：

| 位置 | 角色 |
|---|---|
| entry 1（`000Fh`） | 分派：玩家打斷 → 戰術模式擲骰 → 士氣 → 用物品 → 施法 |
| entry 5（`0B3Ch`） | 接近迴圈：搆得到就打，搆不到就走一步，最多二十輪 |
| entry 13（`07E8h`） | 一步：算基準方向，照戰術模式的五個相對偏移依序試 |

**選路的判準是「進不進得去」，不是「離目標多近」**：五個相對方向依序問，
第一個地形走得過去又沒人佔著的就走，不比較距離。走不成的時候換一個戰術
模式，靠**跨回合**換模式脫困。

remake 照這個骨架實作，三處仍是近似，畫面上標 PROVISIONAL AI：

- **候選名單怎麼來**：原版由 overlay-25 `010Ah:00C0h` 填進 `DS:6CD7h`
  （還沒讀），remake 借用 spec 059 的鄰接反應搜尋代替。挑法本身已經照原版
  ——目標跨回合黏著，重挑時從名單裡擲骰隨機挑。
- **五個方向多一道距離閘門**：原版只問進不進得去，remake 另外要求那一步
  離目標更近（用 `tacticalStepDistances` 的繞路步數，所以繞牆仍算前進）。
- **五個方向都不合用時多一個繞路備案**：八個方向裡挑離目標最近的。

後兩項是同一件事的兩半，擋的是同一個坑：貼著牆的怪物會挑到 ±2 那兩個往旁邊
走的方向，下一步又走回來，一整回合原地打轉。原版靠**跨回合**換模式脫困，
照抄會讓怪物在死路裡卡上好幾回合——實測過整場打不完（`TestPassiveCombatTerminates`
打到第 3334 回合隊伍還活著）。加上這兩道之後，同一場從 2.49 秒打不完變成
0.54 秒收尾，擁擠盤面那一條從 24.9 秒降到 2.5 秒。

## overlay-09 entry 1：一隻怪物的一個回合

它是一條**「依序試各種行為，誰先動就停」**的鏈：

```
0015h  acted = entry 7（0FC8h）
0027h  overlay-25 entry 21（1830h）
002Ch  記錄 +10Dh 為 0 時：acted = overlay-25 entry 34（266Dh）
0045h  mode = runtime 子結構的 +15h
0054h  mode 落在 1..4 而且 骰(1,4) 不是 1 → 沿用（跳到 00A6h）
0060h  其餘一律重擲：骰(1,8) 擲出 8 → mode = 骰(1,2) + 4，否則 mode = 骰(1,4)
00A6h  寫回 +15h
00B5h  還沒動 → acted = entry 8（10DDh）
010Fh  還沒動 → entry 3（03E3h）成立時交給 overlay-25 entry 34
012Eh  runtime +0 非零 → overlay-22 entry 5（0C14h）再交給 entry 34
0169h  還沒動 → entry 2（0203h）
```

所以**每隻怪物身上帶一個戰術模式**（runtime `+15h`，值 1..6）。
1..4 這四個模式有四分之三的機會留到下一回合；5 與 6 每次都會被重擲掉。
重擲時的 `骰(1,8)` 只用來決定走哪一支——擲出 8（八分之一）才取 `骰(1,2) + 4`
得到 5 或 6，其餘七次都重新取 `骰(1,4)`。所以四個「試探型」模式各佔 7/32，
兩個「橫掃型」的各佔 1/16。

實作在 `gamepack.RollTacticMode`。

entry 2（`0203h`）是施法那一支：runtime `+11h` 為 0 且記錄 `+96h`（牧師等級）
大於 0 時，問 overlay-13 entry 13（`1352h`）有沒有法術可放。

## 接近用的候選搜尋：`0912h` 早就解完了

entry 11（`0255h`）呼叫的 `0138h:003Eh` 是 **overlay-31 entry 6（`0912h`）**，
而那一支在 **spec 056 已經逐條閉合，也已經實作成
`internal/combat.NearbyCells`**：展開雙方佔格、過朝向弧、走 `TraceMovement`
取最小成本、朝向未指定時自 0 起找第一個成立的方向。

它前半用的 `013Dh:002Ah` 是 overlay-32 的 `0000h`：

```
000a  [bp+10h]（體型類別）為 0 → 回 false
0012  di = 體型 × 8 + 索引 × 2
0028  *[bp+0Ah] = DS:[2858h + di]      ; dx
0048  *[bp+06h] = DS:[2859h + di]      ; dy
0052  dx 為負 → 回 false
```

那張表就是 spec 056 的**佔格偏移表**（折疊常數 `2858h`、實際起點 `DS:2860h`、
每列 8 bytes、`0FFh` 代表該列到此為止）：體型 1 一格、2 直向兩格、
3 橫向兩格、4 是 2×2。原始位元組重新量過一次，逐位元組相符。

所以「原版先列出目標周圍可站的格子再挑」這件事，**共用機制本身不缺**，
缺的是敵方回合怎麼用它。

### entry 11（`0255h`）是「這一格旁邊有沒有自己人」

```
0272h  push 型別表[型別 × 16 + 31A3h]        ; 體型類別
0279h  push 0FFh                              ; 朝向不指定
027Bh  push 1                                 ; 成本預算 1 ＝ 貼身
027Fh  push DS:6674h                          ; 結果表

```

`23F5h` 整支只有一件事：`f(記錄) = (記錄[+10Eh] == 0) ? 1 : 0`，也就是

型別表 `31A3h + 型別 × 16` 的 `+0` 是體型類別；同一張表的 `+1`

## entry 7（`0FC8h`）是玩家打斷敵方回合

它不是行為，是**每一隻怪物動之前先看玩家有沒有按鍵**：

```
0fd2  0512h:02FAh()        ; 有按鍵嗎？沒有就回 0
0fde  026Bh:0048h()        ; 讀鍵碼；回 0 就再讀一次（擴充鍵的第二個位元組）
0ff4  鍵 == 32h（'2'）→ 把 DS:6D23h 反相，印 "Magic On" 或 "Magic Off"
103e  鍵 == 20h（空白）→ 走 DS:5CF4h 的整個串列，把 +84h < 80h
                          而且 +10Ch != 1 的記錄的 +10Fh 清成 0
```

兩段字就內嵌在同一顆 overlay：`0FB5h` 是 `Magic On`、`0FBEh` 是 `Magic Off`。
所以：

- **`DS:6D23h` 是「電腦幫我放法術」的開關**，戰鬥中按 `2` 切換。
- **空白鍵把控制權交回玩家**：`+10Fh` 就是 overlay-08 entry 3 拿來分派的那個
  旗標（非零走 AI），清成 0 之後那一隻改由玩家下指令。
  `+84h` 的位元 7 與 `+10Ch == 1` 是兩個例外，不會被交回。

## entry 5（`0B3Ch`）是接近迴圈

`07E8h` 不是由 entry 1 呼叫的，是由 **entry 5** 呼叫，一回合裡呼叫很多次。
開場先清三個全域，然後兩段迴圈：

```
0b42  DS:439Eh = 8   ; 上一步的方向，8 代表還沒走過
0b47  DS:439Fh = 0   ; 「卡住」的次數
0b4c  DS:43A0h = 0
0b9f  逃跑迴圈：runtime +14h 非零、+6 > 0、0 < +3 < 14h → 07E8h(記錄)，重來
0c12  輪數 +1；超過 14h（20 輪）就收工
0c3e  射程 = 手上武器（記錄 +CCh）型別的 DS:[54ECh + 型別 × 16] − 1，
        0 或 0FFh 一律當 1                       ; 近戰就是一格
0c7b  目標 = runtime +0Ah 的遠指標；+10Dh 或 +10Eh 為 0 就作廢
0d4b  n = 010Ah:00C0h(記錄, 射程)                ; 射程內有幾個候選
0d5d  n == 0 → 0096h:00A7h(記錄, 0FFh, 0, 0) 成立就走一步（07E8h），
                否則交給 entry 6
0d97  n != 0 → 骰(1, n) 取一個，DS:[6CD7h + 擲出的號碼] 得索引，
                DS:[6517h + 索引 × 4] 得那一隻的記錄，接著打
```

兩件事因此定了下來：**搆得到就打、搆不到才走**，而且**打誰是從射程內的
候選名單裡擲骰隨機挑的**，不是挑最近或最弱的。射程來自武器型別記錄的
`+0Ch`（spec 065 的那張表）。

`runtime +0Ah`／`+0Ch` 是**目標的記錄遠指標**，不是座標。追擊的目標由
`0096h:00A7h`（overlay-13 entry 27，`37B8h`）寫進去，那一支還沒讀。

## 追誰由 overlay-13 entry 27（`37B8h`）決定

`0096h:00A7h` 就是它，簽章是 `f(記錄, 射程, 放寬, 強制重挑)`——
entry 5 用 `(記錄, 0FFh, 0, 0)`，走一步的那一支用 `(記錄, 0FFh, 1, 0)`。

```
37ca  舊目標 = 記錄 +108h 的 +0Ah                ; 遠指標
37de  強制重挑 != 0 → 丟掉
37ec  舊目標 +10Eh == 自己 +10Eh → 丟掉          ; 同一邊
37fe  舊目標 +10Dh == 0 → 丟掉                   ; 不在場
3809  1087h(記錄, 舊目標) 非零 → 留著
382f  目標非 NULL → 找到了，收工
3872  次數 = 14h                                 ; 最多試二十次
3876  n = 010Ah:00C0h(記錄, 射程)                ; 候選填進 DS:6CD7h
38a6  重複：號碼 = 骰(1, n)
38b5    DS:[6CD7h + 號碼] == 0 → 重擲             ; 這一格已經被劃掉
38c6    索引 = DS:[6CD7h + 號碼]；目標 = DS:[6517h + 索引 × 4]
38e5    放寬 != 0 而且 DS:6674h 的 +6 != 0 → 直接收下
38f6    否則 1087h(記錄, 目標) 非零才收下
390a    收下：記錄 +108h 的 +0Ah／+0Ch = 目標
3925    不收：DS:[6CD7h + 號碼] = 0，掃一遍名單還有沒有剩的，
          有就重擲，沒有就 n = 0
3973  一輪挑不到 → 把「放寬」打開（DS:6674h 的 +6 = 1）再跑一輪
3980  收尾把 DS:6674h 的 +6 清回 0，回傳有沒有挑到
```

三件事因此定了下來：

1. **目標會跨回合黏著**——還在場、還是對面的、還過得了 `1087h`，就不重挑。
2. **重挑是從候選名單裡擲骰隨機挑**，挑到不能打的就把那一格劃掉重擲，
   最多二十次。不是挑最近的，也不是挑最弱的。
3. **兩輪制**：第一輪全被 `1087h` 擋掉時，第二輪把判定放寬再挑一次。

remake 把 1 與 2 接上去了（目標存在 `tacticalState.FoeTargets`，重挑用
`rollDice(1, n)`）；候選名單仍是 `OpposingNearbyAt` 借來的，`1087h` 的內容與
`010Ah:00C0h` 怎麼填 `DS:6CD7h` 都還沒讀，所以第 3 點沒有對應物。

## entry 13（`07E8h`）是「走一步」

```

083c  entry 7（0FC8h）回非零 → 返回              ; 玩家打斷

0868  runtime +3 <= 0 → 交給 entry 6

0896  runtime +14h != 0（正在逃）→ 08C5h
08a5  否則 基準方向 = 0096h:0093h(記錄, 目標記錄)  ; overlay-13 261Bh
08c5  逃跑時：模式 = 骰(1,2)
08dc      基準 = 朝向 − ((朝向 + 2) mod 4) div 2   ; 朝向在 DS:6A0Dh（spec 106）
08fd      記錄 +10Eh == 0 → 基準 += 4
0913      基準 mod= 8
092a  步 = 1；「步 < 6 而且還沒走成」時重複：
093a    成立 = 066Eh(記錄, 步, 基準, &出界)
0951    成立 → 跳出迴圈
0955    正在逃而且出界 → 成立 = 0096h:0043h(記錄)   ; 逃出盤面
097a    步 += 1
09b0  方向 = (基準 + DS:[02ACh + 模式 × 5 + 步]) mod 8
09e7  步 != 6 而且 (方向 + 4) mod 8 != DS:439Eh → 0A88h   ; 一切正常
0a0a  否則：DS:439Fh += 1；模式 = (模式 mod 6) + 1
0a30    439Fh <= 1 → 0A88h                        ; 第一次仍然走
0a37    runtime +0Ah／+0Ch 清成 0                  ; 忘掉目標
0a49    439Fh <= 2 → 0A63h，否則 runtime +6 = 0，收工
0a63    0096h:00A7h(記錄, 0FFh, 1, 0) 不成立 → 交給 entry 6
0a88  步 < 6 → DS:439Eh = 方向，否則收工
0aa3  013Dh:0066h(記錄, 方向, 0, 0)               ; 真的移動
```

三條規則從這裡定下來：

1. **步數 1..5 依序試，第一個進得去的就走**，不比較距離。
2. **走回上一步的反方向算「卡住」**：第一次照走，第二次起忘掉目標，
   第三次起這一隻這一輪不再動。五個方向全不通也走同一條路。
3. **模式在卡住時才換**，換法是 `(模式 mod 6) + 1`。

## 基準方向就是目標的方位

`0096h:0093h` 是 **overlay-13 entry 23（`261Bh`）**，spec 098 已經解過：
取雙方的座標，自方向 0 起遞增，回第一個讓 overlay-31 `0579h` 的攻擊弧
成立的方向。兩支都已經實作成 `combat.RequiredFacing` 與
`combat.FacingArcContains`，這次逐分支重讀一次，八個方向的條件與現有實作
逐條相符。

方向表本身在 `DS:274Ah`（X 位移）與 `DS:2753h`（Y 位移），各九項，
第九項是「不指定方向」的 (0, 0)：0 向上，順時針到 7。

## 戰術模式是一列方向偏移（`DS:02ACh`）

`066Eh` 把「步」換成方向：

```
067f  cx = [bp+0Ch]                    ; 步，1..5
068e  模式 = 記錄 +108h 的 +15h
0694  di = 模式 × 5 + cx
069d  al = DS:[02ACh + di]
06ab  ax = 基準方向 + al
06b3  除以 8 取餘數 → 0..7 的方向
```

也就是 **`方向 = (基準方向 + 表[模式 × 5 + 步]) mod 8`，步從 1 數到 5**。

表在 `DS:02ACh`（原始位元組取自 `START.EXE`，檔案位移＝`DS` 位移 ＋
`77B0h`）。**步是 1-based**，所以模式 `m` 實際用到的是
`02ACh + m×5 + 1` 起的五個 byte：

| 模式 | 五個偏移（原值）| mod 8 之後 |
|---:|---|---|
| 1 | `08 07 06 01 02` | 0、−1、−2、+1、+2 |
| 2 | `08 01 02 07 06` | 0、+1、+2、−1、−2 |
| 3 | `07 01 08 06 02` | −1、+1、0、−2、+2 |
| 4 | `01 07 08 02 06` | +1、−1、0、+2、−2 |
| 5 | `08 07 06 05 04` | 0、−1、−2、−3、+4 |
| 6 | `08 01 02 03 04` | 0、+1、+2、+3、+4 |

**六列兩兩成鏡像**：1 與 2 是「先往左試」與「先往右試」、3 與 4 是另一組
鏡像、5 一路往左掃、6 一路往右掃。這個對稱本身就是「步是 1-based」最強的
佐證——用 0-based 讀出來的六列沒有任何對稱可言。
`02ACh` 起的頭五個 byte 全是零，也與「模式從 1 起算」一致。

實作在 `gamepack.DefaultTacticOffsets`／`TacticOffsets.Direction`／
`NextTacticMode`，讀原始位元組的是 `ReadDOSTacticOffsets`。

算出方向之後，`066Eh` 就地試那一格：

```
06bc  013Dh:007Fh(記錄, 方向, &出界, &地形索引)   ; overlay-32 0CB9h
06d5  地形索引 == 0 → *出界 = 1，回 false          ; 走不到
06e5  有人           → 回 false                    ; 佔著了
06ee  al = DS:[2758h + 地形索引 × 4]               ; 格位類別表（spec 053／057）
0705  al >= entity +6 → 回 false                   ; 地形超出這一隻的能力
070e  否則回 true
```

所以每一步的判準是**佔用**與**格位類別對上這一隻的 `+6`**，不是距離。
回 false 的第一種情形（地形索引 0）代表那一格在盤面外，逃跑中的怪物就是
靠它跑出戰場。
