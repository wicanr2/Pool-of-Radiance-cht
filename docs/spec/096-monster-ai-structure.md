# Spec 096：怪物 AI 的骨架（overlay-09）

狀態：DRAFT（每回合的行為鏈與戰術模式已讀出；各行為本身與接近用的候選
搜尋只讀到入口）。日期：2026-09-03。

## 為什麼要讀它

remake 目前的敵方回合是權宜作法（「朝目標走一格，走不進去就試其餘七個
方向」）。實測在**斜向、牆很多的盤面上人一多就互相擋死**：41 隻敵人對
6 人隊伍，第 915 回合兩邊滿血、相鄰對數 0，敵方回報 `CLOSED 0 STEPS`。
四個可能的成因都排除掉了（見 WORKLIST），剩下的就是「移動規則不是原版的」。

## 入口與分派

overlay-08 entry 3（`01E4h`）依角色記錄的 `+10Fh` 分派：非零走
overlay-09 entry 1（`000Fh`），零走 overlay-08 `0307h` 的玩家指令迴圈。

## overlay-09 entry 1：一隻怪物的一個回合

它是一條**「依序試各種行為，誰先動就停」**的鏈：

```
0015h  acted = entry 7（0FC8h）
0027h  overlay-25 entry 21（1830h）
002Ch  記錄 +10Dh 為 0 時：acted = overlay-25 entry 34（266Dh）
0045h  mode = runtime 子結構的 +15h
0054h  mode 為 0 或大於 4 時重擲：
         骰(1,4) 不是 1 就沿用舊的；
         否則 mode = 骰(1,8)，等於 8 再改成 骰(1,2) + 4，其餘 骰(1,4)
00A6h  寫回 +15h
00B5h  還沒動 → acted = entry 8（10DDh）
010Fh  還沒動 → entry 3（03E3h）成立時交給 overlay-25 entry 34
012Eh  runtime +0 非零 → overlay-22 entry 5（0C14h）再交給 entry 34
0169h  還沒動 → entry 2（0203h）
```

所以**每隻怪物身上帶一個戰術模式**（runtime `+15h`，值 1..6），
多數回合沿用，四分之一的回合重擲；重擲時 1..4 佔八分之六、5..6 佔八分之二。

entry 2（`0203h`）是施法那一支：runtime `+11h` 為 0 且記錄 `+96h`（牧師等級）
大於 0 時，問 overlay-13 entry 13（`1352h`）有沒有法術可放。

## 接近用的候選搜尋

entry 11（`0255h`）先用型別表 `31A3h + 型別 × 16` 取一個參數，
呼叫 **overlay-31 entry 6（`0912h`）**，結果是一份候選清單
（`DS:6674h` 起，`6678h` 是筆數），再逐筆交給 overlay-25 entry 30（`23F5h`）。

`0912h` 的前半是：

```
091Ch  for i = 0..3:
0933h    overlay-32 entry 2（code 0）算出第 i 個位移 → (dx, dy)
093Ch    成功 → 候選[i] = (arg + dx, arg + dy)
096Eh    失敗 → 候選[i] 的 X 記成 FFh
097Fh  筆數 = 0；接著掃全部 [5E88h] 個戰鬥單位做篩選
```

也就是說原版**先列出目標周圍可站的格子，再挑**——不是像 remake 現在這樣
「朝目標的方向走一格」。這正是人一多時會不會擋死的分水嶺。
