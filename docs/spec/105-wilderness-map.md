# Spec 105：野外地圖——座標、三張圖怎麼接、地點表

狀態：READY（座標系統、拼接條件、四張表的版面與內容）；
DRAFT（每一步的可通行判定、地點腳本本身）

## 一句話

野外不是 16×16 的格子圖：隊伍的位置存在 `DS:49C3h`（X）與 `DS:49C4h`（Y），
由三張 ECL 區塊（25、26、27）由西到東接成一條，每一格「有沒有東西」用四張
連著放的表查出來。

## 座標與拼接

`49C3`／`49C4` 不是格子座標——碼頭設的值是 (7,29)、(13,27)、(9,29)，Y 超過 15。
X 的範圍是 2..15，Y 的範圍是 8..33。

三張圖由西到東是 **25 → 26 → 27**，跨圖的條件寫在每一張的入口 0：

| 從 | 條件 | 到 | 新的 X |
|---|---|---|---:|
| 26 | `49C3 == 15` 且 `49C4 != 25` | 27 | 3 |
| 26 | `49C3 == 2` 且 `49C4 != 31` | 25 | 14 |
| 27 | `49C3 == 2` | 26 | 14 |
| 25 | `49C3 == 15` | 26 | 3 |

（`49C4 == 25` 與 `49C4 == 31` 兩個例外是牆／河，不給過。）
`49C4 <= 2` 另有一支（北緣），還沒讀。

移動本身也是 ECL 自己做的：入口 0 先把 `49C3`／`49C4` 抄進 `DS:00FBh`／
`DS:00FCh`，再用一張八支的 `ON GOSUB`（ecl7/26 `9A18h`）依方向各對那一對
±1——**八個方向，正好是原版的八方位移動**。

## 地點表：四張表連著放

入口 1 用四張表把座標換成地點編號，再 `ON GOTO` 分派：

```
6E7C = 0；6E79 = 0
迴圈：6E7B = 每列數量表[6E79]；6E7A = Y 表[6E79]
      Y 表[6E79] == 49C4 → 找到這一列
      否則 6E79++、6E7C += 6E7B
找到列之後：在 X 表的 [6E7C, 6E7C+6E7B) 裡找 == 49C3 的那一項
找到就 6E79 = 地點編號表[6E7C]，ON GOTO 6E79
```

四張表的位址（從靜態追蹤的 `GETTABLE` 第一個運算元讀出來）：

| 區塊 | Y 表 | X 表 | 每列數量 | 地點編號 | 列 | 地點 |
|---|---|---|---|---|---:|---:|
| ecl6/25 | `ADD6` | `ADDE` | `ADF5` | `ADFD` | 8 | 23 |
| ecl7/26 | `B04A` | `B053` | `B061` | `B06A` | 9 | 14 |
| ecl8/27 | `ABA6` | `ABAB` | `ABB4` | `ABB9` | 5 | 9 |

四張表是連著放的，所以**長度從位址差算得出來**：列數 = X 表 − Y 表，
項目數 = 每列數量表 − X 表。三張圖都對得起來（每列數量加總 == 項目數）。

```
tools/go.sh run ./cmd/pool-wilderness-map -text
```

## 對 remake 的意思

隊伍已經走得進野外圖了（spec 104 修掉 `2Dh CALL` 之後），但**第一步就被送回
城區**：remake 沒有維護 `49C3`／`49C4`，所以入口 0 的分派讀到的是碼頭設的那
一組值再也不變，而入口 1 的地點查表每次都命中同一個地點。

要接的是：把野外的移動交給 ECL（前端只送方向），並用 `DS:00FBh`／`DS:00FCh`
的結果更新 `49C3`／`49C4`。畫面那一層是另一件事——野外圖用哪一張 GEO、
怎麼投影成畫面，還沒讀。
