# Spec 072：可記憶法術數與睿智加成

狀態：CONFORMED（兩張表的位址與版面、第 2..6 級的值、睿智加成的五個分段、
角色記錄的落點；與三名預設施法者的既有記錄端對端相符）；
DRAFT（第 1 級的格數由哪裡寫入、多職業如何合併）。日期：2026-09-03。

## overlay-23 是「依職業等級重算衍生數值」

同一支函式一次算完好幾件事（`docs/audit/ida-overlay23-derived-stats.json`）：

| 位址 | 算什麼 | 寫到 |
|---|---|---|
| `0009h..0062h` | 逐職業查 `3C16h` 取最好的基礎 THAC0（spec 063）| `+2Dh` |
| `0066h..0078h` | 最高職業等級 | `+73h` |
| `007Ch..009Dh` | 戰士 7 級以上攻擊次數 3，否則 2（spec 051 的 `+A1h`）| `+A1h` |
| `00B0h..00E2h` | 牧師的法術格數 | `+0B2h`..`+0B4h` |
| `00EBh` | 睿智加成 | 同上 |
| `0141h..017Dh` | 法師的法術格數 | `+0B5h`..`+0B7h` |

## 兩張表

取值是 `base + level × 3 + spellLevel`，`spellLevel` 是 1..3，
所以**有效的列基底比表頭多一個 byte**：

| 表 | 表頭 | 有效基底 |
|---|---|---|
| 牧師 | `DS:4034h` | `DS:4035h` |
| 法師 | `DS:414Ch` | `DS:414Dh` |

| 角色等級 | 牧師 | 法師 |
|---:|---|---|
| 2 | 2/0/0 | 2/0/0 |
| 3 | 2/1/0 | 2/1/0 |
| 4 | 3/2/0 | 3/2/0 |
| 5 | 3/3/1 | 4/2/1 |
| 6 | 3/3/2 | 4/2/2 |

與 AD&D 逐項相同。第 7 級以上是零，與 spec 071 的等級上限（牧師 6、法師 6）
一致。**第 1 級不走這條路**（`cmp [bp-3], 1; jle` 直接跳過），表裡那一列是
`FFh` 佔位。

## 記錄裡的排法：`+0B1h` 加組別加等級

overlay-15 的記憶畫面（`0619h`）用同一個基底讀這六格：

```
611  les  di, ds:5CF0h                  ; 目前角色
615  add  di, ax                        ; ax = 職業組 × 3
617  add  di, cx                        ; cx = 法術等級，1 起算
619  cmpb $0, es:[di+0B1h]
```

所以位移是 **`+0B1h + 組 × 3 + 等級`**，等級 1 起算：牧師第 1 級落在 `+0B2h`、
法師第 1 級落在 `+0B5h`，與上面 overlay-23 寫入的位置相符。
`+0B1h` 本身是不含體質加成的 HP（spec 097），與這個陣列只是相鄰。

**這六格是上限，不是遞減的剩餘量。** overlay-15 只讀它們，全遊戲沒有一處減它
（唯一的 `dec` 在 overlay-12，扣的是 `+0B1h` 那個 HP 欄位）。所以
「還能記幾個」要用「上限減掉已經記了幾個」算。

### 十個預設施法者逐一對得上

拿記憶陣列（spec 070）的編號查參數表的職業與等級（spec 074），再和這六格比：

| 檔案 | 職業與等級 | 上限 | 已記 |
|---|---|---|---|
| `chrdatd3` ALFRED | 牧師 6 | 5/5/3 | 5/5/3 |
| `chrdatb3` ALFRED | 牧師 5 | 5/5/2 | 5/3/2 |
| `chrdate3` ALFRED | 牧師 5 | 5/5/2 | 0/5/2 |
| `chrdata7` DIRTEN | 牧師 5 | 5/5/1 | 3/2/1 |
| `chrdatd5` TARRY | 法師 6 | 4/2/2 | 3/2/2 |
| `chrdatd6` CARRY | 法師 6 | 4/2/2 | 4/2/2 |
| `chrdate5` TARRY | 法師 5 | 4/2/1 | 2/2/0 |
| `chrdate6` CARRY | 法師 5 | 4/2/1 | 0/2/0 |
| `chrdatb5` TARRY | 法師 4 | 3/2/0 | 3/1/0 |
| `chrdatb6` CARRY | 法師 4 | 3/2/0 | 2/1/0 |

**十個全部落在上限之內，沒有一個超過。** 這同時釘住四件事：記憶陣列的位置與
1-based 編號、參數表的職業與等級欄位、可記憶數表加睿智加成、以及這裡的排法。
任何一個讀錯就會有人記得比上限多。睿智 18 的牧師拿到 5/5/3 而基礎表是 3/3/2，
差的 +2/+2/+1 正是 AD&D 睿智 18 的加成。

## 第 1 級的格數在建角時寫下

overlay-16 的建角常式（`docs/audit/ida-overlay16-first-level-spell-slots.json`）
走過職業陣列，等級大於零的職業各給**一格**第一級法術：

```
7210  cmp byte ptr es:[di+96h], 0      ; 這個職業有等級嗎
7224  cmp al, 0                        ; 職業 0 ＝ 牧師
7231  mov byte ptr es:[di+0B2h], 1
7239  cmp al, 5                        ; 職業 5 ＝ 法師
7246  mov byte ptr es:[di+0B5h], 1
```

同一段也寫下基礎移動 `+72h = 0Ch`，與 spec 063 相符。

**第 1 級沒有睿智加成**：overlay-23 的加成是在「等級大於 1」的分支裡呼叫的，
一級角色走不到那裡。照原版的行為接，不照規則書補——規則書會給高睿智的
一級牧師額外的格子，原版不會。

## 睿智加成（overlay-23 `01ADh`）

讀 `+12h`（睿智），逐段各加一次，**而且只加在本來就有格子的等級上**：

| 條件 | 加到 |
|---|---|
| 睿智 > 12 | 第 1 級 |
| 睿智 > 13 | 第 1 級（再一次）|
| 睿智 > 14 | 第 2 級 |
| 睿智 > 15 | 第 2 級（再一次）|
| 睿智 > 16 | 第 3 級 |

`cmp .., 0; jbe` 那個守衛不能省：少了它，一個第 2 級的牧師會憑空得到
第三級法術的格子。

## 端對端驗證

ALFRED（牧師 6、睿智 18）：表給 3/3/2，加成後 5/5/3；他的記錄
`+0B2h..+0B4h` 就是 `05 05 03`，而 spec 070 解出來的記憶內容也正好是
治療輕傷×5、束縛敵人×5、三個第三級。
TARRY 與 CARRY（法師 6）：表給 4/2/2，記錄 `+0B5h..+0B7h` 是 `04 02 02`。

表位置、`+1` 偏移、睿智加成、記錄落點四件事任一處錯，這個比對都不會過。

## 先前找不到的原因

上一輪用六種版面在 START.EXE 與 38 顆 overlay 搜 AD&D 的進程都落空
（spec 071）。原因是搜尋樣式從第 1 級的 `1,0,0` 開始，而**那一列根本不在表裡**
——表頭六個 byte 是 `FF`，真正的資料從第 2 級起。搜尋面沒有洞，是樣式本身
帶了一列不存在的資料。

## 不做

- 不補第 1 級的格數。要找到寫它的地方再說。
- 不處理多職業的合併。`+0B2h` 與 `+0B5h` 是兩組欄位，雙職業怎麼疊還沒讀。
