# Spec 075：豁免判定

狀態：CONFORMED（判定順序、角色記錄的五格豁免表與其欄位順序、修正欄位、
法術端的類別欄位）；DRAFT（`0100h:002Fh` 在判定中途做了什麼、怪物記錄是否
共用同一份版面）。日期：2026-09-03。

## 全遊戲只有一支

overlay-24 的 entry 7（code `0D61h`）。施法路徑（spec 074）在 `0984h` 呼叫它，
帶四個 word：呼叫端修正、豁免類別、目標的遠指標。

```
0D6A  擲 d20                              ; 0DE5h，count=1 sides=14h
0D79  骰值 = 1  → 回 0（失敗）
0D84  骰值 = 20 → 回 1（成功）
0D8F  cx = 帶正負號的呼叫端修正（bp+6）
0D95  es:di = 目標記錄
0D98  dx = 帶正負號的 es:[di+101h]        ; 記錄裡的豁免修正
0DA5  ds:6774h = 骰值 + dx + cx
0DAC  ds:6788h = 豁免類別
0DB2  呼叫 0100h:002Fh（目標, 0Ch）
0DC8  al = es:[di + 6Dh + 類別]           ; 目標值
0DCC  目標值 ≤ ds:6774h → 回 1，否則回 0
```

**自然 1 與自然 20 在加修正之前就返回。** 順序反過來的話，一個修正夠大的
角色連自然 1 都會豁免成功。

## 角色記錄 `+6Dh` 起是五個目標值

順序與 AD&D 規則書的欄位相同：

| 索引 | 類別 |
|---:|---|
| 0 | 癱瘓／毒／死亡魔法 |
| 1 | 石化／變形 |
| 2 | 法杖／魔杖／權杖 |
| 3 | 吐息 |
| 4 | 法術 |

七名預設人物逐列與規則書相同，涵蓋五個職業等級組合：

| 記錄 | 職業等級 | `+6Dh..+71h` |
|---|---|---|
| `chrdatd1`／`chrdatd2` | 戰士 8 | 10, 11, 12, 12, 13 |
| `chrdatd3` | 牧師 6 | 9, 12, 13, 15, 14 |
| `chrdatd4` | 賊 9 | 11, 10, 10, 14, 11 |
| `chrdatd5`／`chrdatd6` | 法師 6 | 13, 11, 9, 13, 10 |
| `chrdatd7` | 戰士 4 | 13, 14, 15, 16, 16 |

五組全中，所以順序是 **exact**，不是套規則書套出來的。

`+101h` 是記錄自己的豁免修正，帶正負號；七名預設人物都是 0。

## 法術端

參數表（spec 074）的 `+9` 就是這裡的類別索引：65 個編號用 4（對法術），
Stinking Cloud 與編號 61 的癱瘓效果用 0。施法路徑傳入的呼叫端修正是 0，
所以法術的豁免不另外加減。

## 那五格是誰寫的

overlay-23 `0253h`，一個 far pointer 參數：

```
for i in 0..4:
    record[+6Dh + i] = 14h                       ; 先全設成最差
    for j in 0..7:
        level = record[+96h + j]                  ; 第 j 個職業的等級
        if level <= 0: continue
        value = [41E6h + j*2Dh + level*5 + i]
        if record[+6Dh + i] > value: record[+6Dh + i] = value
```

所以多職角色每個類別各取最好的那一個，與規則書一致。

表在 `DS:41E6h`，每個職業 45 bytes ＝ 9 列 × 5 格，**列用等級直接索引**——
AD&D 每三級才換一列，原版就把同一列重複三次。等級大於 8 時索引落進下一個
職業的第 0 列，那不是溢位而是刻意的接續：賊第 9 級讀到的正是 AD&D 賊 9..12
的 11/10/10/14/11。

職業槽的編號由兩件事釘住：記錄 `+96h` 是牧師、`+9Bh` 是法師（相差 5），
而表的第 5 個職業正是 AD&D 法師那一列。等級上限（牧師 6、戰士 8、法師 6、
賊 9，spec 071）都落在表內。

驗收：七名預設人物記錄裡已經算好的五格全部重算得出來，另外五列直接與
規則書比對（牧師 1..3、戰士 1..2、法師 1..5、賊 1..4、賊 9..12）。

## 還沒讀

- `0100h:002Fh`（overlay-24 entry 3，code `02E2h`）在取目標值之前被呼叫，
  帶常數 `0Ch`。`0253h` 是目前唯一找到的 `+6Dh` 寫入點（四種寫入版面在
  38 顆 overlay 裡全掃過），但 `02E2h` 本身還沒讀。
- 怪物是不是也用同一份 285-byte 版面。
