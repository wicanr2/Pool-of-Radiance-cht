# Spec 075：豁免判定

狀態：CONFORMED（判定順序、角色記錄的五格豁免表與其欄位順序、修正欄位、
法術端的類別欄位）；DRAFT（`0100h:002Fh` 在判定中途做了什麼、怪物記錄是否
共用同一份版面）。日期：2026-09-03。

## 全遊戲只有一支

overlay-24 的 entry 7（code `0D61h`）。施法路徑（spec 074）在 `0984h` 呼叫它，
帶四個 word：呼叫端修正、豁免類別、目標的遠指標。

```
0D6A  擲 d20                              ; 0DE5h，count=1 sides=14h
0D79  骰值 = 1  → 回 0（失敗）
0D84  骰值 = 20 → 回 1（成功）
0D8F  cx = 帶正負號的呼叫端修正（bp+6）
0D95  es:di = 目標記錄
0D98  dx = 帶正負號的 es:[di+101h]        ; 記錄裡的豁免修正
0DA5  ds:6774h = 骰值 + dx + cx
0DAC  ds:6788h = 豁免類別
0DB2  呼叫 0100h:002Fh（目標, 0Ch）
0DC8  al = es:[di + 6Dh + 類別]           ; 目標值
0DCC  目標值 ≤ ds:6774h → 回 1，否則回 0
```

**自然 1 與自然 20 在加修正之前就返回。** 順序反過來的話，一個修正夠大的
角色連自然 1 都會豁免成功。

## 角色記錄 `+6Dh` 起是五個目標值

順序與 AD&D 規則書的欄位相同：

| 索引 | 類別 |
|---:|---|
| 0 | 癱瘓／毒／死亡魔法 |
| 1 | 石化／變形 |
| 2 | 法杖／魔杖／權杖 |
| 3 | 吐息 |
| 4 | 法術 |

七名預設人物逐列與規則書相同，涵蓋五個職業等級組合：

| 記錄 | 職業等級 | `+6Dh..+71h` |
|---|---|---|
| `chrdatd1`／`chrdatd2` | 戰士 8 | 10, 11, 12, 12, 13 |
| `chrdatd3` | 牧師 6 | 9, 12, 13, 15, 14 |
| `chrdatd4` | 賊 9 | 11, 10, 10, 14, 11 |
| `chrdatd5`／`chrdatd6` | 法師 6 | 13, 11, 9, 13, 10 |
| `chrdatd7` | 戰士 4 | 13, 14, 15, 16, 16 |

五組全中，所以順序是 **exact**，不是套規則書套出來的。

`+101h` 是記錄自己的豁免修正，帶正負號；七名預設人物都是 0。

## 法術端

參數表（spec 074）的 `+7` 就是這裡的類別索引：65 個編號用 4（對法術），
Stinking Cloud 與編號 61 的癱瘓效果用 0。施法路徑傳入的呼叫端修正是 0，
所以法術的豁免不另外加減。

## 還沒讀

- `0100h:002Fh`（overlay-24 entry 3，code `02E2h`）在取目標值之前被呼叫，
  帶常數 `0Ch`。它可能是「重算衍生數值」那一類，也可能會動到 `+6Dh` 那五格；
  沒讀之前不能假設目標值在判定期間不變。
- 怪物是不是也用同一份 285-byte 版面。
