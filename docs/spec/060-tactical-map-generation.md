# Spec 060：戰術地圖的生成

狀態：READY（配置大小、格位版面、標頭三個寫入、室外整面填值、
室內生成的視窗與迴圈順序）；DRAFT（室內四支細節建構器、室外四支細節建構器、
`DS:495Bh` 模式值的完整清單、`DS:35E2h` 大地圖表的形狀）。日期：2026-09-02。

## 結論先講

戰術地圖**不是從資料檔載入的**，而是在戰鬥開始時生成。這解釋了為什麼
DAX 盤點裡找不到對應的 consumer——找不到不是儀器有洞，是原版真的沒有這種檔案。

## 證據

| 檔案 | 內容 | 輸入 SHA-256 |
|---|---|---|
| `docs/audit/ida-overlay10-tactical-map-build.json` | overlay-10 `12E5h`（配置與分派）、`1380h` | `b929c704…399b` |
| `docs/audit/ida-overlay10-terrain-fill.json` | overlay-10 `1255h`（室外）、`0820h`（室內） | 同上 |
| `docs/audit/ida-overlay08-tactical-map-teardown.json` | overlay-08 `0000h` 的拆除程序 | `932ce281…a036f` |

`DS:6674h` 這個遠指標在全部 38 顆 overlay 與 `START.EXE` 裡只有兩處被寫：
overlay-10 `134Bh` 的 `GetMem` 與 overlay-08 `004Bh` 的釋放後清零。
配置與釋放的大小都是 `4E9h`，兩邊一致。

## 版面

`4E9h` ＝ 1257 ＝ 7 ＋ 50×25。前 7 個 byte 是標頭，其後是每格一個 byte 的
格位類別，列距 50——與 spec 057／058 由 `y×32h + x + 7` 反推的版面完全吻合，
而且是由配置大小獨立證實的。

配置後立刻寫下三個標頭 byte：

| 位移 | 值 | 已知用途 |
|---|---|---|
| +4 | 0 | 未定 |
| +5 | 1 | 未定 |
| +6 | 0 | 「跳過地形判定」旗標（spec 057）；0 表示判定生效 |

其餘四個 byte 在這一步沒有被寫。

## 室外：overlay-10 `1255h`

1. `FillChar(map + 7, 4E2h, 17h)`——整面 1250 格填成類別 `17h`。
   該類別在格位類別表裡的 `EntryThreshold` 是 1、`PathByte2` 是 0，
   也就是可進入、不擋路徑：平坦戰場。
   `17h` 同時是目的格探測（spec 058）寫下的初值，兩處是同一個常數。
2. 由 `DS:4933h` 的 `+186h`／`+188h` 取得隊伍在大地圖的座標；
   `DS:495Bh` 為 3 時把 X 加 `0Dh`，為 4 時加 `1Ah`。
3. 以 `y × 2Ch + x` 查 `DS:35E2h`，把結果存進 `DS:45BCh`。
   `2Ch` ＝ 44，故 `35E2h` 是一張 44 格寬的大地圖表；三個模式的 X 偏移
   0／13／26 指向同一張表裡的三個橫向區段。
4. 依序呼叫四支建構器 `0C7Ah`、`0DB0h`、`0F3Fh`、`0000h`。

## 室內：overlay-10 `0820h`

由地城幾何生成，不是填平面：

外層 `dy` 由 −2 到 +2、內層 `dx` 由 −6 到 +6，共 13×5 ＝ 65 個地城格。
每一格以隊伍座標（`DS:6A0Bh`、`DS:6A0Ch`）加上偏移得到地城座標，
再用三次牆面查詢（`01BAh`，方向碼 6、0、2）取得該格三個方向的牆，
最後交給四支建構器 `02BEh`、`037Bh`、`0413h`、`061Fh` 寫進戰術格。

13 個地城格對到 50 格寬、5 個地城格對到 25 格高，因此一個地城格約等於
戰術上的 4×5 格。四支建構器如何落筆尚未閉合。

## 生命週期

overlay-08 的 unit 初始化（`0000h`）其實是拆除：先走訪 `DS:6CAFh` 的串列
逐節點釋放 `13h` bytes，再釋放 `DS:6674h` 的 `4E9h` bytes 並把指標清零。
因此戰術地圖的存活期是一場戰鬥，不跨戰鬥保留。

## READY 契約

1. 戰術地圖在戰鬥開始時生成，不得改成從檔案載入或預先烘焙進 game pack。
2. 格數固定 50×25，標頭 7 bytes；配置大小 `4E9h` 是這個版面的獨立佐證，
   兩者不一致時以原版位元組為準。
3. 室外戰場整面是類別 `17h`；不得因為「看起來像草地」就換成別的類別，
   也不得跳過標頭 `+6` 的寫入。
4. 室內戰場的生成順序是外層 Y、內層 X，兩層都由負值遞增；
   在四支建構器閉合前不得自行推定地城格到戰術格的對應比例。
