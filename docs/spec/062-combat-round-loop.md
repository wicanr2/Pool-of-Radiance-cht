# Spec 062：戰鬥回合迴圈與結束條件

狀態：READY（迴圈骨架、回合內的步驟順序、倒地計時、結束條件與清場後的續戰
提示、`DS:4955h` 恆為 0）；DRAFT（`DS:6772h`／`DS:6773h` 的維護者、
回合收尾裡幾個服務的內容）。日期：2026-09-02。

## 為什麼需要這一段

spec 052 為了替先攻分數命名，順帶提過 `0071h` 主迴圈會反覆呼叫選取與行動處理。
本規格把整個迴圈讀完：一個回合裡依序做什麼、戰鬥什麼時候結束、
以及清光敵人之後為什麼不一定就結束。

| `docs/audit/ida-overlay08-combat-loop.json` | overlay-08 `0000h`（拆除）與 `0071h..0123h`（主迴圈） | `932ce281…a036f` |
| `docs/audit/ida-overlay08-initiative-selection.json` | overlay-08 `0124h..01E1h`（先攻選取） | 同上 |

overlay-08 只有一個 entry 被別的 overlay 呼叫——entry 1（`0071h`），由 overlay-03
呼叫。其餘 entry 全是 overlay-08 內部的近呼叫。因此整場戰術戰鬥就是這一支函式。

## 迴圈骨架：overlay-08 `0071h`

```
DS:4954h = 5                       ; 進入戰鬥模式
DS:6A78h = 0096h:007Ah             ; 安裝 overlay-13 entry 18 當回呼
overlay-10 entry 1                 ; 戰鬥佈置
結束 = (DS:6772h == 0) 或 (DS:6773h == 0)
while 不結束:
    overlay-25 entry 31            ; 回合開始
    for 每個 combatant（沿 DS:5CF4h 串列，`+104h` 是下一個）:
        overlay-13 entry 1         ; 移動預算初始化（spec 053）
    [DS:4937h + 596h] = 0
    loop:
        overlay-08 entry 2 選出下一個行動者；選不到就跳出
        overlay-08 entry 3 讓它行動
    overlay-08 entry 6 決定要不要結束
overlay-08 `0000h`                 ; 釋放戰術地圖（spec 060）
```

先攻選取放在**回合內的迴圈**裡，每次行動完再選一次，而不是回合開始時排好一張
順序表。重建時不可改成先排序再依序執行。

## 回合收尾：overlay-08 `0868h`

1. 呼叫 overlay-20 entry 2（參數 1, 1）。
2. `DS:6CD7h` 加一。那個位址是 spec 056 篩選結果陣列的折疊基底，
   陣列本身自 `6CD8h` 起，所以基底那一個 byte 空著被拿來當**回合計數**。
3. 呼叫 overlay-13 entry 25。
4. 沿 `DS:5CF4h` 串列走一遍，每個 combatant：
   - overlay-24 entry 3，effect code `13h`；
   - overlay-24 entry 4；
   - 狀態 `+10Ch` 為 5 時，把 `+108h` 結構的 `+0Eh` 加一；超過 9 就把狀態改成 6。
     這是倒地者的計時：撐過十個回合就轉成另一個狀態。
5. overlay-08 entry 10；回傳非 0 時顯示一則訊息。
6. overlay-25 entry 31、overlay-32 entry 13（帶戰術地圖 record 的 `+2`、`+3` 各加 3）。
7. **結束判定**：`DS:6772h` 或 `DS:6773h` 任一為 0 就把結束旗標設為 1。
8. **清場後的續戰提示**：`DS:6772h > 0`、`DS:6773h == 0` 且 `DS:4955h == 0` 時，
   顯示一則提示並讀鍵；答 `Y` 就把結束旗標改回 0。

第 8 步是「我方還在、敵方清光」那一支才有的，所以 `DS:6773h` 是敵方存活數、
`DS:6772h` 是我方。敵人清光不必然立刻結束戰鬥——這一步不可省略。

## READY 契約

1. 回合內的順序是：回合開始、逐一初始化 combatant、清回合狀態、
   反覆「選行動者→行動」、回合收尾。順序本身就是行為。
2. 先攻每次行動後重選，不得預先排好順序表。
3. 進迴圈前先做一次結束判定，戰鬥可能一個回合都不跑。
4. 倒地計時是每回合加一、超過 9 才轉狀態；不得改成「第 10 回合立刻死亡」
   之外的其他門檻，也不得對非倒地狀態動它。
5. 清光敵人後的續戰提示要保留；`DS:4955h` 非 0 時不問。
6. 結束旗標由回合收尾產出，主迴圈只負責讀它，不自行判斷存活數。

## 實作對應

`cmd/pool-game` 的 `endRound` 就是 `0868h` 的收尾：先推進倒地計時
（`combat.AdvanceDyingCounter`），再數兩邊存活數，「我方還在、敵方清光」時
先問一次要不要繼續，其餘情形才由 `combat.RoundEndsCombat` 決定結束。
攻擊本身不再自行結束戰鬥——契約 6 說結束旗標由回合收尾產出。

`DS:4955h` 閉合了：**全遊戲只有一處寫它**——overlay-11 `03C1h` 的啟動設定
把它設成 0（同一段還設 `494Eh` = 9900h、`4943h` = 4、`52D4h` = 1）。
四種寫入版面在 38 顆 overlay 裡掃過，只有這一個命中，而它寫的是 0。
所以正常遊玩時那個條件恆為真，**「一律問」就是原版的行為**，不是近似。

提示句的原文是 `Continue Battle:`（overlay-08 `0857h`），答 `Y` 會把
「戰鬥結束」那個出參設成 0，也就是繼續打；其餘按鍵讓戰鬥結束。

同一段附近還有 `Your Teammate is Dying`（`0840h`），那是倒地計時的提示，
remake 還沒有取用點。
