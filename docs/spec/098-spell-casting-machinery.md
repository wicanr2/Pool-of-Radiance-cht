# Spec 098：施法的共用機制（擲骰、施法者等級、處理常式的呼叫慣例）

狀態：CONFORMED（擲骰常式與引數順序、施法者等級的取法與那個覆寫旗標、
處理常式呼叫 `08BCh` 的形狀）；DRAFT（`08BCh` 自己在做什麼、四個覆寫參數的
語意、各法術的傷害）。日期：2026-09-03。

## 擲骰：overlay-24 的兩支

`0DE5h`（entry 8，stub `48h`）是全遊戲的擲骰：

```
def  cmpb $0, 0x8(%bp)          ; 顆數
df5  mov  al, 0x8(%bp)
e0a  mov  al, 0x6(%bp)          ; 面數
e0f  push ax
e10  lcall 05BBh:0C94h          ; Turbo Pascal 的 Random(n) → 0..n-1
e15  inc  ax                    ; → 1..n
e16  add  al, -0x3(%bp)
```

Pascal 由左往右推，所以 `[bp+8]` 是**先推的**、`[bp+6]` 是後推的：
**先推顆數、後推面數**，寫成 `Roll(顆數, 面數)`。

反面對照確認過這個順序：overlay-09 entry 1 推 `1` 再推 `8`，
接著 `cmp al, 8` 分岔。若順序相反就是 8d1，永遠等於 8，那條分支是死碼。

`0E30h`（entry 9，stub `4Dh`）是同一件事外加**把顆數記在 `DS:677Ah`**，
然後轉呼叫 `0DE5h`。法術的傷害走這一支，普通判定走 `48h`。

## 施法者等級：overlay-25 `26F8h`

引數是法術編號，回傳等級：

```
2709  mov  al, [di+3194h]              ; 參數表 +0（職業）
270d  cmp  al, 0 → 讀 DS:5CF0h→+96h    ; 牧師等級
271f  cmp  al, 1 → 讀 DS:5CF0h→+9Bh    ; 法師等級
2731  cmp  al, 2 → 12                  ; 物品效果一律 12 級
2739  cmpb $0, ds:6CB3h                ; 非零而且職業不是 2
2752  mov  byte ptr [bp-1], 6          ; → 等級一律當成 6
```

`DS:6CB3h` 由 **overlay-19**（人物檢視畫面：`Weapon`／`AC`／`THAC0`／
`Items`／`Spells`／`in Memory`／`in Spell Book`／`on Scroll`）在 `1AE2h`
與 `1BBDh` 設為 1、在 `1BDDh` 清回 0；overlay-22 的派發表初始化
（`33E1h`）也把它清成 0。所以**從人物畫面施法（戰術地圖之外）時，
施法者等級一律當成 6**，戰鬥中才用真正的職業等級。

## 處理常式怎麼呼叫 `08BCh`，四個覆寫參數各是什麼

`08BCh` 收七個 word（`retf 0Eh`）。由堆疊位移反推（先推的在高位）：

| 位移 | 推入順序 | 是什麼 | 誰用它 |
|---|---:|---|---|
| `[bp+12h]` | 1 | 法術編號 | 查參數表、取施法者等級 |
| `[bp+10h]` | 2 | **施法者等級的覆寫**，0 就用真的 | `08F2h` 的 `cmpb $0` 分岔 |
| `[bp+0Eh]` | 3 | 掛效果時一起傳出去的參數 | `0A3Dh` |
| `[bp+0Ch]` | 4 | **傷害**，0 就整段跳過 | `09DFh` 的 `cmpb $0` / `jbe` |
| `[bp+0Ah]` | 5 | 傷害的種類選擇，寫進 `DS:6777h` | `08E2h`，只在傷害非零時 |
| `[bp+6..8]` | 6、7 | 訊息遠指標 | `08C2h` 複製進區域變數 |

第二格是「施法者等級的覆寫」這件事由**鏡影術**釘住：`1A79h` 把 `Roll(1, 4)`
推在那一格而不是傷害那一格——鏡影的數量借等級那一格傳。

大多數常式四個覆寫參數都推 0，差異全部來自參數表（spec 074）。
會算傷害的那幾支就用第四格把結果傳進去。

Magic Missile（編號 15，`1429h`）是最短的一支：

```
1433  lcall 010Ah:00D4h                 ; 等級 = CasterLevel(編號)
1445  等級 ÷ 2                           ; 有號整數除法
1454  lcall 0100h:004Dh                 ; Roll(等級÷2, 4)
145d  等級 ÷ 2
1468  add  ax, bx                       ; 傷害 = (等級÷2)d4 + 等級÷2
146b  push 8                            ; 第四個覆寫參數
147e  call 08BCh
```

形狀就是 AD&D 的「N 發，每發 1d4+1」，**N ＝ 等級 ÷ 2 取整**。

### 未解：發數與說明書對不起來

說明書寫的是「魔法師每昇兩級可多擲出一個魔法飛彈，第 3 或第 4 級擲 2 個，
第 5 或第 6 級擲 3 個」，也就是 `(等級+1) ÷ 2`。
碼算的是 `等級 ÷ 2`：偶數等級兩者相同（6 級 3 發），
**奇數等級碼少一發，而且第 1 級算出來是 0 發、0 點傷害**。

三個可能的出口已經關掉兩個：

- **`08BCh` 裡沒有下限。** `09DFh` 是 `cmpb $0, [bp+0Ch]` / `jbe`——
  傷害是 0 就整段跳過，連套用都不做。
- **引數順序沒讀反。** Fireball（`262Eh`）推 `等級` 再推 `6`，
  說明書寫的正是「1-6 點 × 施術者等級」，兩邊逐字相符。
  同一支 `26F8h` 回的是**沒有加工的職業等級**。

剩下的可能是「原版就是這個行為，說明書寫得比較寬鬆」。
**這裡照碼接**：原始執行檔是一手資料，說明書是二手的，而 remake 要重現的是
遊戲的行為。`internal/gamepack.CastSpell` 算的就是 `等級 ÷ 2`，
測試把第 1 級的 0 傷害釘住，所以哪天驗出不同的結果會是紅的而不是靜悄悄的。

**決定性的實驗（還沒做）**：在原版拿一個第 1 級法師對敵人施魔法飛彈，
看傷害是不是 0。做完再回來改這一條與 `SpellIDMagicMissile` 那一段。

## Fireball：引數順序的正對照

Fireball（`262Eh`）的傷害是

```
26fd  mov  al, [bp-1]      ; 施法者等級
2700  push ax              ; 顆數
2701  mov  al, 6
2703  push ax              ; 面數
2704  lcall 0100h:004Dh     ; Roll(等級, 6)
```

說明書寫「其程度＝1-6 點×施術者等級」，兩邊逐字相符。這同時確認了
`Roll(顆數, 面數)` 的順序與「`26F8h` 回的是沒有加工的職業等級」。

## 範圍怎麼收人：預算交給 `0419h`

`0912h` 的七個引數（由堆疊位移反推，先推的在高位）：

| 位移 | 是什麼 |
|---|---|
| `[bp+12h]` | 來源 X |
| `[bp+10h]` | 來源 Y |
| `[bp+0Eh]` | **預算**，原封不動交給 `0419h` 當上限 |
| `[bp+0Ch]` | 方向（`FFh` → 8，等於不限方向）|
| `[bp+0Ah]` | 體型類別 |
| `[bp+8]`、`[bp+6]` | 兩個輸出指標 |

所以**「在範圍內」＝「那個預算內走得到」**，不是半徑比大小。
火球術推的預算是 **2**（`2675h`），方向 `FFh`。

remake 已經照這個接（`tacticalState.withinArea`）。**其他範圍法術的預算
還沒讀**，那些先收整邊，`CastEffect.AreaBudget` 為零就是這個意思。

## Fireball 的第二個入口

Fireball（`262Eh`）先設 `DS:677Eh = 1`，然後分兩條：法術編號等於 `40h`
時等級是 `Roll(1,3) × 2 + 1`（也就是 3、5、7 隨機），否則照 `26F8h` 取。
編號 `40h` 與 47 共用這支常式，所以那是另一個來源的火球（捲軸或魔杖）。

接著看 `DS:4933h → +1CCh`：**為零走範圍那條**（`0138h:003Eh`，預算 2），
**非零走 `26E0h`**——那一條先 `013Dh:0061h(X, Y, 0, 8)` 再直接進 `08BCh`，
是單一目標的路。那個欄位是什麼還沒讀，所以 remake 一律走範圍那條。

## 催眠術的花費表

`1513h` 先把 `DS:677Eh` 設為 1（範圍法術），額度 `DS:47A6h = Roll(4, 4)`，
再走目標清單，依目標的 `+73h`（最高職業等級，怪物就是生命骰）扣：

| `+73h` | 1 以下 | 2 | 3 | 4 | 5 | 6 以上 |
|---|---:|---:|---:|---:|---:|---:|
| 花費 | 1 | 2 | 4 | 6 | `+2Eh` 為 0 花 10，否則 20 | 20 |

額度不夠就放不倒。六段以上一律 20，而額度上限是 16，所以**生命骰 6 以上
的怪物催眠術完全無效**——說明書寫的「一定程度以上的敵人，催眠術將會完全
失效」就是這一格。

掛上去的效果碼是 `35h`，overlay-15 的名稱鏈把它叫 **"Funky--"**（spec 069）。

## 二十五支是純泛型的，不必逐支讀

六十七支裡有一大批**只做兩件事**：把一段字面訊息複製到區域變數，
然後推「法術編號 ＋ 四個零」呼叫 `08BCh`。它們沒有自己的算法——射程、
持續、豁免與掛哪一個效果全部來自參數表（spec 074）。

版型（以 Protection From Evil `110Bh` 為例）：

```
55 89 E5 [83 EC nn]      push bp / mov bp,sp / sub sp,nn
A0 79 67 50              mov al, ds:6779h / push ax     ; 法術編號
(B0 00 50) × 4           push 0 四次                     ; 四個覆寫參數
8D 7E nn 16 57           lea di,[bp-nn] / push ss / push di
BF lo hi 0E 57           mov di, 訊息位移 / push cs / push di
9A 34 06 BB 05           lcall 05BBh:0634h              ; 字串指派
0E E8 lo hi              push cs / call 08BCh
89 EC 5D CB              mov sp,bp / pop bp / retf
```

`internal/gamepack.ParseGenericSpellHandlers` 逐位元組比對整個版型，
認出 **25 格**：

| 編號 | 法術 | 訊息 |
|---:|---|---|
| 5、11 | Detect Magic | `is affected` |
| 6、7、16、17 | Protection From Evil／Good | `is protected` |
| 8 | Resist Cold | `is cold-resistant` |
| 18 | Read Magic | `is affected` |
| 19 | Shield | `is shielded` |
| 22 | Find Traps | `is affected` |
| 24 | Resist Fire | `is fire resistant` |
| 25 | Silence, 15' Radius | `is silenced` |
| 29 | Detect Invisibility | `is affected` |
| 30、50、63 | Invisibility | `is invisible` |
| 31 | Knock | `Knock-Knock` |
| 33 | Ray of Enfeeblement | `is weakened` |
| 38 | Cause Blindness | `is blind` |
| 44 | Bestow Curse | `has been cursed!` |
| 45 | Blink | `is blinking` |
| 52、53 | Protection From Evil／Good, 10' Radius | `is protected` |
| 54 | Protection From Normal Missiles | `is protected` |
| 61 | （無名）| `is paralyzed` |

**要比對整個版型，不能只看「有沒有呼叫 08BCh」**：會算傷害的那幾支也呼叫
`08BCh`，只看呼叫會把它們一起收進來，然後傷害就消失了。測試同時釘住
「二十五格」與「魔法飛彈那幾支不在裡面」兩個方向。

加上逐支讀出來的三十四支處理常式（共 37 個編號，Fireball 與 Hold Person
各有兩個編號共用一支），六十七格裡**接得出來的有 62 格**。
數字由 `TestImplementedSpellCount` 釘住——改了實作沒改這裡就會紅。

## 解病術：拿掉效果，不掛效果

`2300h` 整支只是 `call 225Bh`。`225Bh` 逐個問「目標中了這個嗎」再拿掉：

```
2275  lcall 0100h:006Bh(目標, 22h)      ; 有沒有這個效果
228D  lcall 0100h:006Bh(目標, 2Bh)
22AB  lcall 0100h:002Ah(目標, 2Ch)      ; 拿掉
22C1  lcall 0100h:002Ah(目標, 1Fh)
22D1  lcall 0100h:006Bh(目標, 32h)
22EF  lcall 0100h:002Ah(目標, 39h)
```

所以 `0100h:006Bh` 是「有沒有這個效果」、`0100h:002Ah` 是「拿掉這個效果」。

### 解除類與施加類的效果碼互相對得上

| 施加 | 效果碼 | 解除 |
|---|---:|---|
| Cause Blindness（38，純泛型）| `21h` | Cure Blindness（`21E8h`）|
| Bestow Curse（44，純泛型）| `24h` | Remove Curse（`2508h`）|
| Cause Disease（40，`231Dh`）| `2Ch` | Cure Disease（`225Bh`）|

左邊的碼來自**參數表 `+0Ah`**，右邊來自**處理常式裡的字面值**，
兩條路各自解出來卻落在同一個碼上。測試把這三對釘住。
碼與 overlay-15 的名稱鏈對得上：**`2Ch` 是 Cause Disease、`32h` 是
Dreaded Mummy Disease、`1Fh` 是 Helpless**——解病術拿掉的正是那幾個病
以及它們造成的無助，兩份獨立的證據互相印證。

## `+9Fh` 是生物種類、`+6Ch` 是體型

四個互相獨立的使用點指向同一個讀法，每一個都是 `cmp` 一個字面值：

| 位置 | 比什麼 | 那一支在做什麼 |
|---|---|---|
| overlay-22 `2090h` | `+9Fh == 0` | Animate Dead 只對人類屍體 |
| overlay-22 `1927h` | `+9Fh == 0Eh` | Snake Charm 只收蛇那一族 |
| overlay-12 `015Dh` | `+9Fh == 4` | 對不死另外設 `DS:6780h` 的旗標 |
| overlay-22 `11DAh`／`174Bh` | `+9Fh > 1` 或 `+6Ch > 1` | Charm／Hold Person 判「算不算人」|

拿原版的 285-byte 記錄當正對照，值分得很乾淨：

| `+9Fh` | 出現的怪物 |
|---:|---|
| `0` | 4TH LVL FIGHTER、LEVEL 6 MU、SWORDSMAN、NOMAD、MACE、NORRIS THE GRAY… |
| `1` | KOBOLD、GOBLIN、ORC、BUGBEAR、OGRE |
| `2` | HILL GIANT、FIRE GIANT |
| `4` | SKELETON、ZOMBIE、WIGHT、WRAITH、SPECTRE、VAMPIRE |
| `7` | QUICKLINGS |
| `0Ah` | TROLL |
| `0Bh` | BASILISK、POISONOUS FROG、GIANT LIZARD |
| `0Ch` | STIRGE |
| `0Eh` | GIANT SNAKE、LARGE SCORPION、HUGE SCORPION |
| `11h` | MEDUSA、MINOTAUR |

`+6Ch` 是**兩個欄位擠在一個 byte 裡**，這一點有四個獨立的遮罩點作證：

| 位置 | 位元組 | 取的是 |
|---|---|---|
| overlay-10 `1D06h` | `and al, 7` | 低三位 |
| overlay-13 `1518h` | `and al, 7` | 低三位 |
| overlay-12 `1233h` | `and al, 7Fh` | 低七位 |
| overlay-32 `10B5h` | `and al, 7Fh` | 低七位 |
| overlay-13 `150Eh` | `cmp es:[di+6Ch], 80h ; ja` | 位元 7 |

低位是體型（`1` 與人同大、`2` 大型、`3` 巨大），位元 7 另外標著一批大塊頭
（BUGBEAR `81h`、OGRE／TROLL／巨人／MINOTAUR `82h`、GIANT SNAKE／
GIANT LIZARD `83h`）。overlay-32 就是 `0912h` 用來展開體型佔格的那一支
（spec 096），所以低位餵的是戰術盤上佔幾格。

Charm／Hold 比的是**整個 byte**，不是遮罩過的低位，所以熊地精雖然種類是 1
仍然免疫——這是原版的資料選擇，不是判斷寫錯。

## 依這一對接上的四支（2026-09-03）

## 力量那一組：`0100h:007Ah` 是「把力量往上調」

overlay-24 entry 18（`1158h`）收 `(目標, 新力量, 新百分位, var 回填位元組)`：

```
115e  cur    = 目標 +10h        ; 力量
1168  curPct = 目標 +16h        ; 特殊力量百分位
1172  新力量 <  cur                        → 不調
117a  新力量 == 12h 而且 新百分位 < curPct → 不調
11ae  走效果串列 +7Fh，找效果碼是 0Ch 或 26h 且節點 +3 小於 80h 的節點
```

**只往上調，不往下調**；而且只有新力量正好是 `12h`（十進位 18）時才比百分位

- 記錄的 `+10h` 是力量、`+16h` 是特殊力量百分位。能力值依序是
  `+10h`..`+15h`（力量、智力、睿智、敏捷、體質、魅力），與友誼術加在
  `+15h`（魅力）對得上。
- **`1293h` 寫進 `DS:47A6h` 的 `12h` 不是效果碼，是十進位的 18。**
  `DS:47A7h` 那張表（0、1、51、76、91、100）是百分位，正是 AD&D 的
  18/00、18/01、18/51、18/76、18/91 五段。
- 變大術真正掛的效果碼是 **`0Ch`**：參數表 `+0Ah` 與 `1331h` 的
  `mov al, 0Ch`（推給掛效果的 `0100h:0052h`）兩條路一致。
  編號 `3Bh` 掛的是 `26h`，同樣兩條路一致——而 `1158h` 認的正是這兩個碼。

## 挑目標：overlay-13 `1E09h`

`1E09h` 收（輸出結構的遠指標、`[bp+0Ah]`、旗標 `[bp+0Ch]`、法術編號 `[bp+0Eh]`），

`352Ch` 是那個互動介面（`Next Prev Manual`、`Range = `、`Target `、

**射程從裝備中的武器來**（`3563h..3598h`）：`[bp+12h]` 傳進來的射程若是
`FFh`，就去讀角色記錄 `+CCh` 那一格裝備中的物品、取它的型別，
查型別表的 `+0Ch` 再減一；0 與 `FFh` 都墊成 1（spec 065）。

挑目標的畫面上算了**兩個**值，`2A92h` 一個、`2AA7h` 一個：

### `261Bh` 算的是方向，不是距離

```
261b  x1 = 013Dh:006Bh(A) / y1 = 013Dh:0070h(A)
2643  x2 = 013Dh:006Bh(B) / y2 = 013Dh:0070h(B)
2659  n = 0
2671  while 0138h:0034h(x1, y1, x2, y2, n) == 0: n++
267f  回傳 n
```

`0138h:0034h` 是 overlay-31 entry 4（`0579h`）。它先把座標夾在
**0..31h × 0..18h**（50 × 25，就是戰場的大小），拿 `n` 索引 `DS:274Ah`
（X 位移）與 `DS:2753h`（Y 位移）兩張方向表算出 `(ax1, ay1)`，
然後測 `(x2, y2)` 在不在從那裡朝 `n` 展開的 **45 度楔形**裡：

```
5fe  x2 == ax1 且 y2 == ay1                  → 1
61f  n = 0：x2 >= ax1 時 y2 <= ay1 + (x2 − ax1) → 1
645          x2 <  ax1 時 y2 <= ay1 + (ax1 − x2) → 1
```

所以 `n` 是**第幾個方向**，`261Bh` 回傳的是目標相對施法者的方位。

### 距離是 `010Ah:00C5h`（overlay-25 `2591h`）

```
25e8  lcall 0138h:003Eh(…, DS:6674h, DS:6676h)   ; 建路徑
25fb  i = 1
2608  cell = ds:[6676h + i×3]
2614  les  ax, ds:[6517h + cell×4]               ; 那一格站著誰
261a  與目標比對，不同就 i++（上限 ds:6678h）
2641  al = ds:[6677h + i×3]
264b  idiv 2                                     ; ← 距離 ＝ 路徑成本 ÷ 2
```

**距離是「路徑成本除以二」**，路徑由 overlay-31 entry 6（`0912h`）建。
除以二說明成本是以半格為單位存的（斜走與直走不同價），這與盤面是斜投影
（spec 060）相符。同一支 `0912h` 也是怪物 AI 找落腳格用的那一支
（spec 096），所以移動、射程與 AI 三件事共用同一個成本模型。

### `0912h` 的成本從哪來：就是 `0419h`

```
933  lcall 013Dh:002Ah(…)            ; 展開施法者的體型（最多四格）
9e1  lcall 013Dh:002Ah(…)            ; 展開目標的體型
aab  call  0579h(srcX, srcY, tgtX, tgtY, 方向)   ; 先過方向楔形

```

`0419h` 就是 **TraceMovement**（spec 057），remake 早就實作了。它的成本
本來就以**半格**為單位（`limit := budget × 2 + 1`），所以 `2591h` 的

**所以距離 ＝ `TraceMovement(...).Cost ÷ 2`**，走不到就是打不到。

## 解除魔法（`2356h`，法術編號 `29h` 與 `2Eh` 共用）

沒有參數，進場先把 `DS:677Eh` 設成 1（範圍法術），施法者等級取自
`010Ah:00D4h(DS:6779h)`。外層是 `for i := 1 to DS:6B88h`（目標數），
每一輪都從 `DS:6B89h` 取同一個遠指標當目標——**逐位元組讀出來就是這樣，
沒有索引暫存器**（`C4 06 89 6B` 是絕對定址）。

內層沿著目標 `+7Fh` 的效果節點串列走（`+5` 是下一個）：

```
23be  節點 +3 >= 0FFh → 跳過                     ; 解不掉的效果
23cb  效果等級 = 節點 +3 的低四位  → DS:47A7h
23d7  施法者 > 效果：DS:47A6h = 50 + (施法者 − 效果) × 5
23fb  施法者 < 效果：DS:47A6h = 50 − (效果 − 施法者) × 2
2420  相等：        DS:47A6h = 50
2425  骰(1,100) <= DS:47A6h → 0100h:002Ah(節點, 節點 +0, 目標) 把它拿掉
```

所以**每一個效果各擲一次**，成功率以 50% 為基準，施法者高一級加 5、
低一級只扣 2——不對稱，對高階施法者有利。節點 `+3` 的低四位是**下這個效果
的人的等級**，`0FFh` 代表這個效果不吃解除魔法。

至少拿掉一個時印一段字（格式字串在 overlay-22 `234Ah`）並呼叫 `010Ah:00A2h`。

**remake 的接法**（2026-09-05）：`gamepack.EffectList` 是那條串列，
`DispelChance` 是上面那個不對稱的成功率，`EffectList.Dispel` 逐個擲。
戰鬥狀態把 `Asleep`／`HeldRounds`／`Charmed` 三個旗標換成同一條串列——
兩份真相會讓解除魔法解到空的。定身的剩餘回合數就是節點的持續（`+1..+2`），
回合邊界各減一、歸零摘掉；睡眠與魅惑的持續是 0，代表沒有回合計時。

外層那個「每一輪都從 `DS:6B89h` 取同一個遠指標」照著接成**只作用在一個目標**
——逐位元組讀出來就是這樣，不替原版補一個它沒有的索引。

```
211A    `+17h + 0..14h` = 0                ; 清空記憶法術陣列
2138    `+84h` > 7Fh → 0B2h，否則 0B3h      ; 士氣
215A    `+9Fh` = 4                         ; 生物種類改成不死
217C    生命值補到 `+32h`（最大值）
2199    掛效果碼 20h，參數是上面那個打包值
      印 "<名字> is animated"（overlay-22 `2037h`）
21C0    `+10Ch` = 1                        ; 狀態
```

`+72h` 的 6 與 `movement.go` 的 `AnimatedDeadMovementRate` 是同一個常數，
兩處獨立讀出來一致。

**remake 已接**：`tacticalState.animateDead`。屍體倒下時的佔格類別要另外
記著（`Footprint`），不然叫起來只能猜一個值；生命上限也另外記
（`MaxHitPoints`），因為原版補的是 `+32h` 不是「補滿現有的」。
「那一格站不站得住」那一道閘還沒接——屍體本來就在那一格上。

## 臭雲術（`1AF6h`，法術編號 `22h`）

它不是「對目標下效果」，是**在盤面上生一個活的雲團物件**，掛在 `DS:6CAFh`
起頭的單向串列上。節點 19 bytes（`5BBh:329h` 配的）：

| 位移 | 內容 |
|---|---|
| `+0`..`+3` | 施法者的記錄遠指標 |
| `+4`..`+7` | 下一個節點 |
| `+8`..`+0Bh` | 四格各自**原本的地形**（收雲時還原用）|
| `+0Ch`..`+0Fh` | 四格各自「蓋不蓋得住」的旗標 |
| `+10h`／`+11h` | 雲心的 X／Y（`DS:6CADh`／`DS:6CAEh`）|
| `+12h` | 這個施法者身上已經有幾團雲 |

生的時候先走一遍串列數自己的雲（比對 `DS:5CF0h`／`5CF2h`），接著
`010Ah:0052h(1, 等級 + 雲數 × 16, 等級, 28h, 施法者)`。

**雲的形狀是四格，一個乾淨的 2×2**：迴圈的索引是 **1..4**
（`0D67h` 設 1、`0E8Eh` 比 4），所以用到的是 `DS:28A7h` 的 `[1..4]` ＝
`08 02 03 04` ——雲心、東、東南、南。位移表 `DS:274Ah`／`DS:2753h` 九個方向
實測是 `00 01 01 01 00 FF FF FF 00`／`FF FF 00 01 01 01 00 FF 00`，
也就是 0 北、1 東北、2 東、3 東南、4 南、5 西南、6 西、7 西北、8 原地。
（`DS:28A7h` 的第 0 個 `00` 與第 5 個 `05` 都不在窗內。）
每一格問一次 `013Dh:041Dh(x, y, &格內, &地形)`，地形為 0 或
`DS:[2758h + 地形 × 4]` 是 `0FFh` 的就標成 0（雲蓋不到那一格）。

### 效果碼 `28h` 的處理常式在 overlay-12 `0CDEh`（2026-09-05）

雲不是「掛在人身上的效果」，但它仍然走同一條效果分派：建立時
`010Ah:0052h(1, 等級 + 雲數 × 16, 等級, 28h, 施法者)` 掛的就是代碼 `28h`。
它的處理常式簽章與別人相同（`f(模式, 節點, 記錄)`），開頭先把節點 `+3`
除以 16 取出「這是這個施法者的第幾團雲」，再沿 `DS:6CAFh` 找那一團：

```
0CE5  雲序號 = 節點 +3 ÷ 10h
0CFB  沿 DS:6CAFh 走（`+4` 是下一個）：
0D18    雲的 +0 == 這一筆角色記錄 而且 雲的 +12h == 雲序號 → 找到
0D4A  找不到 → 直接結束
0D53  找到（收尾那一路）：印 "The air clears a little..."（overlay-12 `0CC4h`）
0D70  走五格：方向 = DS:[28A7h + i]，dX = DS:[274Ah + 方向]、dY = DS:[2753h + 方向]
      格子座標 = 雲心（`+10h`／`+11h`）加上位移
0DCE  再走戰鬥員（數量 DS:6673h，步長 7）……
```

#### 收雲那一路怎麼還原地形（2026-09-08）

`0DCEh..0E94h` 是四格迴圈的內層。每一格先問「這一格站著人嗎」：

```
0DCE  n = ds:6673h                      ; 戰鬥員數量
0DE3  逐個 i = 1..n，步長 7：
0DEF    [i×7 + 6634h] | [i×7 + 6636h] 為零 → 跳過（這一格是空的）
0E0C    [i×7 + 6638h] == 雲格的 X ？
0E28    [i×7 + 6639h] == 雲格的 Y ？
0E31    兩個都對 → 有人（區域旗標 [bp-9] = 1）
0E3D  有人  → 戰術格 ds:6674h 的 +7 + y×32h + x 寫 1Fh
0E63  沒人  → 從節點 +8 起那四個 byte 取回**原本的地形**寫回去
0E8E  四格走完（[bp-0Bh] == 4）→ 把節點從 DS:6CAFh 的串列摘掉
```

所以節點 `+8`..`+0Bh` 那四格「原本的地形」是**收雲時**用的，而**站著人的
格子不還原**，改寫成類別 `1Fh`——那是「這一格有人佔著」的類別，與 spec 060
的 `17h`（空地）相對。這一段解釋了為什麼節點要記地形：雲散掉之後地形要回去，
但人還站在那裡的格子不能回去。

**另一半在 spec 121**：雲對站在裡面的人做什麼走的是**另一個代碼** `1Eh`
（參數表 `+0Ah`，處理常式 overlay-12 entry 29 `0A76h`），與這裡的 `28h` 是
兩套東西——`28h` 是雲物件自己，`1Eh` 是被燻的人身上的效果。

**節點 `+3` 在這個代碼上的用法與魅惑不同**：魅惑把高三位當旗標
（已套用／原陣營／施法者陣營），這裡高四位是雲的序號。同一個 byte
由各代碼自己解釋——與 spec 112 的「等級覆寫那一格被拿來塞兩個東西」同一招。

戰鬥結束時 overlay-08 `0000h` 沿 `+4` 把整條串列 `FreeMem(13h)` 放掉
（19 bytes，與建立時 `5BBh:329h` 配的大小相同），接著也放掉 `DS:6674h`
起的 `4E9h` bytes。

### 收雲那一路已經讀完了（2026-09-05）

`0DCE` 之後就是還原地形與重疊處理，整段讀完如下：

```
0DCE  掃 DS:6634h 那張表（筆數 DS:6673h，每筆 7 bytes：+0..+3 遠指標、
      +4 X、+5 Y）——這一格上有沒有別的物件
0E43  有 → 那一格的地形寫 1Fh
0E63  沒有 → 從節點 +7+i 取回原地形寫回去
      （地形表是 DS:6674h，位置 y × 32h + x，寫的是該筆的 +7）
0EFC  把節點從 DS:6CAFh 上摘掉並 FreeMem(13h)
0F0A  **再走一遍剩下的雲，把它們的四格重新蓋成 1Eh**
```

最後那一步就是重疊的處理方式：兩團雲共用的格子被前一步還原掉了，
不重蓋就會在另一團中間開一個洞。

這一支本身不對任何人造成傷害——它只管地形。**「站在雲裡會怎樣」與「誰來
呼叫這一支」後來都讀出來了，收在 spec 121**：前者是另一個代碼 `1Eh`，後者的
答案是**沒有人每回合呼叫**——`28h` 的節點到期被摘掉時，收尾那一下才叫它。
`1Fh` 那一組（`DS:6638h` 起、每筆 7 bytes）還沒讀是什麼物件。

remake 這一邊已經照上面接完了（spec 121）：`gamepack.CloudList` 有蓋、收、
還原、重疊重蓋，四格的座標由真的方向位移表算；被燻的人走 `1Eh`，雲自己走
`28h` 的節點，節點到期就散。
