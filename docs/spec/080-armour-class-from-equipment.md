# Spec 080：裝備算出來的護甲等級

狀態：READY（累加器五個槽、魔法盔甲壓制、敏捷項，七名預設人物的 `+111h`
與 `+112h` 逐一相符）。日期：2026-09-03。

## 為什麼需要它

戰鬥現在收得了尾，但六名戰士被六隻骷髏加六隻殭屍打垮（只放倒三隻）。
`cmd/pool-game` 的 `partyCombatStats` 回的是「沒有裝備」的角色——AC 用建角
基礎值、傷害是固定骰，盔甲與武器都不算數。原版那條鏈就是這裡。

## 誰算、算在哪

overlay-25 的 `0C17h` 起是「重算全部衍生值」：走物品鏈（`+C8h` 起、`+2Ah`
是 next），每件備妥（`+34h ≠ 0`）的物品做三件事——累加負重（spec 079）、
把物品填進 `+CCh + 類別 × 4` 的欄位槽（`0F07h` 呼叫 `01F8h`）、以及呼叫
`0281h` 累加護甲。

`0F16h` 那兩個 `lea` 決定了 `0281h` 的兩個輸出位置：

```
0F16h  lea di,[bp-0Dh]   push ss  push di   ; 累加器陣列（五個位元組）
0F1Bh  lea di,[bp-07h]   push ss  push di   ; 「穿著有加值的盔甲」旗標
0F20h  push cs  call 0281h
```

走完物品鏈之後（`0F35h` 起）結算：

```
0F35h  旗標 ≠ 0 時 累加器[3] = 0          ; 魔法盔甲壓掉護符戒指
0F8Dh  dx = 目前的 +111h（重設時等於 +A9h 的基礎 AC）
0F96h  ax = 累加器[4]
0F9Ah  ax < dx 時 累加器[4] = dx           ; 取兩者較大
0FA9h  +111h = 0
0FBBh  for i = 0..4: +111h += 累加器[i]
0FE1h  +112h = 累加器[4] + 累加器[3] + 累加器[2] − 2
```

內部 AC 是「60 減去檯面上的 AC」，所以數字越大越好，`0F9Ah` 取大者就是
「盔甲比裸身差就不穿」。

## 累加器的五個槽

`0281h` 依物品型別表（`DS:54E0h + 型別 × 16`）決定往哪個槽記。**型別記錄的
`+6` 最高位是開關**：`≤ 7Fh` 直接返回，這件物品與 AC 無關；否則 `v = +6 & 7Fh`
是它的 AC 值。

| 條件 | 動作 |
|---|---|
| 類別 = 1（盾） | 累加器[1] = `v + 加值` |
| `v = 0` 且類別 = 9 | 累加器[3] = max(累加器[3], 加值) |
| `v = 0` 且類別 ≠ 9 | 累加器[2] += 加值 |
| `v ≠ 0` | 累加器[4] = max(累加器[4], `v + 加值`) |

`v = 0` 的那兩支還會把物品的 `+33h` 加進角色的 `+101h`（豁免修正，spec 075）。

累加器[0] 不由 `0281h` 寫，它是**敏捷的 AC 調整**：七名預設人物的敏捷都是
18，而累加器算出來的內部 AC 一律少 4——AD&D 的敏捷 18 正好是 −4 AC，換成
內部值就是 +4。

## 魔法盔甲壓掉護符戒指

`0281h` 的第四支（`v ≠ 0`，`034Bh`）只有在真的抬高了累加器[4] 之後才往下走，
接著這五個位元組決定要不要立旗標：

```
0382h  les di,[bp+0Eh]                      ; 物品記錄
0385h  cmp byte ptr es:[di+32h], 0          ; 加值 > 0 ?
038Ah  jle 0399h
038Ch  cmp byte ptr [bp-02h], 2             ; 類別 = 2（盔甲）?
0390h  jne 0399h
0392h  les di,[bp+06h]                      ; 旗標
0395h  mov byte ptr es:[di], 1
```

也就是說：**有加值的類別 2 盔甲**（而且它是目前最好的那件）會立旗標，
結算時 `0F35h` 把護符戒指的槽整個清零。護腕（類別 77）與斗篷不是類別 2，
所以立不了旗標，它們的戒指照算——`chrdatd5`／`chrdatd6` 就是這樣。

規則書裡「魔法盔甲與護符戒指不疊加」這一條，原版是用類別 2 這個窄條件實作的，
不是用「身上有任何護甲」。

## 七名預設人物

| 記錄 | 備妥的護甲物品 | 累加器 | 旗標 | 算出 `+111h` | 實際 |
|---|---|---|:-:|---:|---:|
| `chrdatd1` | Shield +1、Plate Mail +3 | 2 + 60 | 立 | 66 | 66 |
| `chrdatd2` | Shield +2、Plate Mail +2 | 3 + 59 | 立 | 66 | 66 |
| `chrdatd3` | Shield +2、Plate Mail +2、Ring of Protection +1 | 3 + 59（戒指清零） | 立 | 66 | 66 |
| `chrdatd4` | Leather Armor +4 | 56 | 立 | 60 | 60 |
| `chrdatd5` | Bracers AC 3、Ring +3、Cloak of Displacement | 57 + 3 + 2 | 不立 | 66 | 66 |
| `chrdatd6` | Cloak、Ring +2、Bracers AC 3 | 57 + 2 + 2 | 不立 | 65 | 65 |
| `chrdatd7` | Shield、Leather Armor | 1 + 52 | 不立 | 57 | 57 |

`+112h` 同樣七筆相符（58、57、57、54、60、59、50）。`chrdatd3` 的 `+112h`
是 59 + 0 + 0 − 2 = 57，戒指沒有清零的話會算成 58——那個槽是同一條壓制規則
的第二個見證。

## `+112h` 是什麼

它把敏捷（累加器[0]）與盾（累加器[1]）排除在外，再減 2。AD&D 一版從背後
攻擊的規則正是「防禦方失去盾與敏捷加值，攻擊方 +2 命中」，兩邊逐項對得上，
所以 `+112h` 應該是**背擊時用的 AC**（強推論；還沒讀到戰鬥那邊的取用點）。

實作照算不照用：`ArmourClass.Rear` 存著，但戰鬥還沒有背擊判定，先不接。
