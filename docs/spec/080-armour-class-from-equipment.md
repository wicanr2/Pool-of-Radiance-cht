# Spec 080：裝備算出來的護甲等級

狀態：DRAFT（累加器的五個槽、敏捷項、以及六名預設人物逐一相符；第七名
`chrdatd3` 多出一點，成因未讀）。日期：2026-09-03。

## 為什麼需要它

戰鬥現在收得了尾，但六名戰士被六隻骷髏加六隻殭屍打垮（只放倒三隻）。
`cmd/pool-game` 的 `partyCombatStats` 回的是「沒有裝備」的角色——AC 用建角
基礎值、傷害是固定骰，盔甲與武器都不算數。原版那條鏈就是這裡。

## 誰算、算在哪

overlay-25 的 `0C17h` 起是「重算全部衍生值」：走物品鏈（`+C8h` 起、`+2Ah`
是 next），每件物品做三件事——累加負重（spec 079）、把備妥的物品填進
`+CCh + 類別 × 4` 的欄位槽、以及呼叫 `0281h` 累加護甲。

走完之後（`0F8Dh`）把累加器結算成內部 AC：

```
0F8Dh  dx = 目前的 +111h（重設時等於 +A9h 的基礎 AC）
0F96h  ax = 累加器[4]
0F9Ah  ax < dx 時 累加器[4] = dx        ; 取兩者較大
0FA9h  +111h = 0
0FBBh  for i = 0..4: +111h += 累加器[i]
0FE1h  +112h = 累加器[4] + 累加器[3] + 累加器[2] − 2
```

內部 AC 是「60 減去檯面上的 AC」，所以數字越大越好，`0F9Ah` 取大者就是
「盔甲比裸身差就不穿」。

## 累加器的五個槽

`0281h` 依物品型別表（`DS:54E0h + 型別 × 16`）決定往哪個槽記。**型別記錄的
`+6` 最高位是開關**：`≤ 7Fh` 直接返回，這件物品與 AC 無關；否則 `v = +6 & 7Fh`
是它的 AC 值。

| 條件 | 動作 |
|---|---|
| 類別 = 1（盾） | 累加器[1] = `v + 加值` |
| `v = 0` 且類別 = 9 | 累加器[3] = max(累加器[3], 加值) |
| `v = 0` 且類別 ≠ 9 | 累加器[2] += 加值 |
| `v ≠ 0` | 累加器[4] = max(累加器[4], `v + 加值`) |

`v = 0` 的那兩支還會把物品的 `+33h` 加進角色的 `+101h`（豁免修正，spec 075）。

累加器[0] 不由 `0281h` 寫，它是**敏捷的 AC 調整**：七名預設人物的敏捷都是
18，而算出來的內部 AC 一律少 4——AD&D 的敏捷 18 正好是 −4 AC，換成內部值
就是 +4。

## 七名預設人物

| 記錄 | 備妥的護甲物品 | 累加器 | 加敏捷 | 實際 `+111h` |
|---|---|---|---:|---:|
| `chrdatd1` | Shield +1、Plate Mail +3 | 2 + 60 | 66 | 66 |
| `chrdatd2` | Shield +2、Plate Mail +2 | 3 + 59 | 66 | 66 |
| `chrdatd3` | Shield +2、Plate Mail +2、Ring of Protection +1 | 3 + 1 + 59 | 67 | **66** |
| `chrdatd4` | Leather Armor +4 | 56 | 60 | 60 |
| `chrdatd5` | Bracers AC 3、Ring +3、Cloak of Displacement | 57 + 3 + 2 | 66 | 66 |
| `chrdatd6` | Cloak、Ring +2、Bracers AC 3 | 57 + 2 + 2 | 65 | 65 |
| `chrdatd7` | Shield、Leather Armor | 1 + 52 | 57 | 57 |

六筆逐一相符。`chrdatd3` 多出一點，而它與 `chrdatd5`／`chrdatd6` 的差別是
**它同時穿著魔法盔甲與護符戒指**——規則書裡那兩樣不疊加。原版在哪裡壓掉
它還沒讀出來，所以這一條是 DRAFT。

**在讀出來之前不要接進戰鬥**：AC 差一點就是命中率差 5%，而「六筆對、
一筆錯」在測試報表上會看起來像通過。
