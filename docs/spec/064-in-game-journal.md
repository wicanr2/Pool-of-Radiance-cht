# Spec 064：遊戲內《探險者手冊》

狀態：CONFORMED（99 條全部進遊戲、編號可跳、字型覆蓋率 0 缺字）。
日期：2026-09-03。

## 問題

原版把手冊印成紙本。遊戲畫面說「把它抄進手冊，成為線索報導 46」，玩家得離開
螢幕去翻書才讀得到那一條。三十多年後的玩家手上沒有那本書，這句話因此指向
一個不存在的地方——畫面說得出口，玩家做不到。

## 來源與內容

軟體世界代理當年的官方繁中說明書上冊，轉錄在
[`docs/reference/manual/journal-vol1.md`](../reference/manual/journal-vol1.md)
（spec 054）。`cmd/pool-journal-corpus` 把那份連續的 Markdown 切成
「編號 → 全文」，輸出 `internal/journal/zh-TW.json`：

| 章 | 條目 | 編號形式 | 數量 |
|---|---|---|---:|
| 第五章 探險者線索提示 | 線索報導 | 十進位 1..58 | 58 |
| 第六章 酒店傳言 | 傳言 | 十進位 1..23 | 23 |
| 第四章 新菲蘭城議會公告 | 公告字號 | 羅馬數字 LIX..CCXIV | 18 |

編號一律沿用說明書自己的編號，不自創——遊戲畫面報的就是那個編號。

## 切條的三個形狀

三種條目在原書裡長得不一樣，因此各有自己的辨識方式：`### 線索報導 N` 標題、
`**傳言 N**：…` 一段一條、`**公告字號 X**` 之後的段落。頁首（`## p.NN …`）
只記頁碼不進內文，並連同前後空行一起吃掉：一條條目常常跨頁，照字面分段會把
同一句話切成兩段。

## 閘門

- 三章的條目數必須是 58／23／18，線索與傳言的編號必須連續。少一條的症狀是
  玩家查不到那一條，而畫面上看起來像遊戲沒有這個功能，不像資料缺一筆。
- 遊戲文字引用的每一個 `ENTRY N` 都要查得到（測試拿
  `docs/audit/dos-ecl-text-inventory.json` 逐條核對）。
- 市政廳實跑派發的九個公告字號都要查得到（字號來自 spec 054 的既有 VM 測試）。
- 每一行都要排得進畫面：64 欄加上收尾標點的 2 格溢位額度。

## 畫面

`J` 開關（`ESC` 也可關）。`TAB` 換章，左右換條目，上下捲動，直接打編號再
`ENTER` 跳到那一條——遊戲報的是編號，玩家記得的也是編號，所以跳轉以編號為主，
不是逐條翻。公告的字號是羅馬數字，因此跳轉也收字母。

英文模式不開手冊：手冊本身是軟體世界的中譯，而英文模式用的內建字型沒有漢字，
畫出來會是一片空白，看起來像繪圖壞掉而不是沒有這個功能。狀態列直接說明要
`-lang zh`。

驗收畫面：`docs/screenshots/pool-remake-chinese-journal.png`（開啟）與
`pool-remake-chinese-journal-46.png`（打 46 跳到遊戲實際引用的那一條）。

## 附帶修好的三個顯示缺陷

接線時量出來的，都不是手冊獨有的問題：

1. **`wrapDisplay` 會吃掉半形詞之間的空白。** 原本的條件寫成「這個 token 寬度
   是 1」，但 token 是整個詞，於是 `PRESS RETURN OR BUTTON` 被接成
   `PRESSRETURNORBUTTON`。遊戲的事件文字在英文模式與尚未翻譯的句子都走這條
   路徑。判準改成「這個 token 的第一個字是半形」。
2. **收尾標點的溢位沒有上限。** 為了不讓「。」落在行首而允許多一格，連續的
   `。」』` 會一路把字推出畫面。現在只讓一個標點溢位。
3. **Big5 有兩個碼位的字取到了錯的那一個。** `x/text` 的 Big5 編碼器對
   包、港、偽、撐、煮等字回的是 F9xx–FExx 重複區的碼位，而倚天 `stdfont.15`
   只排到次常用字結尾（F9D5），於是這些常見字取不到字模，畫面上是空白方塊。
   改成用解碼器反向建表，並且漢字區先掃、符號區後掃——Big5 在符號區重複收了
   「十」（A2CC 與 A451）與「卅」，先掃符號區會讓最常見的字反而畫不出來。

另外兩類字型缺口以資料處理：轉錄稿裡 Big5 沒有碼位的異體字（敍、裏、却、着、
衞、羣…）在字型層對到標準字形，轉錄本身不動；字型沒有字模的排版符號
（`…`、`—`）在顯示前換成 `...`、`--`。

`cmd/pool-font-coverage`（`tools/font-coverage.sh`）拿實際的字型檔逐字問
「取得到字模嗎」，是這些修正的驗收：現在遊戲文字與手冊合計 0 缺字。
字型是第三方資產、不進 repo，所以這是手動跑的稽核工具，不是測試。

## 不做

- 不改轉錄稿去遷就字型；轉錄是文獻，字型能不能畫是顯示層的事。
- 不做「讀過的條目自動標記」——原書是要玩家自己在空白頁做記號，這個行為
  要先有原版證據再接。
- 不把附錄（金錢換算、法術表、裝備、武器表）放進來；那幾節是規則表，
  接進遊戲要配對應的規則實作，另案處理。
