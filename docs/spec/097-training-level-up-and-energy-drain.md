# Spec 097：經驗值、訓練所昇級、生命骰與能量吸取

狀態：CONFORMED（經驗值在記錄裡的位置與怎麼發、一隻怪物值多少、昇級的三道
閘門、經驗值上限、生命骰與體質加成的四張表、HP 的套用方式、能量吸取與
「恢復」共用的那對欄位）；DRAFT（種族／能力值的等級上限那一段、訓練所自己的
職業遮罩 `+550h` 從哪裡來、昇上法師等級之後的學新法術流程、
`+10Dh` 與狀態 1 的語意）。日期：2026-09-03。

## 經驗值在 `+0ACh`，是 32 bit

overlay-16 的訓練所把它拿來和門檻比：

```
2b91  les  ax, [di+4013h]              ; 門檻（class×38h + (level+1)×4）
2b9a  cmp  es:[di+0AEh], dx            ; 記錄的高位字
2ba3  cmp  es:[di+0ACh], ax            ; 記錄的低位字
2ba8  jbe  可以昇級
```

`+0ACh` 是低位字、`+0AEh` 是高位字，合起來是角色的**累積經驗值**。
門檻表本身見 spec 071。

## 昇級要過三道閘門

overlay-16 對職業索引 0..7 各走一次（`2A25h..2C60h`）：

| 閘門 | 碼 | 條件 |
|---|---|---|
| 種族／能力值上限 | `2AF0h..2B6Bh` | 不通過就整個職業跳過 |
| 經驗值夠 | `2B91h..2BA8h` | 經驗值 ≥ 升到下一級的門檻 |
| 還沒到職業上限 | `2BCDh..2BDEh` | 門檻既不是 0 也不是 `FFFFFFFF` 哨兵 |

`DS:466Eh` 非零時第二道閘門被略過（`2BAAh` 的 `cmp byte ptr ds:466Eh, 0`），
這個旗標的來源沒讀。

## 訓練所會把經驗值砍到上限

同一個迴圈順便算「升**兩**級所需的門檻減一」，取各職業的最小值；
迴圈結束後若那個值大於零，就寫回 `+0ACh`：

```
2c08  les  ax, [di+4013h]              ; 升兩級的門檻
2c49  sub  ax, 1 / sbb dx, 0
2c79  mov  es:[di+0ACh], ax            ; 經驗值被砍到這裡
```

所以在原版裡**訓練之後不可能一次留著兩級份的經驗值**。這不是防呆，是規則：
沒有它，隊伍可以囤經驗值然後連升數級。

## 職業分類遮罩 `DS:5F2h`

八個職業各一個 byte，內容是**分類**位元，不是職業編號：

| 索引 | 職業 | `5F2h` | 位元 |
|---:|---|---:|---|
| 0 | 牧師 | `02` | 神職 |
| 1 | 德魯伊 | `02` | 神職 |
| 2 | 戰士 | `08` | 戰士 |
| 3 | 聖武士 | `0A` | 戰士＋神職 |
| 4 | 遊俠 | `0A` | 戰士＋神職 |
| 5 | 法師 | `01` | 施法 |
| 6 | 賊 | `04` | 賊 |
| 7 | 武僧 | `06` | 神職＋賊 |

位元是 1 施法、2 神職、4 賊、8 戰士。昇級迴圈拿它和「這次要訓練哪一類」
的遮罩作 `and`，非零才升那個職業（`2EE0h` 的 `mov al,[di+5F2h]; and al,[bp-0Ch]`）。
訓練所自己也有一個遮罩（`ds:4937h` 指到的結構的 `+550h`），決定它收哪幾類。

**索引 1、3、4、7 在 Pool of Radiance 走不到**：經驗值表對它們沒有進度
（spec 071），建角也只給牧師／戰士／法師／賊與其複合。表裡有值是引擎帶著的
AD&D 資料，不是這一作的內容。

## 生命骰：兩張表加一個第一級的地板

`4209h` 收（職業分類遮罩、角色記錄），對每個「有等級且分類對得上」的職業擲一次：

```
4244  mov  al, [di+8CAh]     ; 骰子數
424f  mov  al, [di+8D2h]     ; 骰子面數
4254  lcall 0100h:0048h      ; Roll(骰子數, 面數)
4265  cmp  byte ptr es:[di+96h], 1     ; 這個職業目前是第 1 級嗎
4273  mov  al, [di+8D2h] / shl / idiv 3 ; 地板 ＝ 面數 × 2 ÷ 3
428a  jge  不用墊
42a0  mov  [bp-2], al        ; 擲出來低於地板就墊到地板
```

| 索引 | 職業 | `8CAh` 骰子數 | `8D2h` 面數 | 生命骰 |
|---:|---|---:|---:|---|
| 0 | 牧師 | 1 | 8 | 1d8 |
| 1 | 德魯伊 | 1 | 8 | 1d8 |
| 2 | 戰士 | 1 | 10 | 1d10 |
| 3 | 聖武士 | 1 | 10 | 1d10 |
| 4 | 遊俠 | 2 | 8 | 2d8 |
| 5 | 法師 | 1 | 4 | 1d4 |
| 6 | 賊 | 1 | 6 | 1d6 |
| 7 | 武僧 | 2 | 4 | 2d4 |

四個走得到的職業與 AD&D 一版逐項相同，另外四個也是。

**地板只在職業目前是第 1 級時生效**，也就是建角寫下第一級的那一次；
訓練所的昇級是先把 `+96h` 加一再擲，所以到不了這一段。d8 的地板是 5、
d10 是 6、d4 是 2、d6 是 4。

## 體質加成 `DS:4006h`

`3F01h` 對每個有等級的職業各加一次體質加成（記錄 `+14h` 是體質）：

```
3f39  mov  al, [di+4006h]              ; di ＝ 體質
3f43  cmp  byte ptr es:[di+14h], 10h   ; 體質 > 16
3f4d  cmp  byte ptr es:[di+2Fh], 2     ; 而且職業碼正好是 2（純戰士）
3f54  inc  byte ptr [bp-2]
3f5a  cmp  byte ptr es:[di+14h], 11h   ; 體質 > 17 再加一
```

| 體質 | 3 | 4..6 | 7..14 | 15 | 16 | 17 | 18 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 加成 | −2 | −1 | 0 | +1 | +2 | +2 | +2 |
| 純戰士另加 | | | | | | +1 | +2 |

與 AD&D 一版相同。**「純戰士」比的是 `+2Fh` 的複合職業碼等於 2**，
所以戰士／賊（碼 14）拿不到 17、18 的額外加成——照原版接，不照規則書補。

加成是「每個有等級的職業各加一次」，呼叫端再除以職業數，所以淨結果是
每次昇級拿滿一份加成。

## HP 怎麼加上去

`2F80h..3027h`，`職業數` 是這個角色有等級的職業數：

```
擲出來    = 4209h(分類遮罩, 記錄)
先寫 +0B1h：gain = 擲出來 ÷ 職業數；為 0 就當 1；+0B1h += gain
再算實際的：gain = (擲出來 + 3F01h(記錄)) ÷ 職業數；小於 1 就當 1
受傷量    = +32h − +11Bh
+32h     += gain
+11Bh     = +32h − 受傷量
```

兩件事值得記下來：`+0B1h` 收的是**沒有體質加成**的那一份（能量吸取要用它），
而 HP 是**保留受傷量**加上去的，不是治好。除法都是有號整數除法，往零取整。

## `+74h`／`+75h` 是能量吸取的欠帳，不是昇級用的

overlay-12 `21C4h..2286h` 是被吸取的那一段，引數是（次數、角色記錄）：

```
21df  cmp  byte ptr es:[di+10Ch], 8    ; 已經是那個狀態就不再吸
21ed  inc  byte ptr es:[di+74h]        ; 欠一級
225f  dec  byte ptr es:[di+0B1h]
2272  dec  byte ptr es:[di+11Bh]       ; 每點 HP 扣一次
227a  inc  byte ptr es:[di+75h]        ; 欠的 HP 累加
2289  cmp  byte ptr es:[di+73h], 2     ; 最高職業等級掉到 1 以下另走一條
```

還回來的是 **Restoration**（法術編號 56，overlay-22 `2C01h`，spec 073）：

```
2c16  cmp  byte ptr es:[di+74h], 0     ; 沒欠就整支直接返回
2c35  idiv cx                          ; gain = +75h ÷ +74h
2c40  add  al, es:[di+32h]
2c4a  add  al, es:[di+11Bh]
2c55  add  al, es:[di+0B1h]
2c60  sub  al, es:[di+75h]
2c67  dec  byte ptr es:[di+74h]
```

它接著挑一個職業把 `+96h` 加一，挑法是**下一級門檻最小**的那個，
再把 `+0ACh` 補到那個門檻，最後印出「is restored」。

還帳那一段寫成 `gamepack.Restore(欠的等級, 欠的 HP)`，帶單元測試（連還三次
要把欠帳清光、還回來的總和等於原本欠的數）。

**已接進遊戲**（2026-09-05）：欠帳那對欄位進了存檔模型
（`save.Character.DrainedLevels`／`DrainedHitPoints`，`omitempty`），
恢復術（法術編號 56）施出來就呼叫 `Restore` 還一級。**吸取的來源還沒有**
——那要等特殊攻擊那一批接上來，所以現在一律沒欠帳。沒欠帳時什麼都不做
正是原版的行為（`2C16h` 的 `cmp byte ptr es:[di+74h], 0` 直接返回），
不是「還沒接」。

訓練所的昇級迴圈（`2EF9h..2F24h`）也會動這對欄位，但**只扣不給**——
昇級時若身上還欠著吸取的等級，那一級抵掉欠帳，不另外加 HP。

## 經驗值怎麼發

戰鬥結束由 overlay-05 走三步：entry 2（code `0000h`）算總額、
entry 3（code `033Ah`，stub `002Fh`）發下去。

### 一隻怪物值多少

`00C0h..00F4h`：

```
c3  mov al, es:[di+0B1h]      ; 這一隻擲出來的生命值
cf  mov al, es:[di+0BAh]      ; 每點生命值加多少
d6  imul dx
e0  mov ax, es:[di+0B8h]      ; 基礎值（word）
e7  add / adc 累加
```

也就是 **`+0B8h` ＋ `+0BAh` × 生命值**，AD&D 一版的算法。逐筆對得上：

| 怪物 | `+0B8h` | `+0BAh` | 生命值 | 經驗值 |
|---|---:|---:|---:|---:|
| KOBOLD | 5 | 1 | 3 | 8 |
| ORC | 10 | 1 | 5 | 15 |
| OGRE | 90 | 5 | 21 | 195 |
| SPECTRE | 1650 | 10 | 38 | 2030 |

同一個迴圈把敵方的七種貨幣（`+88h` 起）累加到 `DS:6752h` 起的全域，
那是戰利品，不是經驗值。

`+0B1h` 在活著的戰鬥員身上是牠擲出來的生命值。**樣板記錄裡不是每一筆都填了**
（HOBGOBLIN 是 0，而 `+32h` 是 6），所以算的時候要用實際生命值。

### 除以分的人數

`0308h`：

```
308  mov al, ds:829Bh                 ; 沒資格分的人數
313  mov ax, es:[di+67Ch]             ; 隊伍人數
318  sub ax, dx
325  lcall 05BBh:0294h                ; 總額 ÷ 差
```

除數是**有資格分的人數**，不是隊伍人數。沒資格的是 `+10Dh` 為 0 或狀態為 1 的
成員（`05B3h..05C9h` 數的就是這兩種），兩個欄位的語意都還沒閉合。

### 每個人再依職業調整

`033Ah` 走過隊伍鏈，對每個 `+10Dh` 非零且狀態不是 1 的成員：

| 複合職業碼 `+2Fh` | 條件 | 拿到 |
|---|---|---|
| 0 牧師 | 睿智 `+12h` > 15 | 份額 ＋ 十分之一 |
| 2 戰士 | 力量 `+10h` > 15 | 份額 ＋ 十分之一 |
| 5 法師 | 智力 `+11h` > 15 | 份額 ＋ 十分之一 |
| 6 賊 | 敏捷 `+13h` > 15 | 份額 ＋ 十分之一 |
| 8、10..14、16 | 兩職業 | 份額 ÷ 2 |
| 9、15 | 三職業 | 份額 ÷ 3 |
| 其他 | | 份額 |

原版寫成 if / else if 的鏈，所以**複合職業拿不到主屬性加成**。
這是 AD&D 的主屬性 10% 加成，四個職業各看自己的主屬性。

## 已被推翻的斷言

spec 071 曾把 overlay-22 `2C6Bh..2D8Fh` 記成「昇級常式」。那一段是
Restoration 的職業挑選迴圈：它一次都沒有讀角色的經驗值，比的是門檻彼此的大小。
真正由經驗值驅動的昇級在 overlay-16 的訓練所。同一處也把 `+0ACh` 記成
「下一級的門檻」，實際上它是累積經驗值本身。
