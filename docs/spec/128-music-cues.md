# Spec 128：配樂——素材、派曲的形狀，以及界線在哪

狀態：CONFORMED（DOS 版沒有音樂、C64 版驅動的結構與三支包裝、Amiga 模組的
六首 subsong 與渲染的可重現性）；**REMAKE-OWNED**（哪一個情境配哪一首）。
日期：2026-09-06。

## 一句話

**原版 DOS 版沒有音樂**，所以這一層沒有 DOS 對照可比。曲子取自 Amiga 版，
情境的形狀取自 C64 版驅動的三支包裝，而「哪一首配哪個情境」是 remake 自己
決定的——這三件事的證據等級不同，不要在轉述時混成一句「照原版接的」。

## 三個平台各有什麼

| 平台 | 音樂 | 本機有沒有 | 證據 |
|---|---|---|---|
| DOS 1988 | **沒有**，只有 PC 喇叭 | 有 ZIP | **一手**：`Pool of Radiance (1988).zip` 全掃沒有音樂檔 |
| C64 1988 | **有**：`MUSIC`（$4000）＋ `SOUNDFX`／`MDRIVER`（$BA00）| 有 8 面 `.d64` | **一手**：磁碟目錄與檔案位元組 |
| Amiga 1990 | **有**：Wally Beben，6 首 subsong | 只有音樂 rip，**沒有遊戲** | **一手**（音樂）／**二手**（作曲者著錄） |

C64 那八面是**破解版**：`INIT` 裡有 `POOL OF RADIANCE WAS RIPPED BY S.C.I.`、
加了 code wheel 略過與 `PLAY GAME`／`DEMO` 選單。讀驅動與呼叫結構不受影響
（那些是原版的碼），但**不要拿它當「原版載入順序」的證據**。

## C64 版的音樂是怎麼派的

```
LIBRARY $1FA2  JSR $BA00        ; 驅動的每格 tick
               JMP $EA31        ; 接回 KERNAL 的 IRQ 收尾
```

所以 `$BA00` 是 IRQ tick，不是「放第 N 首」。真正的入口是 `$BA03 → $BBF9`：

```
BBF9  LDY #$04 ; STY $BD79      ; 四個聲部
BBFE  LDY $BA07 → $BA06
BC04  JSR $BC59                 ; $BA08..$BA0F → 零頁 $B2..$B9
BC07  ASL A ; STA $BD78 ; ASL A ; CLC ; ADC $BD78   ; **A × 6**
BC11  LDA ($B8),Y …             ; 每首三個 word，加上基底變成絕對位址
```

**曲號在 A**，每首三個聲部指標，資料基底在 `$B8/$B9`（由 `$BA0E/$BA0F` 帶進來）。

全遊戲只有**四處** `JMP $BA03`，都是薄包裝：

| 檔案 | 位址 | 做什麼 |
|---|---|---|
| `INIT` | `$154A` | 基底設 `$C400` 再放 A |
| `INIT` | `$1557` | 基底設 `$BD7B` 再放 A（`$BD7B` 在驅動自己的空間裡＝音效庫）|
| `DUNGEON` | `$19BB` | 直接放 A |
| `COMBAT` | `$2A67` | 直接放 A |

`POST.COM`（八面都有）只呼叫 `$1557` 那一支，也就是只用音效庫。

**所以原版有音樂的情境是三個：開機／標題、地圖、戰鬥。** 這就是
`internal/music` 那三個 `Cue` 的來源。

## Amiga 的素材

ExoticA／UnExoticA 著錄：`Game/Beben_Wally/Pool_of_Radiance.lha`，
內含 `wb.Pool_of_Radiance` **75446 bytes**，格式「Wally Beben」，Don Adan 的 disk rip。
下載到的檔案大小與著錄相同；`tools/build-amiga-music.sh` 每次都重驗這個數字。

模組開頭是 68000 機器碼（`60 00 08 2E` = `BRA.W`、`48 E7 FF FE` =
`MOVEM.L D0-D7/A0-A6,-(SP)`）——播放器連資料，要 UADE 才放得出來。
UADE 2.13 讀出 `playername: Wally Beben`、`There are 6 subsongs in range [1, 6]`。

六首逐首量過（解出 PCM 之後算的，不是聽的）：

| subsong | 長度 | peak | RMS | 非靜音 |
|---:|---:|---:|---:|---:|
| 1 | 240.0s（**截斷**，會循環）| −0.2 dBFS | −13.3 dBFS | 95.4% |
| 2 | 7.7s | −0.3 | −14.3 | 90.9% |
| 3 | 7.7s | −0.3 | −15.2 | 87.2% |
| 4 | 15.4s | −3.7 | −14.4 | 96.7% |
| 5 | 7.7s | −1.8 | −14.5 | 88.1% |
| 6 | 153.7s（自然結束）| −0.2 | −13.8 | 96.6% |

六個 md5 各不相同——2／3／5 長度一樣但內容不同，不是同一首重複。

**渲染是可重現的**：同一份模組、同一顆 image 跑兩次，六個 WAV **逐位元組相同**。
這是對拍的第一關；沒有這一關，之後任何「音訊對得上」的說法都沒有基準。

## 哪一首配哪個情境——**這一格是 remake 自己決定的**

| 情境 | subsong | 理由 |
|---|---:|---|
| 標題 | 1 | 六首裡唯一夠長又會循環的，音量也最飽 |
| 地圖 | 6 | 第二長的一首 |
| 戰鬥 | 4 | 四首短曲裡最長，也是唯一峰值低於 −3 dBFS 的 |

**不能核對**：Amiga 版的遊戲程式不在手上。要把這一格升級成 CONFORMED，
需要 Amiga 版的磁碟映像，找出它呼叫播放器 init 時傳的 subsong 編號與呼叫點——
與上面 C64 那一節做的是同一件事。在那之前這張表就是 remake 的選擇，
規格與程式註解、發行包的 `README-配樂.md` 都要這樣寫。

## 派曲的規則

「同一個情境不重放」——那不是最佳化，是原版的行為（C64 的派曲在比對曲號之後
才換）。少了它，每次重新派曲都會把曲子從頭播起，在地圖上走幾步就聽得出來。

## 散布界線

音訊是第三方著作權（Wally Beben，1990 U.S. Gold／S.S.I.）。

- **不進 repo**：`.gitignore` 擋 `*.ogg`、`Pool_of_Radiance.lha`、
  `wb.Pool_of_Radiance`，`workplace/` 與 `dist-all/` 本來就整個排除。
- **可散布的 `patch` 發行包不帶**，玩家拿到的是沒有音樂的版本，遊戲照常跑。
- **本機的 `full-local` 發行包才放**，並附 `README-配樂.md` 寫明不要散布。
