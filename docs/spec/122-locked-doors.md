# Spec 122：鎖住的門（`Bash`／`Pick`／`Knock`）

狀態：CONFORMED（門的狀態查詢、三個選項各自的閘門與判定、成功之後怎麼寫回
GEO、力量開門的完整表、那三個 byte 的全部讀寫點）；DRAFT（`DS:6CD2h`／
`6CD3h`／`6CD4h` 是誰設回 1 的——範圍已縮到 overlay-11 `0327h`／overlay-14
`07C2h` 那兩處傳址呼叫、
`DS:495Bh` 與 `[4937h]+592h` 那兩道前置的語意、`+10Ch` 的語意）。
日期：2026-09-05。

## 為什麼要讀這一支

`CanMoveDungeonWrapped` 早就照旗標擋人（1 放行、2／3 擋住），
`UnlockDoorWrapped` 也早就會兩邊一起改——**缺的是「什麼時候該改」**。
先前的盤點只量到「鎖住的門有幾道」（GEO2/9 有 29 道、GEO4/2 19 道……），
沒有規則就只能一直擋著。

入口是 **overlay-14 `0DB7h`**。找它的方法是掃字串：整包三十八支 overlay 裡
和門有關的字面只有這一組，就在 `0D96h`：

```
0D96  04 "Bash"
0D9B  05 " Pick"
0DA1  06 " Knock"
0DA8  05 " Exit"
0DAE  08 "Locked. "
```

## 門有三種狀態

`0DEBh` 用**目前站的格子與朝向**問一支：

```
0DDF  push ds:6A0Bh      ; X
0DE2  push ds:6A0Ch      ; Y
0DE5  push ds:6A0Dh      ; 朝向
0DEB  lcall 0131:0039
```

`0131h` 是 overlay-30（spec 109），stub `39h` → entry `(39h − 20h) ÷ 5 = 5`，
程式碼 `0358h`。那一支先把 X／Y **繞回 0..15**（`0383h`..`03AAh`：大於 15 變 0、
小於 0 變 15），所以門的查詢和移動走的是同一套 wrap。回傳值：

| 值 | 意思 | `0DB7h` 怎麼做 |
|---:|---|---|
| 1 | 沒鎖 | 直接放行 |
| 2 | 鎖住 | 出 `Locked.` 選單 |
| 3 | 閂住／撬不開 | 走 `0F3Eh`（另一組同形的碼）|

**這順帶解掉 spec 012 掛著的 `6A0Bh`／`6A0Ch` 用途**：它們就是目前格子的
X／Y，`6A0Dh` 是朝向。

## 選單怎麼組

四個選項不是固定的，各自有閘門（`0E06h`..`0EBFh`）：

| 選項 | 出現條件 |
|---|---|
| `Bash` | `DS:6CD2h != 0` |
| `Pick` | `DS:6CD3h != 0` **且** `0247h(6)` 為真 |
| `Knock` | `DS:6CD4h != 0` **且** `0614h(1Fh)` 為真 |
| `Exit` | 一律有 |

`0247h(索引)` 沿隊伍串列（`DS:5CF4h` 起、`+104h` 接下一個）看有沒有人的
`[+96h + 索引]` 非零。`+96h` 是職業等級陣列的基底（spec 063），索引 6 就是
`+9Ch` ＝ **賊等級**——所以 `Pick` 只在隊上有賊時出現。
`0614h(1Fh)` 同樣沿串列找**記著法術 `1Fh`（敲門術）的人**，回傳那個人的遠指標。

選單只剩 `Exit` 時（`0EC5h` 比對字串）不出選單，直接呼叫 `0000h(X, Y, 朝向)`。

## `Bash`：AD&D 的力量開門表

`02A1h` 沿隊伍串列走，**每個人各試一次**，任何一個成功就算開了
（`[bp-6]` 一被立起來迴圈就停）。判定分兩張表，看門是狀態 2 還是 3。

### 狀態 2（一般鎖住）——`03C9h`

| 力量 `+10h` | 百分位 `+16h` | 成功條件 |
|---:|---:|---|
| 3..7 | — | `Roll(1,6) == 1` |
| 8..15 | — | `Roll(1,6) <= 2` |
| 16..17 | — | `Roll(1,6) <= 3` |
| 18 | 0..50 | `Roll(1,6) <= 3` |
| 18 | 51..99 | `Roll(1,6) <= 4` |
| 18 | 100 | `Roll(1,6) <= 5` |

**與 AD&D 一版的 Open Doors 欄逐格相同**（18/51-75、18/76-90、18/91-99
在書上都是 4，這裡合成一條 51..99，結果一樣）。

> 19 以上在這張表裡**沒有分支**——力量被力量術推到 19 的人碰到狀態 2 的門
> 會直接掉到迴圈尾。照碼記著，不補。

### 狀態 3（閂住／撬不開）——`02ECh`

| 力量 | 百分位 | 成功條件 |
|---:|---:|---|
| 18 | 91..99 | `Roll(1,6) == 1` |
| 18 | 100 | `Roll(1,6) <= 2` |
| 18 | 其他 | 不可能，並且 `DS:6CD2h = 0` |
| 19、20 | — | `Roll(1,6) <= 3` |
| 21、22 | — | `Roll(1,6) <= 4` |
| 23 | — | `Roll(1,6) <= 5` |
| 24 | — | **`Roll(1,8)`** `<= 7` |
| 25 | — | 一定成功 |
| 其他 | — | 不可能，並且 `DS:6CD2h = 0` |

這是 AD&D 那張表**括號裡**的數字（強行打開鎖住／閂住／魔法定住的門）。
24 換成 `1d8` 是因為 `1d6` 表達不了 7。

`DS:6CD2h = 0` 是在**迴圈內**設的，所以隊上只要有一個力量不在表內的人，
`Bash` 下次就不會出現在選單上。誰把它設回 1 還沒讀到（**不是 ECL**，見
〈還沒讀〉）——這條先照碼記著。

## `Pick`：賊的開鎖技能，一扇門只能試一次

`0509h` 也沿隊伍串列走：

```
0536  al = Roll(1, 100)
0544  al > es:[di+78h] → 換下一個      ; +78h 是開鎖百分比（spec 095）
054D  es:[di+10Ch] != 0 → 換下一個
0555  成功
056B  DS:6CD3h = 0                      ; **不論成敗**
```

`056Bh` 在迴圈外而且無條件，所以 **`Pick` 一扇門只出現一次**：試過就消失。
`+10Ch` 的語意還沒閉合（同一個欄位在 spec 062 的回合迴圈裡也被讀）。

## `Knock`：一定成功，吃掉一格記憶

`0669h` 不擲骰：

```
0673  持有者 = 0614h(1Fh)               ; 誰記著敲門術
067C  沒有人 → 回 0
068E  槽號 = 05D1h(持有者, 1Fh)
0698  持有者[+17h + 槽號] = 0           ; 那一格記憶用掉了
069D  回 1
```

`+17h` 是記憶陣列的基底（spec 070：原版一律用 `es:[di+17h]` 加索引，
不是 `+1Fh`）。

## 成功之後：兩邊一起改

`04AEh`（`Bash`）與 `0576h`（`Pick`）**逐位元組相同**：

```
04AE  0112h(X, Y, 朝向)                              ; 這一邊
04BE  0112h(X + DS:274Ah[朝向],
            Y + DS:2753h[朝向],
            (朝向 + 4) mod 8)                        ; 對面那一格的反向
```

`DS:274Ah`／`DS:2753h` 就是九方向的位移表（spec 121 的雲也用同一張）。
`0112h` 先把 X／Y 夾在 0..15，**超出就整支不做**——注意它是**夾不是繞**，
而呼叫端算對面那一格時是直接加位移，所以貼著邊界的門只會改到自己這一邊。

共用 engine 的 `UnlockDoorWrapped` 做的就是這件事（兩邊一起、寫 detail 1），
差別只在它用 `WrapCoordinate` 繞回去而原版在這裡是夾。**貼邊的門會不會有
差異還沒實測**，先記著。

## 誰寫 `6CD2h`／`6CD3h`／`6CD4h`

**這三個不是 ECL 變數。** `cmd/pool-ecl-memory-audit -addresses 6CD2,6CD3,6CD4`
掃八個 DAX 全部區塊，三個位址一筆引用都沒有；而 `cmd/pool-disp-scan` 分開掃
兩種定址形狀（`mod=10` 的 `[基底+disp16]` 是 ECL 變數在引擎側的樣子，
`mod=00 rm=110` 的 `[disp16]` 是 DS 段全域），結果一面倒：

| 位址 | `[disp16]` 絕對 | ECL 引用 |
|---|---:|---:|
| `6CD2h` | 6 筆（含寫入） | 0 |
| `6CD3h` | 4 筆（含寫入） | 0 |
| `6CD4h` | 2 筆 | 0 |
| `6DD5h`（對照組，真的 ECL 變數） | **0** | 18 |

數值落在 spec 106 的 class 1 窗（`6B00h..6EFFh`）裡只是巧合——**判準是
overlay 怎麼定址它，不是數值範圍。**

掃出來的每一處都在 **overlay-14**（`0DB7h` 那一支自己所在的那顆），
另有一處在 overlay-11：

| 位置 | 指令 | 做什麼 |
|---|---|---|
| overlay-14 `032Ch`、`03B1h` | `mov byte [6CD2h], 0` | `02A1h` 的 `Bash` 迴圈內清 0 |
| overlay-14 `055Bh`、`1057h` | `mov byte [6CD3h], 0` | `Pick` 那一側清 0 |
| overlay-14 `0DFAh`、`0E14h`、`0E4Eh` | `cmp byte [6CDxh], 0` | `0DB7h` 選單的三道閘門 |
| overlay-14 `0F3Ah`、`0F54h`、`0F8Eh` | `cmp byte [6CDxh], 0` | `0F3Eh` 那份同形碼的同三道 |
| overlay-11 `0327h`、overlay-14 `07C2h` | `mov di, 6CD2h` ＋ `push ds` ＋ `push di` | **把位址整個傳出去** |

**沒有任何一處寫 1。** 三個位址的絕對定址寫入全部是寫 0，所以「設回 1」
不可能是用絕對定址做的——最後那一列的 `push ds; push di` 是唯一還沒追的
路：位址被推上疊傳給別的函式，那裡才是重設點（很可能是整塊初始化或載入）。
**這是下一步該追的，不是再掃這三個位址。**

> 位址怎麼來的：`dos-ovr-manifest.json` 的 `executable_file_offset` 是
> START.EXE 裡的 stub 位置，不是 `GAME.OVR` 的偏移，不能拿來反查。改用
> `code_bytes` ＋ `relocation_bytes` 依 index 累加，再減掉固定的 `15h`
> 檔頭差。校正值有三個獨立佐證：spec 125 已知的四條 `[4937h]+5AAh = 1`
> 正好落在 overlay-14、本節的三道閘門落在 `0DB7h` 之後、同形碼那三道落在
> `0F3Eh` 之前四個位元組。

## 還沒讀

- `DS:6CD2h`／`6CD3h`／`6CD4h` 誰設回 1（換格子時？換圖時？）。
  沒有這一段，「一扇門只能撬一次」的範圍就界定不了。
  **已排除 ECL**：`cmd/pool-ecl-memory-audit -addresses 6CD2,6CD3,6CD4` 掃八個
  DAX 全部區塊，三個位址**一筆引用都沒有**（工具接受了這三個 target，同一次
  執行對 `6DD5h` 掃得出 18 筆，所以這個零是真的零不是儀器沒開）。
  範圍已經縮到剩一條路，見上一節〈誰寫〉：所有絕對定址的寫入都是寫 0，
  唯一還沒追的是那兩處把位址推上疊傳出去的呼叫。
- `0DB7h` 開頭那兩道前置：`DS:495Bh == 1`、`[4937h] + 592h` 的 word 小於 `FFh`。
- `0F3Eh` 起那一份同形的碼——字串引用是同一組，狀態 3 走它。
  兩份的差別還沒逐行比。
- `+10Ch`（`Pick` 那道額外條件）。
## remake 這一側

| 東西 | 對應原版 |
|---|---|
| `gamepack.ForceDoorRoll(狀態, 力量, 百分位)` | `02ECh`／`03C9h` 兩張表 |
| `gamepack.BashDoor` | `02A1h` 的整隊迴圈與 `DS:6CD2h` |
| `gamepack.PickLockOpens` | `0536h` 的 `Roll(1,100) <= [+78h]` |
| `cmd/pool-game/door.go` 的 `doorMenu` | `0DB7h` 的選單與三道閘門 |
| `openDoor` → engine `UnlockDoorWrapped` | `04AEh` 的兩次 `0112h` |

`doorMenu` **刻意不用 `cellMenuOptions`**：那一條的選擇要餵回 ECL VM，
門這一個不用，混在一起兩種選單會互相踩到。

`DS:6CD2h`／`6CD3h` 誰設回 1 還沒讀到（不是 ECL、也不是絕對定址寫的，
見〈誰寫〉），所以 remake 把它們**綁在那一道門上**
（座標＋朝向一樣就是同一道門，換一道就是新的一份）。原版是兩個全域 byte，
真正的重設時機讀出來之前，這是能對得上「一扇門只能撬一次」的最小假設。

門的旗標本身仍然存在 GEO 裡，所以開過的門會**跟著存檔走**——`UnlockDoorWrapped`
改的是載入的 `Grid`，和原版改 `DS:69BAh` 指到的那張圖是同一件事。
