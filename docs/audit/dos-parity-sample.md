# 發行包對原版 DOS 的抽樣對拍

日期：2026-09-07（逐格相同那兩張）／2026-09-08（建隊到進城）
版本：`v1.1.1-20260907`（`patch`）與 `v1.1.2-dev`（本機建置，未發布）
重生：`tools/dosgolem-reference.sh` → `tools/appimage-dos-parity.sh <版本> patch [zh|en]`

## 對的是什麼

比的是**發行的 AppImage**，不是原始碼建置。spec 126 那組 7744/7744 是單元測試在
比 remake 內部合成出來的那張圖；「測試綠」與「我們寄出去的那個檔案畫得對」是
兩件事，中間隔著打包、資源內嵌、視窗縮放與實際的繪圖路徑。

原版那一側由 **dosgolem** 跑真的 `START.EXE` 產生，不是 DOSBox。dosgolem 是
可程式化的 DOS 執行器：送鍵、等畫面、取畫面全部對齊指令數，而且直接吐
320×200 的 EGA 色號陣列。DOSBox 只能從外面看畫面，送鍵靠 xdotool、等畫面靠
sleep，而猜對與猜錯在截圖上長得一樣。

remake 那一側是 Xvfb 裡的真視窗截圖（960×600），用**最近鄰**降回 320×200
再對回 16 色比。平滑縮放會把差異抹掉，所以不用。

**抽樣，不是全程。** 取的是兩張最說明問題的：整張標題，與第一人稱那一框。

## 結果

| 畫面 | 相同 | 比例 | 說明 |
|---|---:|---:|---|
| 標題（整張 320×200）| 63,866 / 64,000 | **99.79%** | 差的 134 格全在第 147–153 列、第 137–183 欄 |
| 第一人稱框（88×88）| 7,744 / 7,744 | **100%** | |

### 標題那 134 格

全部落在一個 47×7 的方框裡，那正好是 remake 自己加的按鍵提示
`ENTER／空白鍵`。原版沒有這一行——它靠 `int 16h` 靜靜地等。
**其餘 63,866 格逐格相同**：同一份 `TITLE.DAX`、同樣的位置與縮放。

### 第一人稱那一框

一個畫面只留一組斷言，來源是 dosgolem（AGENTS.md §7）。兩組數字擺在一起，
讀的人分不出哪一個是誰說的，而「兩邊互相同意」在其中一邊悄悄退步時反而不會
開口。

> 2026-09-07 稍早這一項還是 18.93%，原因是 dosgolem 少了 EGA 圖形控制器
> （`3CE`／`3CF`），第一人稱框在它那邊畫成黑底白線框。它的 master 併進其他
> 分支的平面式寫入模式之後就畫得出來了，這一項才從 `blocked` 變成 `compared`。

### 框線對得上

繩索外框在原版是 320×200 的四條 8 像素帶（上 0–7、下 184–191、左 0–7、
右 312–319）。remake 的畫布是它的兩倍，外框也是兩倍寬的同一圈——**降回
320×200 之後四條帶逐格落在同一個位置**：種族／性別／職業／陣營四張是
8064/8064，其餘幾張的差都是別的東西畫進那一圈，不是框自己歪掉。

差在哪：

- **原版底下那一列在框外。** `CHOOSE A FUNCTION`、`KEEP THIS CHARACTER? YES NO`、
  `AREA CAST VIEW ENCAMP SEARCH LOOK` 都畫在 native 192–198，也就是繩索框
  **下面**；remake 畫在框裡。左右兩條框帶在那幾列因此對不上（menu 的 22 格）。
- **人物資料頁／姓名／肖像**（約 160 格）：remake 在上框那一帶多了一行
  `SSI GOLD BOX / POOL REMAKE`，原版沒有。
- **按下 B 的第一幕**（498 格）：remake 在第一人稱框外面另外圍了一圈繩索
  （`drawRopeBox`），原版那一框沒有獨立外框。

### 內容差在哪

| 畫面 | 原版 | remake |
|---|---|---|
| 人物管理選擇項 | 四項，首字母以另一種顏色標示 | 另加一欄 `C A L E`、一行標題、一行 `LIBRARY／PARTY` 計數 |
| 人物資料頁 | `LEVEL`／`EXP`、`AC`／`THAC0`／`ENCUMBRANCE`、`HP`／`DAMAGE`／`MOVEMENT`、`STATUS OKAY`，右上角肖像 | **只有性別／種族／職業、年齡、六屬性、金幣、HP**；那八個欄位與肖像都沒有 |
| 肖像編輯器 | 在整張人物資料頁上換頭與身體，底下 `HEAD BODY KEEP` | 一張只有三行字的獨立畫面 |
| 戰鬥造形設計 | **OLD／NEW 兩組** `READY`／`ACTION` 共四格，底部橫向指令列 | 一組兩格，左側直式選單 |
| 按下 B 的第一幕 | 半身像在第一人稱框內，右邊是隊伍面板與 `15,1 W 00:00` | **同上**（2026-09-08 修好；先前整個右半邊留白）|

## 沒有對的

- **人物管理選擇項、種族／職業／陣營選單、人物資料頁**：dosgolem 走得到，
  但這幾張的版面是 remake 自己的——原版是 320×200 的文字排版，remake 是
  640×400 加繩索外框與漢字。逐格比沒有意義，它們的中文化由
  `tools/capture-chinese-menu.sh` 顧。
- **商店、神殿、結局**：dosgolem 的鍵序還沒走到。
- **中文文字區**：`-lang zh` 下遊戲文字是中文、原版是英文，本來就不同。
  這一輪取的兩張都不含遊戲文字，所以不必扣。

## 戰鬥畫面（2026-09-08）

dosgolem 的鍵序延長到第一場遭遇：導覽結束之後往前三步就會撞上
`YOU ARE SURPRISED BY …`，再按 Return 就是戰鬥畫面（第 49 幀）。

那一張量出來的版面**與冒險畫面不是同一套**（spec 129）：外框下緣在 tile
row 22 而不是 23，而且第 22 欄還有一條直的，把畫面切成左邊 7×7 格的戰場與
右邊的資訊欄；最下面那一列指令仍在框外。remake 先前用的是冒險那一套框、
畫的是自己的 50×25 全圖與四行狀態，所以整個版面對不上。

改成原版那一套之後：

| | 整張 | 外框 |
|---|---:|---:|
| combat | 34420／64000 ＝ 53.78% | **9152／9152 ＝ 100.00%** |

**整張只有 53.78% 是預期的**：原版那一側是實際遭遇的戰場，remake 這一側是
`F5` 叫出來的同一支繪製，盤面內容本來就不同。這一項看的是版面。

### 順帶修掉一個量測定義的問題

`frame_cells` 原本把外框的**直行整條算到畫面最底**，於是框下面那一列
（native 192..198，指令列）也被當成框。那一列是文字，兩邊語言不同必然不一樣
——戰鬥那一項第一次跑出來差的 72 格**全部**落在那七列，一格框線都沒差。
改成直行只算到框的下緣之後，menu-empty、race、gender、class、alignment、
icon、menu-party 七張的外框都回到 100%。

同一輪把指令列的起點對齊原版：量到原版從 native x 0..1 起（邏輯 0..2），
remake 先前從邏輯 20 起。

## 三張的數字每次跑都會動一點

`sheet`、`intro`、`combat` 每次對拍都會差幾個像素（同一版連跑三次量到
`sheet` 54818／54808／54813）。**那是屬性 roll 的隨機性，不是退步**——
資料頁印的是骰出來的六個數字，導覽那一幕的隊伍面板印的是 HP，戰鬥那一張
連怪物擺位都可能不同。

其餘十一張（`title`、`first-person`、`menu-empty`、`race`、`gender`、
`class`、`alignment`、`name`、`portrait`、`icon`、`menu-party`）**逐次完全
相同**，所以它們是真正的迴歸訊號：數字一動就是有東西變了。

判讀時要分開看：那三張只在**差十個像素以上**時才值得追，其餘十一張差一個
像素就要查。

## 市政廳外那一格（2026-09-09 走到的）

鍵序（`tools/dosgolem-reference.sh` 的 `POOL_DOSGOLEM_KEYS`，輸出用
`POOL_DOSGOLEM_OUT` 另外指一個目錄）：

```
rep:9:Space,Return,Return,c,rep:5:End,Return,Return,Return,Return,Return,
Return,y,H,E,R,O,Return,k,e,y,a,a,e,b,rep:18:Return,
Right,Right,Up,Up,Up,rep:6:Return
```

導覽結束在 `(0,4)` 朝西，右轉兩次朝東再往前三步就是 `(3,4)`。原版在那裡
分兩段：

1. `YOU ARE OUTSIDE THE CITY HALL. THE CITY CLERK WAITS INSIDE TO AWARD
   COMMISSIONS.`，底下是 `PRESS <ENTER>/<RETURN> TO CONTINUE`。
2. 按 Return 之後換成 `PROCLAMATIONS ARE POSTED ON THE WALLS. IN YOUR
   JOURNAL YOU NOTE PROCLAMATIONS LXIV, LXXVIII, CIX, AND LIX.`，
   **底下換成指令列 `AREA CAST VIEW ENCAMP SEARCH LOOK`**。

**第一段時方向鍵完全按不動，第二段時走得動**——這是後來另外跑一趟量的
（鍵序把 `Up,Up,Up` 之後改成 `Up,Up,Return,Up`）：`59-Up` 是第一段，
`60-Up`／`61-Up` 的畫面**一格都沒變**；`62-Return` 換成第二段，`63-Up` 就
走到下一格了。所以第一段是真的擋住移動，第二段是真的回到自由移動。

remake 現在對得上了（`docs/screenshots/pool-remake-chinese-journal-cue.png`）：
走進那一格就停在「按鍵繼續」，按一次 Return 之後第二段的四行一次顯示、底下是
指令列、方向鍵走得動，手冊提示畫在框裡。

**按幾次是腳本決定的。** `11h PRINT` 與 `12h PRINTCLEAR` 都只是往框裡寫字，
兩者之間沒有等待指令；要玩家按一下的地方，腳本自己放一個**只有一個選項**的
`HORIZONTAL MENU`——市政廳外那一格就是 `AC1E GOSUB AF1C`，選項是字串
`PRESS <RETURN> OR BUTTON TO CONTINUE`。overlay-03 `11B1h` 在選項數是 1 時
不畫那個選項，改畫自己的 `PRESS <ENTER>/<RETURN> TO CONTINUE`（`118Ah`），
所以六種寫法的腳本提示在畫面上都長一樣。詳見 spec 082。

**四個公告字號 remake 是對的**：低解析度縮圖上最後一個看起來像 `CXX`，
把原版那一塊放大六倍看是 `LIX.`——縮圖不能拿來讀字。

**這一格現在進了對拍抽樣**（2026-09-10），不再只是手動比對：
`city-hall-1` 整張 78.6%、`city-hall-2` 整張 77.3%（與 `sheet`、`intro`、`combat` 一樣，逐次會差幾個像素），外框兩張都是
7463／7936 ＝ 94.04%（與 `intro` 同一個框，差在 remake 的框比原版低 11 列）。
整張的差距主要來自中文與英文的字形本身，不是版面。

基準是**另一組鍵序**產的：主基準那條走「導覽完往西撞遭遇」，不經過市政廳，
而改它會讓 `combat` 那一項的基準幀失效。重生的方式是

```
POOL_DOSGOLEM_OUT=workplace/dosgolem-ref-cityhall \
POOL_DOSGOLEM_KEYS='<主鍵序，結尾換成 Left,Left,Up,Up,Up,Return,Up>' \
tools/dosgolem-reference.sh
```

`dos-parity-compare.py` 吃第四個參數當第二組基準，plan 用 `"ref": "cityhall"`
指定來源；那一組不在就跳過那兩項，不擋整份對拍。

## 兩件在截圖上才看得出來的事（2026-09-09）

走到市政廳那一趟順手發現的，兩件都與「畫面怎麼被放大」有關。

**視窗要是邏輯畫布的整數倍。** 先前是 960×600，也就是 640×400 的 **1.5 倍**；
非整數倍會把某些像素行複製、某些丟掉。改成 1280×800（2 倍，也是原版
320×200 的 4 倍）。對拍的降取樣因此從 ÷3 變成 ÷4，**十四張的數字一個都沒變**
——兩種倍率取到的是同一組邏輯像素，所以這一項是視覺品質，不是對拍精度。

**加粗不能靠把字身往右膨脹。** 倚天的字模是照「筆畫一格、空隙一格」設計的：
全形 16 欄裡字身佔 0..14，第 15 欄是字與字之間唯一的留白，而字**內部**的縫隙
也只有一格。`rasterGlyph` 的加粗把每個亮點往右擴一格，於是同時吃掉字間留白
**與字內空隙**——「鈕」的金字旁、「繼」的絲字旁糊成一塊，那一列看起來像疊字。

先只把加粗限制在 `x < width-1`（還回字間那一格），字仍然擠——**字內的縫隙還是
死的**。改成：**字身不加粗，厚度從顏色拿**。`Face.ShadowFace()` 產生「膨脹一格
減掉字身」的外圈，`drawText` 先用同色系暗一階畫外圈、再用主色畫字身。EGA 的
十六色就是「暗八色 ＋ 亮八色」，亮色索引正好是暗色加八，所以配對是查表得來的
（亮黃 14 配棕 6、亮青 11 配青 3）。亮暗有別，字內的縫隙讀得出來，字與字之間
也分得開。

追這一條的過程值得記：先懷疑「同一列畫了兩段字」（寫了測試，數 footer 那一
條上有幾個 `drawText`，只有一段）、再懷疑 advance（量出來全形 16、半形 8，
都對）、再懷疑非整數倍縮放（改成 2 倍，還是疊）——最後把同一行字用同一個
face 畫到邏輯解析度的點陣圖，bold 開關一比就看出來了。**能單獨重現的最小
實驗比任何猜測都快。**

診斷對了之後還差一步：一開始的修法（只還字間那一格）治的是症狀。真正的問題
是「用解析度換厚度」——在一個一格寬的筆畫上再加一格，字就沒有內部了。
