# 發行包對原版 DOS 的抽樣對拍

日期：2026-09-07　版本：`v1.1.1-20260907`（`full-local`，`-lang zh`）
重生：`tools/dosgolem-reference.sh` → `tools/appimage-dos-parity.sh <版本> full-local zh`

## 對的是什麼

比的是**打包好的 AppImage**，不是原始碼建置。spec 126 那組 7744/7744 是單元
測試在比 remake 內部合成出來的那張圖；「測試綠」與「我們寄出去的那個檔案畫得
對」是兩件事，中間隔著打包、資源內嵌、視窗縮放與實際的繪圖路徑。

原版那一側由 **dosgolem** 跑真的 `START.EXE` 產生，不是 DOSBox。dosgolem 是
可程式化的 DOS 執行器：送鍵、等畫面、取畫面全部對齊指令數，而且直接吐
320×200 的 EGA 色號陣列。DOSBox 只能從外面看畫面，送鍵靠 xdotool、等畫面靠
sleep，而猜對與猜錯在截圖上長得一樣。

remake 那一側是 Xvfb 裡的真視窗截圖（960×600），用**最近鄰**降回 320×200
再對回 16 色比。平滑縮放會把差異抹掉，所以不用。

**抽樣，不是全程。** 取的是兩張最說明問題的：整張標題，與第一人稱那一框。

## 結果

| 畫面 | 相同 | 比例 | 說明 |
|---|---:|---:|---|
| 標題（整張 320×200）| 63,866 / 64,000 | **99.79%** | 差的 134 格全在第 147–153 列、第 137–183 欄 |
| 第一人稱框（88×88）對 DOSBox 既有基準 | 7,744 / 7,744 | **100%** | 交叉核對，見下 |
| 第一人稱框（88×88）對 dosgolem | 1,466 / 7,744 | 18.93% | **基準側的缺口**，見下 |

### 標題那 134 格

全部落在一個 47×7 的方框裡，那正好是 remake 自己加的按鍵提示
`ENTER／空白鍵`。原版沒有這一行——它靠 `int 16h` 靜靜地等。
**其餘 63,866 格逐格相同**：同一份 `TITLE.DAX`、同樣的位置與縮放。

### 第一人稱那一框的兩個數字

對 DOSBox 既有基準是 **7744/7744**（100%），對 dosgolem 是 1466/7744。
兩個 oracle 對不起來的時候，先問是誰錯：

dosgolem 目前**還沒實作 EGA 圖形控制器**（`3CE`／`3CF`）。原版畫第一人稱視野
時整組都用上了——Set/Reset、Enable Set/Reset、Data Rotate、Bit Mask、
Read Map Select，量到 2,745 次寫入。少了那條路，CPU 寫進去的位元組會直接落到
每一個開著的平面，於是每一格不是全 0 就是全 1：**基準側畫出來是黑底白線框**。

所以 18.93% 量的是 oracle 的缺口，不是 remake 的正確性。細節在 dosgolem 的
`docs/findings/004-graphics-controller-is-used-by-the-3d-view.md`。

## 沒有對的

- **人物管理選擇項、種族／職業／陣營選單、人物資料頁**：dosgolem 走得到
  （鍵盤與存檔都通了），但這幾張的版面是 remake 自己的——原版是 320×200
  的文字排版，remake 是 640×400 加繩索外框與漢字。逐格比沒有意義，
  它們的中文化由 `tools/capture-chinese-menu.sh` 顧。
- **戰鬥、商店、神殿、結局**：dosgolem 還沒走到。
- **中文文字區**：`-lang zh` 下遊戲文字是中文、原版是英文，本來就不同。
  這一輪取的兩張都不含遊戲文字，所以不必扣。
